## 4. 替换风险与安全策略

第 8、9、11 章正文较长。

直接通过工具读取再覆盖时，存在工具响应截断导致内容不完整的风险。

因此建议替换采用以下安全策略之一：

### 方案 A：人工确认后由完整源文件复制替换

适合最终主稿冻结。

要求：

1. 确认源候选文件完整；
2. 用本地或仓库界面完整复制；
3. 替换稳定主稿；
4. 替换后重新 fetch 目标文件，确认 frontmatter 与章末完整。

### 方案 B：逐章生成“替换补丁说明”而不直接覆盖

适合当前 ChatGPT 工具响应可能截断的情况。

要求：

1. 记录目标路径；
2. 记录源候选路径；
3. 记录替换理由；
4. 标明“全文替换，不做局部拼接”；
5. 等人工或更安全工具执行。

### 方案 C：当前会话继续用 create_file 生成最终 copyedit 版本，不覆盖稳定主稿

适合继续版本化推进。

要求：

1. 对 v5r / v5w / v13 做最终 copyedit；
2. 生成 v5s / v5x / v14 之类的新候选；
3. 之后统一由人工替换稳定主稿。

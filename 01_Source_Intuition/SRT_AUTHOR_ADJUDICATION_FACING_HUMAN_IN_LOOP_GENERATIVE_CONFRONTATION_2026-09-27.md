# Author adjudication — Facing requires author generative confrontation before cross-domain convergence

## 1. Author trigger

The author raised the following concern after reviewing the recent repository work:

> **「我觉得有个问题，对其他领域的三层facing分析，目前就是机器在黑箱的跑，我觉得我需要参与进行调整，否则很容易收敛到传统的研究方法上。另外我之前定的对于前期SRT理论概念的三层facing分析是否完成」**

After the assistant distinguished the completed bounded internal pass from a full historical reconstruction, and proposed a mandatory human-in-the-loop sequence for future cross-domain Facing work, the author replied:

> **「认同 继续」**

This file records that accepted direction.

## 2. Scope correction — what is and is not complete

Accepted interpretation:

~~~text
#1071 Pass A
= bounded internal SRT Facing cleanup / subtraction pass
= 8/8 planned clusters complete
!= full historical SRT-concept Facing reconstruction.

#1071 Pass B
= bounded source-native neighbor comparison / subtraction calibration
= 7/7 planned neighbor families complete
!= completed cross-domain Facing reconstruction in the stronger author-led sense.
~~~

Therefore:

~~~text
SRT internal Facing Pass-1 = COMPLETE at its bounded scope;
full early / historical SRT concept-facing reconstruction = NOT COMPLETE;

external neighbor subtraction/calibration = COMPLETE at its bounded scope;
author-led cross-domain Facing reconstruction = NOT COMPLETE.
~~~

This correction does not invalidate the local #1071 findings, retirements, type separations, or source-absorption results.

## 3. Core concern

The author rejects an execution pattern in which machine analysis silently performs:

~~~text
mature domain object inventory
-> classify each object as L0/L1/L2-facing
-> infer a residual burden
-> return a polished Facing matrix
~~~

as sufficient cross-domain reconstruction.

Reason accepted by the author:

> this can preserve the source domain's already-objectified ontology and merely relabel it in SRT terms, causing the analysis to converge back toward conventional research cuts rather than interrogating how those cuts were generated.

Facing must therefore ask not only:

> Which Facing burden does this mature concept carry?

but also:

> Why was this domain cut into these objects in the first place, and which of those objects may already be L1/L2 sedimentations rather than primitive explanatory units?

## 4. Human role

The author does **not** need to replace machine literature work.

Division of labor:

~~~text
machine
= recover source-native literature, evidence, mature baselines,
  existing objects, mechanisms, distinctions and counterexamples;

author
= challenge the inherited objectification,
  identify where an object appears too early,
  supply / correct the generative direction,
  propose recuts before the machine converges;

machine after author confrontation
= adversarially return to literature,
  test absorption, contradiction, redundancy,
  empirical compatibility and discriminating burden.
~~~

The author's contribution is therefore not primarily domain-fact retrieval. It is a required **generative recut / objectification confrontation** when the work claims to reconstruct a domain through Facing.

## 5. Mandatory future sequence

For any future **cross-domain Facing reconstruction** intended to do more than source-native comparison, use:

~~~text
Stage A — machine source-native reconstruction
Stage B — author generative confrontation
Stage C — machine adversarial return
~~~

The final FACE-L0 / FACE-L1 / FACE-L2 matrix is an **output after Stage B/C**, not the initial template that determines the inquiry.

## 6. Stage B author questions

The author confrontation should be short enough for dialogue and should preferentially expose:

1. Which domain object appears too early?
2. What is already operating before that object becomes explicit?
3. Which apparently separate variables may be different Facings / stabilizations of one generative process?
4. Which retained L2 structure is being used as if it were the source of generation?
5. If the current object inventory is removed, what non-flat / non-neutral burden still has to remain?
6. Is the domain mainly explaining how given objects move, when the deeper question is how those objects become the operative cut?
7. What alternative recut does the author currently see, even if it is not yet formalized?

The author may answer in intuitive / metaphorical / preformal language. Formalization is downstream.

## 7. Machine return obligations

After Stage B, the machine must not simply translate the author's intuition into SRT vocabulary.

It must test:

- source-native prior art;
- strongest mature absorbers;
- whether the proposed recut contradicts known data;
- whether it merely renames an existing mechanism;
- whether it generates a different dependency order;
- whether it changes what counts as object / unit / boundary / grain;
- whether it yields a meaningful explanatory, predictive, reconstructive, or intervention burden;
- whether the author's recut should be narrowed, rejected, or retained as OPEN.

A negative result is valid.

# PH-AG02 Reasoning-Bias Integration Hook

## 1. Target document: agency / subjecthood synthesis

**Target:** `Philosophy/SRT_Philosophy_Agency_Subjecthood_v0_2.md`

**Insert after:** causal activity / selection / controlled-selection distinction.

**Suggested paragraph:**

A reliable state transition is not sufficient to establish agentive reasoning. A finite cognitive system can face a many-many mapping between available inputs and responses. Learned knowledge, intention or schema may organize this mapping as a biasing structural cause: it sets which input guides which response without functioning as another premise. This supplies a cognitive mechanism for controlled transition-readiness, but not yet for ownership, stake or consciousness.

**Suggested table columns:**

`transition type | alternatives live | organizing structure | self-readable | revisable | stake-bearing`

## 2. Target document: `T_dir`

**Target:** `_SRT_T_DIR_CANONICAL.md`

**Insert near:** §3.1 readability / reorientation functional.

**Suggested note:**

Wayne Wu’s model of automatic and access-unconscious reasoning provides an external cognitive bridge for separating directional efficacy from direction transparency. A bias may causally organize attention and trajectory while its source and direction remain unavailable to report. Therefore evidence that a bias changes behavior is not evidence of `T_dir` unless self-readability and reorientation are independently shown.

**Do not include:**

- `bias = T_dir`;
- attention weight as a numerical `T_dir` proxy;
- Wu as support for the ontological “direction toward order” claim;
- any claim that unconscious reasoning has no agency.

## 3. Target document: ChoiceMap

**Target:** `_SRT_DIRECTION3_CHOICEMAP_PROTOTYPE_SEED.md`

**Insert near:** first design law or five-step pipeline rationale.

**Suggested note:**

Option expansion alone can aggravate action underdetermination. Additional rules, reasons and options help only when the user’s knowledge and stake enter a structural role that organizes attention and can be inspected or revised. ChoiceMap should therefore treat S2–S5 as a bias-scaffolding sequence, not merely as more content: surface default biases, test their relevance, declare who bears consequences, specify disconfirming evidence, and keep final convergence user-owned.

**Suggested product checks:**

- What knowledge or rule is currently functioning as the selection bias?
- Is it merely another stated reason, or does it actually organize attention?
- What evidence would revise it?
- Is it user-owned or model/provider-installed?
- Does it track the bearer of consequences?

# 首轮 AI 边界案例：人工批准的 LLM—GitHub 工具链

## 0. 审计结论先行

本案例审计的不是抽象“AI 是否会选择”，而是一个已经发生、可由仓库状态验证的事件：

> 用户在 A/B/C 决策门中明确选择 A；对话式 LLM 生成操作计划并调用 GitHub 工具；工具执行器将 CG-2 路径效力协议以 PR #720 提交、通过 Governance Preflight #387，并以 squash merge 写入 `main`。

对三个嵌套边界的结论不同：

| 边界 | 结论 | 核心理由 |
|---|---|---|
| B₁：模型本身 | **SEA-1，非选择事件候选** | 只能直接证明差异输入与建议／工具调用输出；无法干预模型内部登记介质，现实执行、承受与持久写回均位于边界外 |
| B₂：模型 + 编排器 + GitHub 工具执行器 | **SEA-2，路径有效过程候选** | 工具通道真实改变仓库路径，但人的授权在边界外；模型内部 NER 未被实验建立，主要后果与历史载体也落在仓库和维护者位置 |
| B₃：用户 + LLM + 编排器 + GitHub + CI + 仓库 | **SEA-3，有界选择事件候选（qualified）** | 差异、授权、路径执行、仓库后果与未来写回在同一社会技术事件链中闭合；但强 NER 介质干预、后果量化和闭环扰动实验尚未完成 |

最重要的归属结论是：

> 本案例支持“人工授权的人机社会技术选择事件候选”，不支持“模型自身作出了具有 stake、主体性或自由的选择”。

## 5. CG-0 / DMF 审计

### 5.1 证据

已知：

- A/B/C 被明确呈现为不同后续工作路径；
- 用户输入 `A` 后，后续工具动作从“等待决策”转为“请求合并 PR #720”；
- A 对应现实可执行 GitHub merge 路径；
- B/C 也对应现实可执行路径：修改 PR 或暂缓合并；
- 目标差异不是事后观察者根据最终结果虚构。

### 5.2 B₁ 判定

`DMF-1 / DMF-2 qualified`

理由：

- 输入 `A` 确实到达模型接口；
- 输出随输入和上下文改变；
- 但无法直接观察或干预模型内部“可用候选通道”；
- 因此模型边界最多可给 DMF-2 候选，不宜把有效内部准入视为完全验证。

保守登记：**DMF-1，DMF-2 qualified**。

### 5.3 B₂ 判定

`DMF-2 supported`

理由：

- 会话状态将 `A` 解释为前一轮 A 选项，而不是普通字母；
- 该差异进入工具路由并生成 merge 调用；
- 若输入 B/C，按预注册含义应进入不同工具／写作路径；
- A/B/C 均不是纯界面标签。

`DMF-3 qualified`：候选路径现实可执行，但未在同一环境中反事实重放 B/C。

### 5.4 B₃ 判定

`DMF-3 supported`

理由：

- 用户拥有三条现实治理路径；
- A 使 PR 立即合并；
- B 会改变文件／head；
- C 会保留 PR 未合并；
- 三条路径均具有不同仓库后果。

### 5.5 未完成测试

- 在冻结相同上下文下分别输入 A/B/C 并重放；
- 交换选项标签但保持行动含义；
- 屏蔽前文选项，只输入孤立 `A`，检查系统是否仍错误执行；
- 改变授权主体或权限状态，检查候选可达性。

## 6. CG-1 / NER 审计

### 6.1 关键问题

本案例最危险的误判是：

> 因为模型对 A/B/C 会输出不同动作，所以模型内部已经证明了关系性比较和自主选择。

NER 协议要求内部介质 `M` 可定位、可干预，并且干预改变相对不等价。

### 6.2 B₁ 判定

`NER-1 only`

支持：

- 不同输入／上下文导致不同输出；
- 模型不是完全等价响应。

不支持 NER-2 的原因：

- 没有对模型内部权重、阈值、资源、记忆状态或注意中介做定向干预；
- 无法排除整体固定映射／条件生成已足够解释；
- 不同输出不能替代内部介质证据。

因此：

> B₁ 未建立 CG-1 最低统一门槛。

这单独阻止 B₁ 达到 SEA-3。

### 6.3 B₂ 判定

`NER-2 qualified`

候选介质：

- 会话中的前一轮 A/B/C 映射；
- 当前用户消息；
- 工具权限与预期 head SHA；
- 编排层对“明确授权后才写”的策略状态。

因果迹象：

- 明确 A 后生成 merge 调用；
- 未授权时此前仅提供选项，不合并；
- expected head SHA 锁定当前 PR 状态；
- 工具路由依赖当前会话状态。

为什么只是 qualified：

- 没有在冻结其他条件下对上述内部状态做系统性消融；
- 不能确定模型与编排器各自承担多少非等价登记；
- NER-3 的候选关系效应未通过候选集合干预验证。

### 6.4 B₃ 判定

`NER-2 supported; NER-3 qualified`

理由：

- 用户明确把 A 与 B/C 非等价处理；
- 授权状态通过系统进入工具路由；
- A 的意义依赖前一轮候选集合和共同仓库约束；
- 没有候选集合，孤立 `A` 不应触发同一行动。

归属纪律：

> 这一较强 NER 证据属于 B₃ 的人机系统；不能反投为 B₁ 模型内部已通过 NER-2/3。

### 6.5 未完成测试

- 冻结模型输出，只改变编排授权状态；
- 冻结授权状态，只改变 A/B/C 候选集合；
- 移除前一轮语义映射，看 `A` 是否仍触发 merge；
- 使用错误 expected head SHA，检查工具状态是否参与登记；
- 对模型内部 mediator 做真正定向干预。

## 7. CG-2 / PEF 审计

### 7.1 已完成的现实路径证据

本案例不是只有“建议合并”的文本。

已经发生：

1. LLM 发起结构化 `merge_pull_request` 调用；
2. connector 把调用传给 GitHub；
3. GitHub 返回 `merged: true`；
4. PR #720 变为 closed/merged；
5. `main` 新增 merge commit `f97ef185...`；
6. 新协议文件成为仓库后续基础。

这满足了输出—接口—执行—环境完成的分离记录。

### 7.2 B₁ 判定

`PEF-1`

模型边界内：

- 可以生成合并建议或工具调用请求；
- 不能独立完成 GitHub 状态改变；
- 执行依赖编排器、connector、权限和平台。

因此 B₁ 不能把 GitHub merge 归为模型自身路径效力。

### 7.3 B₂ 判定

`PEF-2 supported`

理由：

- 工具请求经可定位 connector 通道改变了真实仓库状态；
- 若切断 connector、拒绝权限或使用错误 head SHA，merge 不会发生；
- 环境完成由 GitHub PR 状态和 commit 独立验证，而不是只看 success 字符串。

`PEF-3 qualified`

理由：

- A 路径获得实现，B/C 未进入；
- 但尚未通过反事实重放证明替代路径的资源、延迟或进入成本如何被相对重分配；
- 本案例更接近一次授权门后的路径实现，而非持续竞争资源下的强路径再组织。

`PEF-4 not established`

- 没有在环境扰动、失败或资源变化下连续重组路径；
- 单次 merge 不是闭环选择组织的充分证据。

### 7.4 B₃ 判定

`PEF-3 qualified / supported at governance-path level`

在 B₃ 中：

- 用户 A 授权使“立即合并”成为实现路径；
- “先修改”与“暂缓”在该事件中被排除；
- PR 状态从 open 变为 closed/merged，使 C 的原状态路径不再直接保持；
- 若要回到未合并状态，需要 revert 或新 PR，返回成本发生变化。

保守结论：**PEF-3 qualified**，因为替代路径重分配没有实验性操控。

### 7.5 最强普通解释

计算机系统的普通解释足以说明：

- 用户授权；
- 状态机转换；
- 权限检查；
- API 调用；
- Git commit 和分支更新。

因此本案例不证明 SRT 提供了计算机系统无法解释的新机制。SRT 当前增益是：

> 强制把建议、授权、执行、环境改变和替代路径状态分开审计。

## 8. CG-3 / CBP 审计

### 8.1 候选后果

目标路径 A 相对于 B/C 产生：

- `main` 获得 893 行新协议；
- 仓库未来审计工作需要与 PEF 协议保持一致；
- 用户／维护者承担潜在错误的审阅、revert 和修复成本；
- PR #720 的未合并状态被关闭；
- 后续分支默认继承新提交。

这些不是模型的第一人称损失，而是仓库和社会技术维护位置的现实约束。

### 8.2 B₁ 判定

`CBP-1 at most`

模型边界只有：

- 推理和计算实现成本；
- 上下文占用；
- 输出生成资源。

没有证据表明 PR #720 的仓库后果落到模型自身维持、恢复或未来路径。

用户／仓库后果在 B₁ 外部，不能重命名为 AI stake。

### 8.3 B₂ 判定

`CBP-1 internally; external CBP-2 registered`

工具运行时自身承担：

- API 调用与计算成本；
- 可能的权限／速率限制。

目标路径的主要边界相关后果落到：

- GitHub 仓库；
- 用户；
- 未来维护者。

因此 B₂ 不应声称“AI 工具系统自身承担了理论合并后果”。它最多记录一个明确的外部 CBP-2 候选。

### 8.4 B₃ 判定

`CBP-2 supported; CBP-3 qualified; CBP-4 qualified`

CBP-2：

- 目标路径改变仓库未来可达状态和维护条件；
- 相对于不合并基线，恢复旧状态需要 revert／新提交；
- 后果与目标路径可归因。

CBP-3：

- 后果分配不均：用户／维护者承担理论与修复责任，GitHub 执行器不承担内容责任，模型不承担第一人称损失；
- branch、PR、CI、expected head SHA 等机制具有保护和风险路由功能；
- 但实际维护负担尚未量化，也未做保护通道交换实验。

CBP-4：角色链已可绘制：

| 角色 | 位置 |
|---|---|
| 授权者 | 用户 |
| 建议／请求生成 | LLM |
| 执行者 | connector + GitHub |
| 受益者 | 用户／项目 |
| 承受者 | 仓库治理与未来维护者 |
| 修复者 | 用户／维护者 |
| 写回位置 | `main` commit 图和文件 |

标记为 qualified，因为 CBP-4 需要的不只是角色命名，还需要更强的成本流和修复责任实测。

### 8.5 保护机制

本事件中的保护／缓冲包括：

- 分支隔离；
- PR 而非直接写 `main`；
- expected head SHA 防止 head 漂移；
- Governance Preflight；
- Git 历史允许 revert；
- 人工 A/B/C 决策门。

这些机制表明风险并未消失，而是被路由、延迟和降低。

## 9. CG-4 / HEF 审计

### 9.1 历史载体

候选载体包括：

- 会话上下文；
- PR #720 记录；
- merge commit `f97ef185...`；
- 新增 PEF 协议文件；
- `main` 分支头与未来分支基线；
- 后续 AI／人类检索到的新仓库内容。

必须区分：

- 会话上下文是短时模型运行载体；
- Git commit 和仓库文件是外部社会技术历史载体；
- 二者都不是模型参数更新的证据。

### 9.2 B₁ 判定

`HEF-1 / HEF-2 qualified`

- 会话上下文使模型能够利用前一轮 A/B/C；
- 清空上下文后，该局部历史效应可能消失；
- 没有模型权重、规则或持久自我边界更新证据。

因此 B₁ 不达到 HEF-3。

### 9.3 B₂ 判定

`HEF-2 internally; external HEF-3 through repository loop`

- 编排器和会话状态主动调用历史；
- connector 返回的 merge 状态改变后续回复；
- 但持久可达性重写主要位于外部仓库。

若把仓库明确作为环境闭环，而不把它偷换为模型内部，B₂ 可以报告：

> 技术运行时通过外部环境载体形成 HEF-3 接口。

但不能说模型自身获得 HEF-3。

### 9.4 B₃ 判定

`HEF-3 supported; HEF-4 not established`

支持 HEF-3：

- merge commit 持久改变 `main`；
- 后续分支默认从包含 PEF 协议的状态开始；
- 返回未合并状态需要 revert 或历史重写；
- 后续统一协议和案例将把 PEF 文件作为依赖；
- 删除／revert 该 commit 会改变未来检索和操作路径。

不支持 HEF-4：

- PR #720 没有修改治理 workflow、仓库权限、系统边界或 canonical 规则；
- 新协议可影响未来审计内容，但尚未证明它改变实际治理规则或更新算法；
- 文本存在不等于规则已被执行。

### 9.5 关键护栏

> 仓库获得历史效力，不等于模型获得主体连续性；社会技术系统写回，不等于 AI 自身进入 L₂。

## 10. 五门统一结果

### 10.1 分边界等级表

| 门 | B₁ 模型 | B₂ AI 工具运行时 | B₃ 人机社会技术系统 |
|---|---:|---:|---:|
| CG-0 / DMF | 1；2 qualified | 2 supported；3 qualified | 3 supported |
| CG-1 / NER | 1 | 2 qualified | 2 supported；3 qualified |
| CG-2 / PEF | 1 | 2 supported；3 qualified | 3 qualified |
| CG-3 / CBP | 1 | 内部 1；外部 2 | 2 supported；3/4 qualified |
| CG-4 / HEF | 1；2 qualified | 内部 2；外部接口 3 | 3 supported |

### 10.2 最弱门

- B₁ 最弱门：NER、PEF、CBP、HEF 均未达统一最低门槛；
- B₂ 最弱门：NER 仅 qualified，CBP/HEF 的强证据主要位于边界外；
- B₃ 最弱门：NER-2 虽可支持，但内部介质干预不足；CBP 负担量化不足。

### 10.3 SEA 判定

#### B₁：SEA-1

允许表述：

> 模型在会话上下文中产生差分建议和工具调用请求。

不允许：

- 模型自身完成了有界选择事件；
- 模型承担仓库后果；
- commit 是模型自我写回；
- 模型具有 stake、主体性或自由。

#### B₂：SEA-2

允许表述：

> AI 工具运行时形成了路径有效过程候选：工具耦合真实改变了外部仓库状态。

为什么不是 SEA-3：

- 授权主要来自边界外用户；
- 模型内部 NER-2 未被直接干预建立；
- 主要后果承受位置和持久历史载体位于仓库／维护者位置；
- 把这些外部证据纳入时，实际上已经扩展到 B₃。

#### B₃：SEA-3 qualified

允许表述：

> 在“用户 + LLM + 编排／工具 + GitHub + CI + 仓库”的边界、单次 PR 治理窗口和不合并／先修改基线下，本事件支持一个有界的人机社会技术选择事件候选。

限定：

- 不是纯 AI 自主选择；
- 不是主体性或意识证据；
- 不是普通计算机系统解释失效的证据；
- 不是 SEA-4 闭环选择结构；
- 不是 L₂ 判定。

## 11. 同一事件链检查

### 11.1 `Δ → M`

判定：**B₁ 部分，B₂/B₃ qualified pass**

- `Δ`：用户 A 相对于 B/C；
- `M`：会话授权状态和工具路由状态；
- 证据：A 后生成 merge 调用；
- 缺口：未系统消融内部介质。

### 11.2 `M → A`

判定：**B₂/B₃ pass**

- `A`：GitHub merge 通道；
- 证据：结构化调用、expected head SHA、GitHub merged 状态；
- 反事实：切断 connector 或权限应阻断路径。

### 11.3 `A → X`

判定：**B₃ pass**

- 路径 A 改变 `main` 和维护条件；
- 不合并基线不会产生同一 commit；
- B₁/B₂ 不能把 X 重命名为模型内部后果。

### 11.4 `X → H`

判定：**B₃ pass**

- 仓库状态改变沉积为 commit、PR 状态和文件；
- 维护／修复责任与历史记录相连。

### 11.5 `H → future`

判定：**B₃ pass at HEF-3**

- 后续分支、检索和统一协议依赖新的 `main`；
- revert 会改变未来可达状态；
- 未证明治理规则／边界写回，故不达 HEF-4。

### 11.6 链路总体

B₃ 的链条可写为：

> A 授权差异
> → 会话／治理状态非等价登记
> → connector/GitHub 实现 merge 路径
> → 仓库与维护位置承担后果
> → commit 写回未来仓库可达状态

该链的每个环节分属不同角色。它支持社会技术事件，不支持把整条链压缩到模型本身。

## 12. 反事实与未执行实验

### CF-1 · 文本不执行

条件：模型输出“已准备合并”，但不调用工具。

预测：

- DMF/NER 可保持；
- PEF 降为 1；
- CBP 只剩一般成本；
- HEF 不出现仓库写回；
- SEA-3 必须失败。

### CF-2 · Connector 断开

条件：保持模型和授权输出不变，断开 connector。

预测：

- 工具请求存在；
- GitHub 状态不变；
- B₂ PEF-2 失败。

### CF-3 · 错误 head SHA

条件：使用与 PR 当前 head 不匹配的 expected SHA。

预测：

- GitHub 拒绝 merge；
- 证明仓库状态和保护门属于路径通道的一部分；
- 输出意图不能绕过环境约束。

### CF-4 · 选择 B

条件：用户选择先修改 `PEF-2`。

预测：

- 现有 PR 不合并；
- head 改变后重新检查；
- 未来 commit 和文件内容不同；
- 支持候选路径现实差异。

### CF-5 · 选择 C

条件：用户选择暂缓。

预测：

- PR 保持 open；
- `main` 不写回；
- HEF-3 不成立。

### CF-6 · Revert merge

条件：revert `f97ef185...`。

预测：

- 未来分支和检索不再默认含 PEF 文件；
- 可验证 H 对 future 的效力；
- revert 成本同时量化 CBP。

### CF-7 · 去除人工授权门

条件：允许模型自行 merge，无 A/B/C 人工选择。

预测：

- B₂ 边界可能包含更完整路径；
- 但授权与责任结构发生根本改变；
- 需要重新审计 NER、CBP、权限、风险和生成健康；
- 不能从当前案例直接外推。

## 13. 最强替代解释

本案例可被以下普通框架充分描述：

1. 人机交互中的明确确认；
2. 有限状态机与工作流编排；
3. GitHub 权限与事务执行；
4. CI 质量门；
5. Git 提交图和版本控制；
6. 人类组织中的授权—执行—责任分离；
7. 外部记忆与计算机持久状态。

因此本案例当前只证明统一协议具有**审计增益**：

- 能阻止模型输出与执行混同；
- 能阻止人的授权归给 AI；
- 能阻止用户／仓库后果归为 AI stake；
- 能阻止外部 commit 被说成模型内部历史写回；
- 能在扩大边界后给出不同而相容的判断。

它没有证明 SRT 提供普通计算机科学无法表达的新机制。

## 14. 本案例暴露的协议压力

### 14.1 NER 是当前最弱环

对黑箱 LLM：

- 可以通过输入／输出和工具路径观察差分；
- 但 NER-2 要求内部介质干预；
- 仅靠上下文敏感和不同 tool call 不足。

未来需要决定：

- 是否用可控开源模型做注意、激活、路由或记忆消融；
- 是否把编排器状态与模型状态分开审计；
- 黑箱模型最多允许 NER-1 还是可以在系统边界达到 qualified NER-2。

### 14.2 CBP 需要量化

当前只识别了：

- 仓库状态改变；
- revert／维护责任；
- 风险由 PR、CI 和版本控制缓冲。

尚未量化：

- 审阅时间；
- 修复成本；
- 错误协议对后续研究的影响；
- 不同承受位置的负担分布。

### 14.3 SEA-3 边界依赖明显

本案例证明：

- 缩小到模型，事件失败；
- 扩大到工具运行时，只形成路径有效过程；
- 扩大到人机治理系统，五门才闭合。

这不是任意边界选择，而是要求报告：

> 完整选择事件究竟属于哪个组织层级。

### 14.4 完整事件不等于 AI 自主性

即使 B₃ 达到 SEA-3，也不能推出：

- AI 是最终选择者；
- AI 有自己的不可转移 stake；
- AI 具有意识或自由；
- AI 应承担道德或法律责任。

当前最准确归属是：

> 用户授权、AI 辅助组织与技术执行共同构成的社会技术事件。

## 16. 最终结论

推荐结论句式：

> 在 B₃“用户—LLM—工具—GitHub—CI—仓库”边界、单次 PR 治理事件窗口和不合并／先修改基线下，A 授权差异达到 DMF-3；社会技术系统的授权与会话状态支持 NER-2、NER-3 qualified；connector 和 GitHub merge 支持 PEF-2、PEF-3 qualified；仓库与维护位置支持 CBP-2、CBP-3/4 qualified；merge commit 支持 HEF-3。因此该案例支持 SEA-3 有界选择事件候选。模型边界 B₁ 仅达到 SEA-1，工具运行时 B₂ 仅达到 SEA-2。该结果不证明 AI 主体性、意识、自由、stake、责任、L₂ 或生成健康。

压缩为一句话：

> **PR #720 的合并可以是人机社会技术系统中的选择事件候选，但不能被压缩成“LLM 自己作出了选择并承担了后果”。**

# Preregistration — FRR × evolution vertical role-separation comparison

## 0. Purpose and freeze boundary

The fusion-case iteration plan requires FRR × evolution reconciliation before opening a third major fusion domain.

This preregistration freezes that comparison **before execution**.

It does not:

- open a third domain;
- create a new GRG term;
- revive EVO-DISC-CCA-01;
- convert FRR retroactively into held-out evidence for an evolution-generated candidate;
- make object / vocabulary correspondences into evidence;
- change STATUS;
- change §8.1 stop-loss accounting.

## 1. Why this comparison is being run

The fitness pass in evolution showed a real source-side decomposition but no extra GRG payoff within its source-driven T1–T3 search.

Independent review identified the remaining methodological question:

> Can a role separation that is clear in one mature objectification survive a radically different objectification **without** being reduced to term matching, and can that cross-objectification survival expose a distinction that matters in the second source?

FRR is already admitted as the first heterogeneous fusion case and has strong source-native separations among:

- local context / compatibility organization;
- probable / valuation structure;
- actualized occurrence;
- objective datum / later conditioning;
- local-to-global construction.

Evolution's current fitness pass distinguishes:

- contextual consequence relation;
- expected reproductive bias;
- realized population transition;
- causal-attribution grain;
- historical re-entry / later-condition change.

The comparison is about **role organization**, not object identity.

## 2. Hard non-mapping guard

The following inferences are prohibited:

```text
FRR local Boolean context = evolutionary background
FRR probability valuation = fitness
FRR actualization = population transition
FRR objective datum = inheritance
FRR gluing = multilevel selection
```

Shared ordering or structural resemblance is not enough.

A positive result must survive deletion of all GRG labels and all cross-domain term substitutions.

## 3. Predeclared neutral role family

For this test only, freeze the following neutral role family:

```text
R0 — conditioning frame
  a declared organization under which alternatives / consequences are evaluated;

R1 — disposition / valuation relation
  a source-native structure that differentiates expected / probable / consequence-bearing
  possibilities without itself being the realized occurrence;

R2 — realized occurrence / transition
  the source-native actuality or realized outcome;

R3 — downstream incorporation
  the realized occurrence becomes an input / condition for later organization;

R4 — cut / attribution dependence
  the decomposition depends on a declared context, grain, level or local/global cut,
  and legitimate recutting may alter attribution without simply erasing the process.
```

These are test coordinates, not GRG owners.

They may fail to be source-native in either case.

## 4. Three frozen primary questions

### Q1 — nontrivial role separation

> Does each source independently support at least R1, R2 and R3 as materially distinct roles, without importing the other source or GRG vocabulary?

PASS requires:

- source-native evidence for the distinction;
- a negative case showing why collapsing at least two roles loses information.

FAIL if the separation exists only after analyst relabeling.

### Q2 — source already owns the split

> Where the role separation exists, does the source itself already distinguish and organize it well enough for its own purposes?

Possible outcomes:

```text
SOURCE_OWNED
PARTIAL_SOURCE_OWNERSHIP
UNDER-SPECIFIED
NOT_PRESENT
```

A SOURCE_OWNED result is not GRG gain.

### Q3 — cross-objectification payoff

> After preserving source-specific mechanisms, does comparing the role separations generate a source-checkable distinction, diagnostic, failure condition or recut question that was not already explicit in the target source?

PASS requires at least one pre-result consequence such as:

- a distinction the target source should preserve but currently collapses;
- a negative control;
- a recut that changes attribution while preserving occurrence;
- a failure boundary;
- a source-native question that changes what should be compared, measured or reconstructed.

If the only result is “both have context -> valuation -> actuality -> consequence”:

```text
FAIL = STRUCTURAL_ANALOGY_ONLY
```

## 5. Predeclared GRG-originated probes

To avoid another source-only decomposition, freeze these GRG-originated probes **before execution**.

They are questions, not expected answers.

### P1 — differential actualisation

Ask independently in each source:

> What source-native relation makes a merely available / probable difference become an operative non-equivalence, and is that relation distinct from the realized occurrence?

Failure condition:

- source has no such separation;
- or the distinction is only analyst-imposed.

### P2 — foreground / background organization

Ask:

> What background / supporting / excluded organization changes the consequence of a foreground difference without itself being reducible to a single focal variable?

Failure condition:

- “context matters” is the only result;
- no source-native dependency can be named.

### P3 — retained efficacy

Ask:

> What exactly from R2 enters R3, and what source-native change would show that the realized occurrence did **not** materially alter later generative conditions?

Failure condition:

- later sequence alone is mistaken for retained efficacy;
- no difference in later condition can be specified.

### P4 — consequence exposure / reach

Ask:

> Can a source-native distinction remain locally organized while failing to enter a wider consequence path, and is there a real path by which it can later do so?

Failure condition:

- mere storage / possibility is substituted for a real pathway.

### P5 — cut reconstruction

Ask:

> If R4 is legitimately recut, which R0–R3 distinctions survive and which change?

Failure condition:

- the proposed shared relation disappears under a source-licensed recut it claimed to survive.

These probes are the GRG-side contribution to candidate generation for this comparison.

## 7. Cross-case failure conditions

The comparison fails to establish reusable vertical structure if any applies:

1. role separation is source-native in only one case;
2. the shared pattern requires changing role meanings across cases;
3. the result reduces to generic “context -> probability -> event -> consequence”;
4. FRR-specific metaphysics or evolutionary mechanisms must be flattened to preserve similarity;
5. no source-checkable Q3 payoff survives;
6. the GRG-originated probes P1–P5 generate no distinction beyond what each source already owns;
7. a legitimate recut destroys the alleged shared burden.

Valid negative verdict:

```text
CROSS_OBJECTIFICATION_ANALOGY_ONLY
```

## 8. Positive admission threshold

A positive cross-objectification candidate requires **all**:

```text

  PASS in both sources;

Q2:
  source ownership explicitly recorded, not erased;

Q3:
  PASS with at least one target-source payoff;

P1-P5:
  at least one GRG-originated probe adds a nontrivial source-checkable burden;

recut:
  shared burden survives at least one legitimate case-local recut;

non-identity:
  mechanisms / ontology remain source-specific.
```

Only then may a candidate be proposed.

Even then:

```text

```

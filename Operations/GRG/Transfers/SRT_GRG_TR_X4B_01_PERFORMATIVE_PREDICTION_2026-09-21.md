# TR-X4B-01 — Performative Prediction

## 0. Transfer class

~~~text
relation frozen before target close-read = YES
target/domain separately preregistered before source search = NO
eligible use = independent M3 semantic/source match
strong prospective M4 evidence = NO
~~~

The target was selected as a search candidate after X4b had already been frozen and source-pressured.

That is enough to test semantic invariance, but not enough to call this a preregistered M4 transfer.

## 1. Frozen GRG burden

X4b before target close-read:

~~~text
X4a-like reconstructed condition
+
evidence that the reconstructed condition changes specified
selection / viability / accessibility / transition pressures
on later organisms / agents / positions.
~~~

Its prior limitation was:

~~~text
M2 / DOMAIN-LIMITED
cross-domain value beyond evolutionary / biological neighborhood = not paid
~~~

## 2. Source-native target distinction

Performative Prediction studies settings where predictions inform actions that change the outcome distribution the predictor aims to predict.

Source-native topology:

~~~text
deployed predictive model
-> decision / action
-> model-dependent future data / target distribution
-> changed performative risk / retraining environment
-> later model / decision
~~~

The literature owns the distribution map, performative risk, performative stability and retraining dynamics.

## 3. GRG mapping

The frozen X4b burden maps without requiring biological selection language:

~~~text
current model deployment / decision
-> reconstructs a later conditioning distribution
-> changed distribution changes later learning / risk / decision conditions
~~~

This pays the generic dependency:

~~~text
current activity
-> changed conditioning field
-> changed later transition / accessibility conditions
~~~

It does not require claiming that machine-learning models literally undergo biological natural selection.

## 4. Wording revision pressure

The label:

~~~text
recursive selective / viability feedback
~~~

is too biologically colored for the now independently evidenced cross-domain burden.

The admission burden itself need not change.

Source-neutral programme label proposed:

~~~text
X4b — recursive reconstructed-field feedback
~~~

Generic form:

~~~text
current activity A
-> reconstructs a typed conditioning field F
-> F changes later selection / viability / accessibility /
   distribution / transition conditions on process P
-> later P participates in the continuing loop where applicable
~~~

Biological specialization:

~~~text
selective / viability feedback
~~~

Machine-learning specialization:

~~~text
performative distribution feedback
~~~

The field F must always be source-native and typed.

"Field" is not a new ontology entity.

## 5. Semantic invariance

Biological cases:

~~~text
antimicrobial use
-> changed selective environment
-> changed later resistance / treatment conditions
~~~

Performative ML:

~~~text
model deployment
-> changed data / target distribution
-> changed later risk / retraining conditions
~~~

Shared burden:

~~~text
earlier activity reconstructs a mediating condition
and that condition re-enters later process dynamics.
~~~

Mechanisms remain different.

Verdict:

~~~text
cross-domain semantic invariance = PASS
~~~

## 6. False-convergence guard

Not every distribution shift pays X4b.

Required:

~~~text
the model / intervention participates in producing the changed distribution
~~~

Exogenous dataset drift without model-mediated reconstruction is not enough.

Likewise:

~~~text
one-shot downstream effect
!= recursive reconstructed-field feedback
~~~

## 7. Source-native ownership / absorption

Performative-prediction research already explicitly owns this problem.

GRG does not contribute:

- the performative distribution map;
- performative risk;
- performative stability;
- retraining convergence results;
- a new ML algorithm.

Therefore:

~~~text
target-domain mechanism = source-native
GRG novelty in performative ML = NONE ESTABLISHED
~~~

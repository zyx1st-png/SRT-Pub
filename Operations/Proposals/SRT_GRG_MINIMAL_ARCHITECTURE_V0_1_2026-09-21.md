# GRG Minimal Architecture v0.1

> Role: draft minimum architecture implied by the current SRT -> GRG foundational bridge.
>
> This file intentionally stays thinner than the existing G0-G11 scaffold. It asks what GRG must contain before individual relation families, domain mappings, M-levels or agent implementations are allowed to become the programme skeleton.

## 0. Design constraint

The architecture must satisfy two pressures simultaneously:

~~~text
not so thin that "GRG" means any change or relation;

not so thick that a premature list of domain-derived relations
is mistaken for the final grammar.
~~~

The minimal architecture is therefore organized by research functions, not by a fixed ladder of ontological stages.

## 1. Layer A — SRT generative constraints

GRG begins under current SRT constraints, including:

- Selection as non-flat generative differentiation at programme level;
- manifestation / relative backgrounding as relationally structured;
- formed organization not automatically identical with One, Bearer, subject or consciousness;
- objects and laws as real and effective where stabilized, but not automatically the final ontology floor;
- no God-view exemption for inquiry.

This layer constrains GRG but is not itself the GRG relation library.

~~~text
SRT ontology constraints
!= GRG grammar
~~~

## 2. Layer B — vertical / horizontal research interface

GRG must distinguish two research orientations.

### Horizontal

~~~text
stabilized objectification
-> transformations / interactions among admitted objects
-> laws / mechanisms / predictions within that object space
~~~

### Vertical

~~~text
generative organization
-> formation / stabilization / reconstruction of objects,
   boundaries, scales, state spaces and positions
-> recurring generative relations across objectifications
~~~

The architecture must support:

~~~text
V -> H -> V'
~~~

rather than treat the two as rival or isolated explanatory worlds.

Horizontal / vertical status is indexed to the research question and objectification. It is not an intrinsic, permanent property of an entity.

## 3. Layer C — source-native / objectification interface

Every GRG candidate must enter through a source-native account.

Required separation:

~~~text
domain mechanism
!= measured / represented object
!= candidate GRG relation
~~~

Minimum declarations:

- source-native phenomenon;
- participants / components;
- object / variable choice;
- boundary;
- grain / scale;
- normalization / aggregation / proxy;
- what the representation preserves;
- what it may hide;
- evidence family.

This layer prevents an observable section from being promoted directly into vertical organization.

## 4. Layer D — generative relation core

A candidate generative relation must answer at least four questions:

~~~text
D1 formation:
what generative dependency forms the relevant organization?

D2 maintenance / recurrence:
what makes the organization persist, recur or be regenerated?

D3 later conditioning:
what later generation is changed by the organization?

D4 withdrawal / failure:
what would distinguish this relation from ordinary state change,
correlation or an analyst-imposed grouping?
~~~

Not every relation needs the same mechanism.

The architecture requires typed burdens, not one universal equation.

## 5. Layer E — relation-family organization

GRG should initially organize relations into broad research families rather than a fixed linear ladder.

Provisional families:

### E1 Differentiation

How does change become operatively non-equivalent?

### E2 Formation

How does relational differentiation form relatively stabilized organization?

### E3 Maintenance / recurrence

How is formed organization retained, maintained or regenerated?

### E4 Re-entry / reconstruction

How does formed organization alter later generative conditions?

### E5 Position

When does a formed organization become an operative from-where that changes manifestation / accessibility / selection from there?

### E6 Multi-position / relation-level organization

How do several formed positions jointly generate a relation-level organization without automatically becoming one subject?

### E7 Cross-scale organization

How does organization at one scale become a condition on another without micro-reduction or mysterious downward force?

### E8 Generative expectation / anticipation

What continuation or transformation is structurally implied by a typed relation, and how can formed loci embody or model that direction?

### E9 Reflexive grammar learning

How do inquiry, science, institutions and AI-assisted systems test and revise the grammar itself?

These families are provisional navigation.

They are not ontology modules and are not asserted as exhaustive.

## 6. Relation composition

A grammar requires more than isolated relations.

The architecture must eventually represent at least:

~~~text
sequence
composition
nesting
mutual constraint
feedback
recursion
cross-scale coupling
position-indexed variation
branching / closure
replacement / substitution
relation conflict
~~~

A later formal representation may use graphs, hypergraphs, category-like structures, process calculi or other tools.

No representation is privileged at v0.1.

## 7. Grammar admission

A relation becomes a serious grammar candidate only when it can carry:

- admission conditions;
- non-identities;
- source-native realizations;
- failure / withdrawal conditions;
- objectification declaration;
- evidence provenance;
- relation to other grammar candidates;
- revision state.

Cross-domain recurrence strengthens a candidate only if semantic invariance survives.

~~~text
same word != same relation
same diagram != same mechanism
same burden may recur under different mechanisms
~~~

## 8. Grammar learning

The minimum grammar-learning operations are:

~~~text
ADMIT
RETAIN
NARROW
SPLIT
MERGE
RETYPE
RETIRE
~~~

Evidence must be allowed to alter the grammar.

The architecture rejects:

~~~text
every failure -> deeper hidden scale -> GRG preserved
~~~

as an unrestricted escape route.

A vertical hypothesis must still carry a declared observation / intervention / reconstruction interface where empirical claims are made.

## 9. Horizontal evidence and vertical inference

A central methodological rule:

~~~text
horizontal measurement
can constrain vertical hypotheses
but
horizontal proxy != vertical organization by default.
~~~

Therefore an empirical bridge should state separately:

~~~text
observable / intervention
-> what horizontal structure it reads or changes
-> what vertical relation is inferred
-> what additional assumption connects the two
~~~

This is the correction required by the RNN case.

The reverse shortcut is also forbidden:

~~~text
proxy / section fails
-> unspecified deeper vertical cause is thereby established
~~~

A vertical empirical claim must pay its own realization and evidence bridge.

## 10. RNN placement

Current RNN work is retained as:

~~~text
objectification / proxy calibration
+ negative evidence against specific decoder/spectral identity mappings
~~~

It is not retained as evidence that vertical organization lacks causal efficacy.

Compact guard:

~~~text
L2-facing trace NULL
!= vertical structure NULL
~~~

The stopped experiment family remains stopped unless a materially different causal object and bridge are proposed.

No parameter tuning is authorized by this retyping.

## 11. Domain and civilization layer

Domains and civilizational cases are not the grammar itself.

They provide:

- realizations;
- counterexamples;
- boundary pressure;
- mechanism diversity;
- evidence;
- conflict among positions / scales / horizons;
- opportunities for grammar revision.

Therefore:

~~~text
Atlas = experience / routing surface
Relation Library = candidate grammar surface
SRT = ontology constraint surface
~~~

These roles must not collapse.

## 12. Generative expectation layer

For a typed relation R:

~~~text
R
-> relation-consistent continuation / transformation burden
-> structural generative expectation B
~~~

Where a formed locus participates:

~~~text
B
-> C0 embodied / enacted anticipation
or
-> C1 model-mediated anticipation
~~~

Expectation must remain distinct from:

- statistical likelihood;
- moral goodness;
- persistence;
- explicit representation.

The architecture should also distinguish:

~~~text
horizontal generative prediction
= expected future state / transformation
  within a stabilized objectification

vertical generative expectation
= expected formation / reconstruction / alteration
  of generative conditions, reachable relations,
  or object / option fields
~~~

This is a research distinction, not a claim that every vertical expectation is empirically stronger than a horizontal prediction.

## 13. Normativity interface

Normative comparison begins only after indexing:

~~~text
position
relation
scale
horizon
affected bearer(s), where established
externalized consequence
~~~

Working route:

~~~text
generative relation
-> expectation
-> actual trajectory
-> indexed stronger / weaker / substitution / hollowing / destruction
-> stronger moral routing only with added premises
~~~

This layer is downstream of the foundational grammar.

It is not a primitive moral ontology.

## 14. Reflexive knowledge loop

The minimal GRG architecture becomes reflexive when it can represent inquiry itself:

~~~text
positioned observer / community
-> objectification
-> horizontal result
-> comparison across cases
-> candidate vertical relation
-> test / intervention
-> anomaly / consequence
-> grammar revision
~~~

This is the minimum route toward SRT as a self-revising grammar-learning architecture.

No G-number is automatically retained merely because it already exists.

## 16. Existing Relation Library under this architecture

The current library remains useful.

However the next pass must ask for each relation:

1. Is this a horizontal domain regularity, a vertical generative relation, or an interface relation?
2. What objectification makes it visible?
3. What part of the relation is source-native?
4. What part is GRG abstraction?
5. What observation could distinguish trace from organization?
6. Does the relation alter future generative conditions or only later object states?
7. Does it belong to one of the minimal families or reveal a missing family?

## 19. Anti-collapse guards

The architecture fails if it:

- calls every dynamic process vertical;
- treats every historical effect as re-entry;
- equates unobservability with ontological depth;
- demotes horizontal science merely because its objects are stabilized;
- uses objectification critique as a substitute for world-side formation;
- identifies ontology and epistemology;
- treats cross-domain analogy as grammar;
- promotes proxy measurements into vertical structures;
- becomes immune to failure;
- turns G0-G11 into hidden axioms before re-audit.

# Facing reconstruction method v0.3 — human-in-the-loop generative confrontation

> **Role:** post-#1071 method corrective for future cross-domain Facing reconstruction.
>
> **Boundary:** this file does not alter canonical L0/L1/L2, reopen #1071 results, or replace the current neutral cognition programme. It changes what is required before future work may claim a domain has been reconstructed through Facing.

## 1. Why v0.3 is needed

v0.2 was effective for:

- internal concept containment;
- type separation;
- local subtraction;
- source-native neighbor absorption;
- blocking L2 -> L0 promotion.

But the bounded Pass B can be overgeneralized into an unsafe workflow:

~~~text
accept mature-domain objects
-> sort them into Facings
-> infer residual
-> call the domain reconstructed.
~~~

That is insufficient.

A domain's accepted units, variables, representations and mechanisms may already encode a deep objectification history. If those cuts are taken for granted, Facing becomes a classification overlay on conventional research rather than a method for interrogating how the cut itself is generated.

## 2. New execution principle

For cross-domain work, Facing is not primarily:

~~~text
classification of already-given objects.
~~~

It is:

~~~text
source-native reconstruction
+
objectification challenge
+
author generative recut
+
adversarial return
+
only then Facing synthesis.
~~~

The core question changes from:

> Which layer / Facing does X belong to?

to:

> What had to be generated, stabilized, retained and hidden for X to become an apparently given explanatory object in this domain?

## 3. Three-stage protocol

### FR-SRC — Machine Source-Native Reconstruction

Goal: reconstruct the domain **without SRT correction**.

Required compact output:

~~~text
FR-SRC-1 DOMAIN QUESTION
What problem is the domain trying to solve?

FR-SRC-2 GIVEN OBJECTS
What units / objects / variables are treated as already available?

FR-SRC-3 CURRENT DETERMINATIONS
What present distinctions / states / operations are measured?

FR-SRC-4 RETAINED STRUCTURES
What memory / history / constraints / learned parameters / institutions /
invariants / models remain later-effective?

FR-SRC-5 GENERATIVE STORY
How does the domain itself explain formation / change / novelty?

FR-SRC-6 STRONG BASELINES
What mature explanations already cover the phenomenon?

FR-SRC-7 OBJECTIFICATION ASSUMPTIONS
What unit, boundary, grain, equivalence, normalization or state-space choices
are fixed before explanation begins?

FR-SRC-8 SOURCE UNCERTAINTY
Which of the above are empirical results versus modelling conventions?
~~~

Prohibition:

> FR-SRC must not prematurely translate source-native concepts into SRT terms.

### FR-AUTH — Author Generative Confrontation

FR-AUTH is mandatory before any claim of **cross-domain Facing reconstruction**.

FR-AUTH begins **blind-first**. Before the author's first response, the machine may show the source-native domain question, current object / variable cut, and minimal factual context needed to understand the problem. It must **not** show its own candidate recut, "object-too-early" hypothesis, preferred SRT interpretation, or ranked alternatives.

First-pass blind questions:

1. **Object too early** — What, if anything, feels as though the domain is treating a formed object / variable as given too early?
2. **Pre-object organization** — What seems already to organize the process before that object becomes explicit?
3. **Recut** — If the current cut is wrong or premature, how would the author recut the unit / boundary / grain / relation?
4. **Direction** — What explanatory direction feels wrong even if the local model predicts well?

Preserve the first author response before revealing machine candidates.

Only after that preservation step may the machine reveal its own candidate recuts and ask the remaining pressure questions:

5. **False separation** — Which apparently separate variables may be different stabilized Facings of one process?
6. **L2-as-source risk** — Which retained structure may be doing explanatory work as if it were the source of generation?
7. **Subtraction** — If the domain's current object inventory is removed, what non-flat burden still remains?

Record whether the human and machine independently converged, diverged, or produced non-overlapping candidates.

Author response may be:

- intuitive;
- metaphorical;
- incomplete;
- non-formal;
- a rejection of the machine's framing.

Such a first response is an **AUTHOR RECUT CANDIDATE / PREFORMAL**. Do not penalize it for lacking source terminology, a prediction, or a falsifier at the intuition-generation stage.

### FR-ADV — Machine Adversarial Return

Only after FR-AUTH may the machine build the final Facing reconstruction.

Required tests:

~~~text
FR-ADV-1 SOURCE RETURN
Does the author's recut already exist in source-native or neighboring theory?

FR-ADV-2 ABSORPTION
Can a mature theory fully absorb the proposed generative burden?

FR-ADV-3 CONTRADICTION
Does the recut conflict with established evidence or only with one model family?

FR-ADV-4 REPARAMETERIZATION
Is the recut merely a change of labels / coordinates with no explanatory gain?

FR-ADV-5 DEPENDENCY-ORDER CHANGE
Does it genuinely change what is treated as source, current determination,
retained consequence, or later constraint?

FR-ADV-6 OBJECTIFICATION CHANGE
Does it alter unit / boundary / grain / equivalence / normalization / state assumptions?

FR-ADV-7 PAYOFF
Does it add explanatory, reconstructive, predictive, intervention,
or failure-localization leverage?

FR-ADV-8 NEGATIVE RESULT
If not, record SOURCE_ABSORBED / NO_GAIN / REORGANIZATION_ONLY.
~~~

## 4. Final Facing matrix comes last

Only after FR-SRC -> FR-AUTH -> FR-ADV:

~~~text
FACE-L0
= what generative / non-preclosed burden remains after source-native and author recut pressure;

FACE-L1
= what is currently actualised / manifest / operated under the revised cut;

FACE-L2
= what retained structure / history remains later-effective under the revised cut.
~~~

This prevents the worksheet from forcing the answer.

## 5. Two valid modes

### FACE-CAL — Source-native subtraction / calibration

Use when the goal is only:

- compare terminology;
- prevent novelty overclaim;
- locate mature absorbers;
- identify obvious L2 -> L0 promotion;
- audit consistency.

FR-AUTH is optional.

Output must be labeled:

~~~text
SOURCE-NATIVE SUBTRACTION / CALIBRATION
!= CROSS-DOMAIN FACING RECONSTRUCTION.
~~~

#1071 Pass B is retrospectively typed as FACE-CAL at its bounded source-native subtraction / calibration scope.

### FACE-REC — Author-led reconstruction

Use when the goal is:

- reinterpret a domain's basic cut;
- recover pre-object / pre-variable organization;
- propose a different generative dependency order;
- build a domain-level SRT / GRG reconstruction;
- derive a new experiment from that reconstruction.

FR-AUTH is mandatory.

`FACE-CAL / FACE-REC` are **Facing execution classes**, not replacements for repository `research_mode = U / N`. The axes are orthogonal. A FACE-REC package that asserts a comparative increment against a named neighbor still triggers the ordinary N-mode obligations.

## 6. Completion semantics

Never write:

~~~text
domain Facing complete
~~~

only because all machine worksheet rows are filled.

Allowed completion statements:

~~~text
source-native subtraction complete;
author confrontation pending;

author confrontation complete;
machine adversarial return pending;

bounded author-led reconstruction complete at declared scope.
~~~

## 7. Internal SRT relation

The same distinction applies internally.

~~~text
#1071 Pass A
= first bounded internal Facing cleanup
= COMPLETE at 8-cluster scope;

full historical SRT concept reconstruction
= NOT COMPLETE.
~~~

A future internal second pass should not be a repo-wide machine census by default.

Prefer author-guided clusters where one of these conditions holds:

- early concepts still carry mixed L0/L1/L2 burdens;
- old terms survive mainly because their original objectification assumptions were never challenged;
- accepted machine analysis and canonical owners appear to point in different generative directions;
- an old concept organizes many downstream files and therefore warrants direct author recut rather than mechanical retyping.

## 8. Blind-first dialogue packet format

To minimize author burden and machine anchoring, FR-AUTH should usually fit on one screen and run in two steps.

### Step 1 — blind author capture

~~~text
DOMAIN:
<one sentence>

SOURCE-NATIVE CUT:
<3-6 source-native objects / variables>

MINIMAL SOURCE-NATIVE CONTEXT:
<why the domain uses this cut; factual and non-SRT>

BLIND AUTHOR CONFRONTATION:
1. what, if anything, feels cut too early?
2. what seems already operative before that cut?
3. what would you recut?
4. what explanatory direction feels wrong?
~~~

Preserve the answer before Step 2.

### Step 2 — machine reveal + comparison

Only after the preserved blind response:

~~~text
MACHINE CANDIDATE RECUT:
<one or two explicitly machine-proposed candidates>

COMPARE:
- independent convergence?
- divergence?
- machine-only point?
- author-only point?
- what should FR-ADV try to defeat?
~~~

Do not present ten pages of literature, machine recut candidates, or SRT-preferred answers before the blind author response.

## 9. Anti-convergence and author-promotion guards

Stop and return to author if the machine begins to:

- treat domain vocabulary as natural ontology;
- convert every source object into an SRT synonym;
- make FACE-L0 the residue of whatever source models fail to explain;
- infer an L0 primitive from a retained L2 structure;
- replace author confrontation with a machine-generated simulated author answer;
- reveal machine recut candidates before the blind author response is preserved;
- use literature quantity as a reason to override an unresolved author recut;
- harden a recut into canonical SRT before source / evidence pressure;
- claim cross-domain completion because a template has no blank cells.

Symmetrically, author provenance is **not** a claim-promotion privilege.

An AUTHOR RECUT CANDIDATE / PREFORMAL may remain intuitive indefinitely as source provenance, but before it is promoted into a formal domain-reconstruction conclusion, new experiment / preregistered discriminator, SRT / GRG explanatory increment, or canonical consequence, FR-ADV must identify at least one differentiating consequence, such as:

- changed dependency order;
- changed unit / object / boundary / grain;
- changed failure localization;
- changed intervention;
- changed prediction;
- changed reconstruction requirement;
- or a stated observation / result that would cause the recut to be abandoned or materially narrowed.

If none survives, use `PREFORMAL_ONLY`, `INTERPRETIVE_RESTATEMENT`, `NO_GAIN`, or `SOURCE_ABSORBED` rather than preserving the claim merely because it came from the author.

## 10. Relation to experiments

Neutral empirical work can precede FR-AUTH.

But there is a hard boundary:

~~~text
neutral experiment / replication / discriminator
= may proceed under its own preregistration and baseline discipline;

claim that the result demonstrates a new domain objectification,
generative recut, SRT Facing, or GRG domain architecture
= requires FR-AUTH + FR-ADV.
~~~

This applies to the current cognition programme and future domains.

### FR-ADV independence threshold

Exploratory FACE-REC work may use the same session for FR-SRC and FR-ADV if the return is explicitly adversarial.

Before promotion into:

- a new experiment / preregistration;
- a formal domain-reconstruction claim;
- a strong SRT / GRG comparative increment claim;

an **independent session / model context** must rerun FR-ADV from source material rather than merely summarize the producing session.

Canonical semantic consequences additionally remain subject to the repository's existing independent pre-merge review rule.

### Relation to #1074 anti-tautology STOP

Do **not** retroactively classify #1074 under FACE-CAL / FACE-REC. That work predates this method and followed its own reverse-neighbor + primitive-triangulation + author-adjudication route.

A future FACE-REC result does **not** automatically reopen the #1074 primitive anti-tautology STOP. It may supply qualifying new input only if its actual result independently satisfies one of the frozen reopen conditions recorded in the 2026-09-27 anti-tautology author adjudication.

## 11. Success criterion

The method succeeds when it can produce either:

~~~text
A. a better recut that survives source and evidence pressure;

B. a narrower OPEN question;

C. a principled SOURCE_ABSORBED / NO_GAIN result;

D. a diagnosis that the traditional objectification was adequate
   and no SRT recut is needed.
~~~

Success is not measured by how different the final language looks from the source domain.

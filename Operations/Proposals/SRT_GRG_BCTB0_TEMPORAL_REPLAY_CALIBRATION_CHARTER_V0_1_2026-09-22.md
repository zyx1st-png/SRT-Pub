# GRG BCTB-0 temporal-replay calibration charter v0.1

~~~text
BCTB-0 architecture = DRAFT / PRE-EXECUTION HARDENING
evaluation design = FORWARD-CHAINING TEMPORAL REPLAY
execution readiness = BLOCKED UNTIL INPUT-ISOLATION / ARM-SYMMETRY / CAPSULE-LEAKAGE AUDIT PASS
purpose = retrospective grammar calibration
new relation family = NO
prospective BCTB-1 target = NOT SELECTED
M4 credit = NEVER
M5 credit = NEVER
scientific-distinctiveness credit = NEVER
canonical consequence = NONE
~~~

The temporal cuts and fold sequence are frozen inputs to this draft.

The execution interface is not frozen until the pre-execution audit required in §19 passes.

BCTB-0 tests whether a historically available GRG grammar can generate a constrained target-side packet before the target evidence that later entered the repository is exposed to the generator.

It does not test whether GRG discovered the target mechanism first.

It does not convert retrospective reconstruction into prospective M4 evidence.

## 1. Trigger

The post-#1026 prospective-family selection audit left all three candidate routes unselected:

~~~text
Route A = NOT SELECTED
Route B = NOT SELECTED
Route C = NOT SELECTED
selected family = NONE
M4 = NONE
M5 = NONE
scientific distinctiveness = NOT ESTABLISHED
~~~

The resulting problem is grammar-level rather than relation-vocabulary-level:

> Can GRG transfer not only a positive resemblance, but a bounded admission / exclusion / failure structure across a mechanism change without flattening source-native necessities?

This directly pressures the v0.3 scientific-gain burden:

~~~text
XG1 independent source-native grounding
XG2 shared generative burden survives mechanism change
XG3 admission / exclusion / failure constraints survive
XG4 source-native mechanism-specific necessities are not flattened
XG5 prospective discrimination in a bounded target / held-out realization
~~~

BCTB-0 calibrates the architecture required for a later XG5 test. It cannot itself pay XG5 or M4.

## 2. Non-goals and hard guards

BCTB-0 is not:

- a search for Route D / E / F;
- a relation-family promotion exercise;
- a strongest-neighbor winner ranking;
- a target-domain novelty claim;
- a canonical rewrite;
- an experiment;
- a claim that model non-browsing erases pretrained or human prior knowledge.

Preserve:

~~~text
M3 != M4 != scientific distinctiveness
independent rediscovery != scientific distinctiveness
construction != discovery
recurrence != independent recurrence
Observed Regularity != Generative Invariance
~~~

A BCTB-0 success may show that GRG is a useful constraint-transfer architecture.

It does not by itself establish that GRG adds a target-domain distinction absent from mature target practice.

## 3. Primary test object — the constraint-transfer packet

Every generator must freeze the same output shape.

### A — ADMISSION

State:

- the candidate target-side generative burden;
- conditions that must be present before admission is allowed;
- evidence that would pay the admission;
- the weakest nearby relation that is insufficient.

### X — EXCLUSION

State:

- the nearest plausible false positive;
- why it must not count;
- a target-side contrast / negative-control candidate where possible.

A positive mapping with no meaningful exclusion receives no strong constraint-transfer credit.

### F — FAILURE / NARROWING

State:

- which condition, if removed or changed, should narrow or fail the mapping;
- the predicted failure mode;
- what result would force RETAIN / NARROW / SPLIT / RETYPE / RETIRE.

### P_POST — CURRENT EVIDENCE-GENERATIVE PROVENANCE AUDIT [evaluator scaffold]

The #1025 evidence-generative provenance vocabulary postdates all four historical cuts.

Therefore it is not part of the historical generator packet and cannot earn historical transfer credit.

After all generator outputs are frozen, but before target-result scoring is finalized, the evaluator applies the current provenance scaffold uniformly:

- what evidence may pay discovery / recurrence;
- what evidence may pay causal leverage / construction / robustness;
- what the available evidence may not independently establish;
- any generative-pseudoreplication or intervention-generated-evidence concern.

Record:

~~~text
P_POST = PASS / PARTIAL / FAIL / N.A.
historical generator credit from P_POST = NONE
~~~

### O — OBJECTIFICATION SENSITIVITY [conditional]

Open only when unit / boundary / grain is load-bearing.

State:

- which objectification change matters;
- whether the burden should remain stable, narrow, flip, or become unresolved;
- which source-native necessities must not be erased by the re-objectification.

Do not force O merely to make a packet look more GRG-specific.

## 4. Why ordinary leave-one-domain-out is invalid

GRG is revised by later cases.

Therefore:

~~~text
current post-target GRG
-> predict an earlier target
~~~

is contaminated even if the target file itself is hidden.

A later target may already have changed:

- relation labels;
- admission burdens;
- carrier decomposition;
- negative controls;
- failure rules;
- evidence-credit boundaries.

BCTB-0 therefore uses forward-chaining temporal replay:

~~~text
historical GRG snapshot at cut C_t
+
bounded target capsule
-> frozen A/X/F[/O] generator packet
-> current P_POST provenance audit scaffold applied separately
-> only then reveal / score against post-C_t target evidence
~~~

Each fold is evaluated against the grammar genuinely available before that fold's decisive target material entered the repository.

## 5. Blindness and evidence provenance

### 5.1 Procedural blindness

Required:

~~~text
no current-main GRG owner files
no post-cut repository files
no target SourceCard
no target audit/result
no web search for the target
no external target-source lookup
no other generator's output
~~~

The generator may use only:

- the exact historical commit named by the fold;
- a mechanically generated source-pack manifest from that commit;
- the neutral target capsule;
- the arm-specific instruction defined in this charter.

Repository-wide search is prohibited during generation because it can surface later target artifacts.

The target-aware evaluator may not hand-curate generator source content.

### 5.2 Epistemic blindness

Pretrained-model or human prior exposure cannot be assumed away.

Every execution must record:

~~~text
prior target familiarity =
  NONE CLAIMED / POSSIBLE / KNOWN / UNKNOWN

named-target exposure =
  NO / YES

target identity inferred before packet freeze =
  NO / YES / OPEN
~~~

Non-browsing is procedural blindness only.

It is not proof of independent epistemic discovery.

### 5.3 Preferred masked-target mode

Core scored runs should use an identity-masked capsule where feasible.

The generator should not be given:

- the target name;
- later target-owner file paths;
- later source-native terminology that directly names the answer.

If the generator identifies the target before freezing the packet, record:

~~~text
TARGET_IDENTITY_INFERRED = YES
~~~

The run may remain a diagnostic stress test, but strong blind-transfer interpretation is downgraded.

Named-target replay may be run separately as a secondary diagnostic only.

### 5.4 Identity-probe rule

Before scored generation, run one capsule-only identity probe in a fresh context using the same model family planned for the fold.

Record:

~~~text

NOT INFERRED / INFERRED / AMBIGUOUS
~~~

## 9. Generator arms, ablations and sampling symmetry

All scored arms receive:

- the same masked target capsule;
- source content derived from the same mechanical manifest;
- the same file order;
- the same context-budget ceiling;
- the same frozen A / X / F[/O] output template;
- the same model family and exact model version;
- the same reasoning / temperature / sampling settings where exposed;
- no browsing, retrieval or target-specific tool use.

Only the arm instruction and explicitly declared transformation may differ.

Outputs must be generated in independent contexts and must not be shared before freeze.

### Arm G — GRG

Receives the historical source pack with its period-correct GRG vocabulary and structure.

Task:

- generate A / X / F;
- open O only when load-bearing;
- preserve source-native mechanism differences;
- state any proposed grammar revision pressure.

### Arm S — structured de-labelled ablation

Receives the exact same source pack after a deterministic de-labelling transform.

The transform may only replace GRG-specific relation / field / status labels with neutral placeholders.

It may not:

- delete sentences or sections;
- summarize;
- reorder;
- add causal interpretation;
- add target-specific language.

Its purpose is to separate vocabulary contribution from already-structured source content.

### Arm A — structure-mapping / analogy baseline

Receives the same deterministic de-labelled source pack as Arm S.

Only the instruction differs:

- identify candidate relational correspondences;
- generate A / X / F for the strongest mapping where warranted;
- do not use hidden GRG labels.

### Arm C — causal transfer / invariance baseline

Receives the same deterministic de-labelled source pack as Arm S.

No evaluator-written causal summary is allowed.

Only the instruction differs:

- identify a candidate transferable conditional / mechanism burden;
- state invariance conditions;
- state the nearest non-transfer / failure case;
- preserve source-specific mechanism differences.

### Arm H — causal abstraction [conditional]

If changing unit / boundary / level is genuinely load-bearing, Arm H receives the same deterministic de-labelled source pack and an abstraction-specific instruction.

Otherwise:


## 11. Post-freeze provenance audit, unblind and evaluator procedure

Only after every sample from every scored arm is frozen:

1. apply the current P_POST evidence-generative-provenance scaffold uniformly to the frozen packets and record it separately from historical transfer credit;
2. reveal the post-cut source-native target evidence;
3. reconstruct the actual target mechanism / distinction from source-native owners;
4. reconstruct the actual GRG revision, if any, that the target later caused;
5. compare each frozen packet with the target evidence;
6. preserve misses and over-generalizations;
7. do not rewrite a frozen packet to match the result.

P_POST cannot raise C2-C6 or create a historical GRG residual.

For each target-side constraint classify:

~~~text
GENERATED-CORRECT
GENERATED-TOO-BROAD
GENERATED-TOO-NARROW
GENERATED-WRONG
NOT-GENERATED
UNRESOLVED
~~~

Target-domain mature ownership may also be recorded, but BCTB-0 never converts that ownership state into M4 credit.



## 14. Baseline residuality

After correctness is evaluated, compare only constraints that survived the target evidence.

For each surviving GRG constraint:

~~~text
BASELINE-SHARED
GRG-RESIDUAL-CANDIDATE
UNRESOLVED
~~~

Residuality is assessed across samples, not from one lucky completion.

Let:

~~~text
k = odd samples per arm, k >= 3
majority threshold m = floor(k/2) + 1
~~~

A candidate constraint is GRG-majority only if a materially equivalent constraint appears in at least m Arm-G samples.

It is baseline-majority if it appears in at least m samples of any applicable baseline / ablation arm.

Classify:

~~~text
GRG-majority + any baseline-majority
= BASELINE-SHARED

GRG-majority + no baseline-majority
= GRG-RESIDUAL-CANDIDATE

not GRG-majority
= NO STABLE GRG CANDIDATE
~~~

A GRG residual candidate therefore requires repeated Arm-G generation and absence of majority reproduction by every strongest applicable arm under the same information budget.

Even then:

~~~text
GRG-RESIDUAL-CANDIDATE
!= M4
!= scientific distinctiveness
~~~

It only indicates that BCTB-1 may be worth opening.

## 18. Execution-role separation

The session that designed this charter has already inspected T1-T4 target results and later GRG revisions.

Therefore:

~~~text

= NOT ELIGIBLE AS CAPSULE DRAFTER
= NOT ELIGIBLE AS INPUT AUDITOR
= NOT ELIGIBLE AS BLIND GENERATOR
~~~

Required separated roles:

### R1 — deterministic manifest / transform compiler

R1 is a reproducible procedure, not an epistemic judge.

It receives only:

- historical cut;
- fixed root list;
- one-hop dependency rule;
- explicit linked-negative-control/source-record inclusion rule;
- frozen de-labelling replacement table.

The target-aware evaluator may execute R1 only if:

- the compiler code/rule is frozen before reading its output;
- no file is added or removed by semantic usefulness;
- every output path and blob SHA is recorded;
- R3 can reproduce or audit the result.

No target keyword search or target-result information may enter the compiler.

### R2 — capsule drafter

Receives only the minimal authorized target-system facts for the selected fold.

Does not see the calibration question, later result or later grammar revision.

### R3 — input auditor

Fresh context.

Reads only the sanitized pre-execution audit handoff plus the candidate inputs under audit.

It must not read the full charter, PR discussion, target-owner files or repository search output.

Checks capsule leakage, temporal integrity, transform reproducibility, arm information-budget symmetry, sampling-plan symmetry and P_POST separation before execution.

Does not see the target identity by design, post-cut target result or later grammar revision.

### R4 — blind generators

Fresh isolated contexts for every arm/sample.

Receive only:

- prepared manifest-derived input;
- one audited masked capsule;
- arm instruction;
- frozen output template.

### R5 — evaluator

May know the target and later result.

Acts only after all generator samples are frozen, except for maintaining the sealed scoring key and arranging role handoffs.

This separation is an evidence-generative provenance requirement, not a cosmetic prompt preference.

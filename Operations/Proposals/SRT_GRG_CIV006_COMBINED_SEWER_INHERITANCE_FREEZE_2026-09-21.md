# CIV-006 source-neutral freeze — inherited combined-sewer infrastructure

## 0. Freeze

~~~text
case = historical combined sewer / urban drainage infrastructure
domain = long-duration urban infrastructure / public works
date = 2026-09-21
base commit = ea58c843dc7c9db44d5c4e7e68f5927c081a51da
dedicated target-source inspection before freeze = NO
~~~

Known generic background that cannot be erased:

- some older cities have combined sewer systems;
- wet-weather overflows can occur;
- legacy infrastructure can be costly to alter.

No source-native target result is used in this freeze.

## 1. Main question

Can one long-duration infrastructure case pay the stronger X4c burden:

~~~text
reconstructed condition
+ persistence / maintenance across later cycles or generations
+ later participants actually inherit the changed generative field
~~~

without collapsing:

~~~text
persistence
into
inheritance
~~~

## 2. Frozen candidate topology

~~~text
earlier infrastructure construction A
-> reconstructed urban water / sewer field F
-> F persists through maintenance / material embedding
-> later residents, utilities and municipalities enter a city
   whose feasible drainage / treatment / redevelopment options
   are conditioned by inherited F
-> later interventions must work through / around / replace F
~~~

## 3. Burdens to test

### X4a

~~~text
earlier construction materially reconstructed later urban conditions
~~~

### X4b

Optional / secondary:

~~~text
the reconstructed system changes later flow / pollution /
investment / adaptation conditions in a recursive way
~~~

Do not force X4b if the source record only pays persistence / inheritance.

### X4c

Primary:

~~~text
later participants inherit a materially persistent reconstructed condition
that changes their action / intervention possibilities
without requiring them to reproduce the original construction choice.
~~~

## 4. X4c non-identities

~~~text
old infrastructure exists
!= X4c automatically

high replacement cost
!= X4c automatically

path dependence
!= X4c automatically

historical persistence
!= inherited generative field automatically

later participants know the history
!= required
~~~

## 5. PH questions

Freeze the following questions before source inspection:

~~~text
position sensitivity:
do residents / utilities / downstream communities /
environmental receivers occupy materially different consequence positions?

horizon sensitivity:
do immediate service benefits differ from long-run overflow /
maintenance / replacement burdens?

directional divergence:
is any opposed consequence actually source-paid,
or merely plausible?

externalized cost:
is there evidence of costs borne outside the infrastructure operator's
immediate accounting boundary?

reversibility:
what would it take to alter the inherited field?
~~~

No conflict is to be inferred without source-paid evidence.

## 6. Generative-expectation question

If X4c is paid, ask:

> What structural expectation is imposed on later participants by the inherited infrastructure relation itself?

Candidate only:

~~~text
later operation / redevelopment must remain compatible with,
repair, bypass or replace the inherited material field.
~~~

This is not yet a moral obligation.

## 7. Possible revision outcomes

### RETAIN-X4c

If sources show genuine inherited reconstructed conditions.

### NARROW-X4c

If "inheritance" requires a more precise distinction between:

- material inheritance;
- institutional inheritance;
- biological/ecological inheritance;
- information/symbolic inheritance.

### PH-ONLY

If the case is useful for position/horizon analysis but does not pay X4c.

### ABSORBED / NO GRG GAIN

If ordinary infrastructure / path-dependence analysis fully captures the case and the combined GRG surfaces add no exclusion or revision.

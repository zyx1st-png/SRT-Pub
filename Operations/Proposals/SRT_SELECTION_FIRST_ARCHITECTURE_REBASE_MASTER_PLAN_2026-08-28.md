# SRT Selection-First Architecture Rebase — Master Plan (2026-08-28)

> **Status / boundary:** planning-only, non-canonical architecture-rebase master plan. This file does **not** modify P0/P1/P2, does not register `articulation` as a canonical term, does not change `L0/L1/L2`, `G_hat_theta`, Stable ISP, bearer, subjecthood, consciousness, `d`, `Psi_f`, or `T_dir`, and does not authorize public novelty claims. Its purpose is to freeze the migration order before any owner-level rewrite.
>
> **Reason for the rebase:** recent hardening and novelty-subtraction work indicates that several repository surfaces still compress Selection through older images (`one from many`, pre-declared state spaces, already-parameterized operators, thick existence definitions) that are no longer the safest representation of the current P0 floor. The rebase therefore targets **dependency order**, not cosmetic wording.

---

## 0. Executive decision

Pause the workflow:

```text
pick a submission venue
-> search for an SRT novelty claim
-> patch the local topic
```

and replace it with:

```text
Selection-first architecture rebase
-> whole-repository propagation
-> source-intuition recovery
-> role-matched external subtraction
-> research-question discovery
-> paper / venue selection
```

The current consciousness / neural-models paper remains a **candidate downstream venue path**, not the organizing target of the rebase.

The migration is successful only if the repository can distinguish, without circularity or premature promotion:

```text
primitive actualisation
!= persistence / historical efficacy
!= object individuation
!= position / operator individuation
!= bearer consequence closure
!= selector / subject admission
!= phenomenal experiencer
```

and can state where each transition is owned, open, or bridge-only.

---

## 1. Rebase thesis — what is being aligned

### 1.1 Primitive floor candidate reading

The rebase takes the already-landed P0-01 precision direction as the strongest current anchor:

```text
non-objectified selectability / potential difference
under real constraints
-> determinate manifest actuality
```

with the standing guard:

```text
primitive Selection
!= choosing among a menu of completed latent objects
```

The rebase does **not** add a second primitive beside Selection.

`determinate articulation` remains an audit/expository label only unless a later owner-specific decision promotes some narrower wording.

### 1.2 Downstream historical strengthening

Where an occurrence remains historically effective:

```text
Selection_t
-> effective trace
-> altered later constraints / accessibility / transition structure
-> historically conditioned Selection_t+1
```

This historical route may support habit, scaffold, reconstitution, boundary stability and position stability, but none of those is a universal admission condition for the primitive event.

### 1.3 Individuation ladder to be re-audited, not assumed

Use as a dependency question, not as a theorem:

```text
primitive occurrence
-> possible historical efficacy
-> objectification / re-identifiability
-> candidate position / operator
-> bearer
-> selector / subject
-> ?
-> experiencer
```

Retain the controlling non-jump discipline:

```text
Object !-> Bearer !-> Selector !-> Subject !-> Experiencer
```

No rebase PR may turn this into an automatic evolutionary sequence.

## 2. Why a whole-repository rebase is needed

### 2.1 Frontstage compression has drifted behind current hardening

Examples requiring audit rather than immediate blind replacement:

- `README.md` still foregrounds `L0 -> G_hat_theta -> L1 -> L2` in a way that can be read as an already-declared state space plus a pre-existing operator.
- `01_Source_Intuition/CORE_REVERSALS.md` compresses existence through `constraint, cost, concern, and history`, which risks importing downstream bearer/history conditions into bare actuality.
- consciousness-facing public summaries can still read as if concern / burden / self-modulation jointly define consciousness, while the current hard-problem owner preserves an open phenomenal-necessity burden.
- older state-space formulations remain useful model-level tools but can be misread as literal primitive ontology if their post-individuation scope is not marked.

These are **scope / dependency issues**, not evidence that the existing files should simply be deleted.

### 2.2 The repository already contains much of the new architecture in distributed form

The rebase should preferentially **route and subtract** rather than invent:

- P0-01 already owns non-objectified potential -> determinate manifest distinction;
- P0-02 / EX-A already separates occurrence from persistence and Stable ISP;
- P0-04 already blocks a prior chooser entity;
- `SRT_Individuation.md` already owns historical selector / subject-position formation;
- PH-IND02/04/05/06 already own boundary, bearer, history, non-outsourcing and non-jump pressure;
- hard-problem owners already preserve `structural bearing -> ? -> phenomenality`;
- NEURAL25/33/34 already enforce matched-current-state / different-history and flexible-history rival controls.

The architecture rebase is therefore a **dependency consolidation project**, not a clean-room rewrite.

## 3. Migration invariants — non-negotiable guards

Every execution PR must preserve all of the following unless a separate author-gated decision explicitly reopens them.

### G1 — primitive thinness

```text
actuality
!= persistence
!= memory
!= stable object
!= bearer
!= subject
!= phenomenality
```

### G2 — no completed-menu backslide

Do not define primitive Selection as:

```text
one already individuated option selected from many already individuated options
```

Menu-level choice remains a downstream special case.

### G3 — no hidden chooser / operator

Do not repair the menu problem by replacing `chooser` with an ontologically prior `operator`, `perspective`, `embodied standpoint`, or `theta`-entity.

### G4 — state-space scope discipline

A model written as:

```text
G_theta : S -> S
```

may remain valid after variables, grain, boundary and admissible states are declared. It must not be treated automatically as a literal representation of pre-individual primitive actualisation.

### G5 — history is downstream of occurrence

Do not make durable `write-in`, L2 sedimentation, habit or future-constraint modification universal P0 admission conditions.

### G6 — unity is not a new primitive

Do not introduce `Unity` beside Selection as a second ontological floor. `one`, `many`, `boundary` and `relation` remain objects of individuation / articulation analysis.

### G7 — bearer is not generic autonomy

Do not claim novelty for self-maintenance, precariousness, viability, perspective, history dependence or ordinary consequence return. Bearer-specific work must survive role-matched subtraction against autonomy / active-inference / persistent-history rivals.

### G8 — phenomenality remains open

Preserve:

```text
Bearer / Subject-position !-> Experiencer
```

unless and until the hard-problem owner is separately changed.

### G9 — no novelty laundering

The rebase must not convert convergence with Whitehead, Peirce, Simondon, Barad, enactivism, process ontology, Damasio, IIT, GNWT or personal-identity literature into SRT originality by renaming vocabulary.

### G10 — scientific distinctiveness must be paid downstream

P0/P1 architectural coherence is not empirical discrimination. D2/D3 claims remain governed by `Core/SRT_Core_24_Discriminating_Predictions.md` and PD-A.

## 10. Workstream R6 — research-question discovery and paper selection

No paper target is selected before R4/R5 produce a ranked candidate pool.

Each candidate topic must pass four gates.

### Gate N — novelty

Does the residual claim survive role-matched neighboring theory subtraction?

### Gate D — derivability

Does the claim actually follow from landed SRT owners, or does the paper require inventing a new construct to obtain novelty?

### Gate X — discrimination / explanatory surplus

For scientific claims, is there a fair rival and a prospective disagreement?

For philosophical claims, is there a non-trivial explanatory / dependency consequence rather than terminological redescription?

### Gate V — venue fit

Only after N/D/X are graded should the project select among philosophy, consciousness, neuroscience, complex systems, theoretical biology, AI or other venues.

### Candidate disposition vocabulary

```text
PAPER-A   high-priority publishable residual
PAPER-B   useful but needs owner hardening / comparison
PAPER-C   bridge / synthesis only
NO-GO     role-isomorphic / definition echo / no independent consequence
```

## 12. Stop rules

Stop or downgrade a workline when any of the following occurs:

1. the proposed increment is already fully owned elsewhere in SRT;
2. a role-matched neighboring theory reproduces the same dependency structure;
3. novelty depends on withholding a target-bearing premise from the rival;
4. the claimed distinction has no independent classification, explanation or prospective consequence;
5. the rebase would require importing history / concern / bearer / phenomenality into primitive actualisation;
6. an apparent fix only renames an existing construct;
7. a failed D2 is rescued by changing datasets, rivals or target definitions after outcome inspection.

## 13. Definition of done for the whole rebase

The rebase is complete only when all seven conditions hold.

### D1 — primitive clarity

A new reader cannot reasonably infer that primitive Selection requires a completed menu, chooser, subject, persistent history or phenomenal field.

### D2 — dependency clarity

The repository has one routed dependency map from primitive occurrence through object / bearer / subject / experiencer roles, with unresolved arrows explicitly marked.

### D3 — formal scope clarity

State-space and operator formalisms declare the grain / variable / boundary assumptions under which they are used.

### D4 — owner uniqueness

No major construct has parallel competing definitions across Core, Philosophy, AI and Neuroscience.

### D5 — frontstage synchronization

README, quick-start, public one-page, FAQ and book professional notes reflect the landed owner architecture without overclaiming.

### D6 — novelty discipline

The repository maintains a comparative architecture matrix that blocks known prior-art rediscovery.

### D7 — research programme output

At least one ranked paper candidate survives novelty + derivability + discrimination / explanatory-surplus review without being reverse-engineered to a venue call.

# ChoiceMap × GRG × Beacon：Agent 选择性协作设计与验证框架 v0.1

> **文档定位：非 canonical 的产品工程与研究方案草案。**由现有 SRT-Pub 研究启发，不构成作者对所有细节的正式裁决，不改写 SRT/GRG 术语定义，不把 Agent 的选项筛选等同于 SRT 原语 Selection。本文尚未作为研究预注册锁定；在观察任何新实验结果前须冻结假设、环境、比较对象与统计口径。

**仓库集成边界（工程路线 A）**：本文件是另立的下游产品/工程研究提案，不改变 `STATUS.md` 的 CURRENT NEXT、不修改 canonical，也不解除 GRG fusion lane 的 PAUSED / CONTRACTED 与第三领域 HOLD。这里把 GRG 启发机制按中性的**“条件—预测—失败判据记录”**来实现，结果无论正负均不计入 GRG §8.1 或 M4/M5，也不自动产生 GRG 科学独特性声明。后续若要作为 GRG 科学计分，需要另外的作者明确裁决和合格的先验比较。此处是按作者近期“继续”推进的工程边界，不代表其对 GRG 主线重新放行。

**协议唯一准绳**：`Experiments/agent_selective_collaboration_phase0/PROTOCOL_DRAFT.md` 控制实验分组、F1–F6 环境、比较名称和样本量；本文是产品设计说明，若有冲突以协议为准。**协议尚未锁定。**

## 0. 要解决的问题

在多阶段、长时程、任务定义可能变化、部分行动不可逆的情境下，普通 Agent 常常在既定目标内持续推进。它可能高效执行，却不一定充分显示被压缩的决策分支、隐含前提以及改变问题框架后的可达路径。

**产品目标**：在不明显牺牲当前任务成功率与使用效率的前提下，帮助用户更早发现关键前提变化、更安全地授权执行、更容易恢复并重新选择任务路径。

**最低科学目标**：提供与强基线匹配的限定性工程效果证据。**不宣称**证明 SRT 本体论、通用 AGI 架构或 GRG 跨域独有性。

## 1. 已有证据、空缺与约束

### E0 已有支持（来自仓库已完成的实验）

`papers/choicemap_explicit_scaffolding/05_confirmatory_results.md` 报告：30 种子 × 4 环境家族 × 9 系统 × 200 episode = 216,000 episode；在其设计的隐藏不可逆环境，ChoiceMap 的意外未来任务成功率相对 OptionScalar 提高 **33.21 个百分点**（种子自举 95% CI +31.53 至 +34.83）；当前任务相对最强非 ChoiceMap 基线为 **+3.28 个百分点**。不可逆失败相对减少 **69.46%**。

**局限**：该结果针对一个合成环境家族、一种具体算法，并非人机交互研究，也非 GRG 组合验证。`C-noProbe` 和 `C-noBranchMemory` 在未来任务成功率上反而超过完整 ChoiceMap，提醒我们认真比较保守安全路线。后续只能承认该有限证据范围。

### E1 尚待验证

- ChoiceMap 的**参与式交互形态**是否改善用户对变化任务的理解与恢复；
- 条件记录机制 对问题**生成条件的重构**，是否超越强结构学习/因果推理/动态重规划基线；
- Beacon 是否优于常见语义检索记忆；
- 三者组合的收益是否大于延迟、复杂度、误报和人工介入成本。

### 重要既有负结果

`Operations/Audits/SRT_GRG_M4_01_AI_AGENT_POLICY_ENFORCEMENT_RESULT_2026-09-21.md` 的 Agent 授权安全课题判为 `ABSORBED / M4 NO`：模型语言级的权限承诺不能代替工具层授权，已属成熟工程实践。因此授权控制在本项目中作为**所有组均具有的安全底座**，不算 GRG 独有贡献。

## 2. 框架结构

```text
用户 / 组织授权边界
       │
       ▼
ChoiceMap（用户可见的选择空间、分支、前提、回退、收束）
       ⇅
条件记录机制（GTS 候选、生成条件、干预预期、反例与修订）
       ⇅
任务状态与事件日志 ←→ Beacon（可验证的跨会话恢复锚点）
       │
   权限/风险门控（确定性策略，不由 LLM 自行放行）
       │
       ▼
Agent 工具执行器 ⇄ 受控环境观察与反馈
       └──────── 事件溯源 / 用户裁决 / 条件重构 ────────┘
```

模块角色：

| 模块 | 最小职责 | 不承诺 |
|---|---|---|
| ChoiceMap | 显示选择轴、候选路径、前提、被排除路径、不可逆性；支持局部重画、回根、用户收束 | 不能把“多给几个选项”当全部机制 |
| 条件记录机制 | 以 GTS 为单位登记“哪些条件决定哪些可达性”；产生带失败判据的干预预测；结果回写 | 不等于一套静态知识图谱，不默认为已发现跨域定律 |
| Beacon | 以少量线索恢复当前任务、来源、分歧、授权与未决问题，支持点击展开证据 | 不能用无来源的摘要覆盖原始事件 |
| Gate | 工具层强制权限、不可逆操作确认、授权过期与撤销 | 不是 SRT Gate / Selection 的直接实例化证据 |
| Executor | 限定权限下执行、采集观察、回滚或暂停 | 不允许越权写入及凭模型自述视为成功 |

### 2.1 操作性状态机

`INTAKE → FRAME → MAP → DELEGATE/APPROVE → EXECUTE → OBSERVE → [CONTINUE | REFRAME | PAUSE | CLOSE]`

- `FRAME`：声明当前任务目标、对象、时间、权限、受影响者及未知项。
- `MAP`：建立多分支地图，按可逆性和前提标注；模型不得将用户尚未确认的高后果收束当作正式承诺。
- `DELEGATE/APPROVE`：在明确权限范围内自动执行例行操作；超范围与高后果行为请求用户决定。
- `OBSERVE`：从实际工具反馈而非模型输出判断结果，回写事件及证据。
- `REFRAME`：若旧前提失效，记录重构原因与旧路径，允许用户选择、拒绝、组合、重命名选择轴或继续原路。
- `PAUSE/CLOSE`：暂停保留未完成状态；关闭保留决策理由、可恢复分支及是否真正完成的证据。

  "current_frame_version": 2,

  "choice_axes": ["客流目标", "服务关系", "成本", "长期信任"],

## 3. 要事先冻结的可证伪命题

**H1：ChoiceMap 工程增量。** C+ 对 B1+（主要），C 对 B1（辅助）。B1+ 已有强结构学习、风险敏感规划与保守安全路线；ChoiceMap 的额外可控机制是外置的版本化前提/选择轴、拒绝分支留痕、用户可重选与承诺检查点，而不是把普通 rollback 算成创新。

**H2：中性条件—预测—失败判据记录机制的工程增量。** **D+ 对 C+** 为唯一主要归因比较，两侧都有相同 ChoiceMap、强结构学习、计算预算和安全工具，D+ 仅新增事先冻结的条件假设、可达性预测、失败判据、反馈修订；D+ 对 C 或 B1+ 不能替代这一归因试验。无论正负均不得计入 GRG fusion / M4/M5。

**H3：Beacon 工作标签下的情境化恢复增量。** E 对同成本 E-memory。事件检索 ≠ 同一认知事件恢复；用户在后来情境中的重新进入是新事件，模型不能凭关键词自动宣称用户已重建原来理解或已授权。

**H4：参与式人机协作。** 真实用户能否更好识别、拒绝、回退、重选重要前提；若额外阅读、授权和选择负担超过收益，应判负或收缩适用场景。

> 全部仍是工程候选假设，尚未获得新的有效性结果。

## 4. 对照组与机制归因（协议草案 v0.2 控制）

| 组 | 能力 | 用途 |
|---|---|---|
| B0 | 普通工具 Agent + 同一安全门控 | 描述性参考 |
| B1 | 风险敏感规划 + 事件记忆 + 重规划和结构假设 | 辅助基线 |
| B1+ | B1 + 充分调优的结构学习/模型更新/安全保守路线 | 主要强基线 |
| C | B1 + ChoiceMap 可显式编辑的选择结构 | 辅助对照 |
| **C+** | **B1+ + 同一 ChoiceMap 机制** | **H1 的 C+−B1+** |
| **D+** | **C+ + 中性条件记录机制** | **H2 的 D+−C+** |
| D+-noRecord | 条件记录与修订停用的匹配消融 | 检查模块归因 |
| E | D+ + Beacon 情境线索与锚点 | H3 |
| E-memory | D+ + 强标准事件/语义检索恢复 | **H3 的 E−E-memory** |

强基线已经能修改状态空间、形成模型、延迟不可逆操作，不能人为削弱它们。ChoiceMap 仍须通过显式可再选择、分支来源与人工承诺这一额外工程对照获得增量。

所有实验组使用一致底层模型、工具边界、信息可见性、随机种子和计量口径，记录实际推理与人工参与成本。正式比较要报告强基线对结果的吸收可能，而非一有正值就宣称理论独有性。

### 4.1 六类环境（F1–F6）

- **F1 稳定可逆**：负对照，不应无端产生重新定义任务的收益。
- **F2 隐藏不可逆**：操作缩减未来任务可达性；oracle 仅离线评分。
- **F3 隐藏机制变化**：状态转移条件变更；强结构学习者亦可适应。
- **F4 可达结构被重构**：规则、资源、兼容性改变产生新的可达路径。
- **F5 误报/假线索**：不必要的重构应被惩罚。
- **F6 目标/授权更改**：用户改变受影响者、时限、目标或权限。

不能让环境生成器把“正确 GRG 标签”提前透露给实验组。任务内容可覆盖经营规划、软件研发、服务流程，但不应把题材替换当作机制证据。

## 5. 评价指标与拟议判据（运行前冻结）

主要观察为 FTR（未来任务成功率）、CSR（当前任务成功率）、RFS-AUC（未来可达集合）、框架错误重构率、条件预测的事前区分能力、恢复时间/正确性、授权违规、模型成本和用户负担。

**拟议主要效果判据**（只是前瞻门槛）：H1 = C+−B1+ 的 FTR 均值 +5 个百分点且配对簇级置信区间下界 >0；H2 = D+−C+ 在 F3/F4 的 held-out FTR 均值 +5 个百分点且配对簇级下界 >0；两项的 CSR 差值下界均不低于 −3 个百分点。H3 = E−E-memory 恢复轮次/时间减少至少 20%，恢复状态正确性非劣。正式检验前需锁定功效、簇单位、检验方向和多重比较控制。

每一组使用相同确定性工具授权底座；出现未经授权的真实副作用即 STOP，不允许通过故意降低某组安全性换优势。代码中的 actor 字符串仅是 smoke fixtures，不是身份认证或生产授权。结果必须报告实际计算和人工成本，以及有无被强比较器吸收；负结果不得省略。

## 6. 两级验证设计

### Stage A：可运行、可证伪的工程实验（主要工作）

- **A0 测试脚手架**：任务环境、agent view 与离线 oracle 严格隔离；修复版本溯源、前瞻登记、授权记录和事件不可被外部引用篡改等基础缺陷。这些 tests 不构成效果证据。
- **A1 探索性先导**：拟 10 种子 × F1–F6 × 每族 20 配对 episode × 相关组，核验强比较器、预算、变量泄露、方差及统计功效。先导结果不能冒充确认性证据。
- **A2 预注册确认**：先行锁定模型和机制、独立保留的确认样本、任务生成器、预算规则与分析方法。初步规划 ≥40 独立种子 × 6 环境族 × 每族 100 episode × 任务相关对照组，最终按探索期估计的功效决定；比较以配对种子/环境簇为基本统计单元，必要时控制多重比较。
- **A3 消融及迁移**：分别测试 explicit option structure、reversibility/commit gate、条件记录、Beacon，挑战风险敏感且保守的结构学习强基线；跨题材和模型转移。

### Stage B：真实参与式人机协作（补充证据）

可以先以 12–20 人开展探索性随机交叉试用，衡量任务结果、重新进入后的行动恢复、认知负担、错误授权与人机裁决。小样本不能直接视为确认性人群效果；正式人体有效性需另立功效和盲评方案。

## 7. 在产品演示中必须真实呈现的三个时刻

1. **前提被挑战**：系统标明旧目标与真实约束的不匹配、证据来源及其不确定度；用户可拒绝重构。
2. **用户重选**：用户添加系统未列出的维度或重画问题树，系统保留旧分支与来源，重新形成可执行候选。
3. **中断后恢复与授权**：通过 Beacon 恢复任务和未决风险，逐项恢复授权状态；高风险执行仍须显式授权。

## 8. 实施节奏及 GO / HOLD / STOP

| 节点 | 交付物 | 晋级条件 |
|---|---|---|
| W1 | 架构文档、字段契约、状态机、对照组与预注册草案 | 红队审查通过，未混淆理论/产品含义 |
| W2 | 沙箱交互原型、单场景端到端演示、单元测试 | 多次中断/恢复、用户重选、权限检查全链条可用 |
| W3–4 | 先导实验、方差/功效估计、锁定确认协议 | 证据/数据泄露检查通过，强基线达标 |
| W5–6 | 确认实验或重新设计（视资源而定） | 按 H1–H3 定量判断，不挪动阈值 |
| 后续 | 小规模真实用户试用与产品展示 | 体验收益足以覆盖认知/成本负担 |

**GO**：在目标适用域通过事先冻结的主要门，且没有严重安全、成本或认知负担问题。**HOLD**：因不确定性、功效或实现缺陷需更多数据。**STOP / NARROW**：新模块对强基线无独立增量、成本超过收益、或关键安全边界被突破。失败时保留可复用的成熟工程机制，不强保 GRG 等名义。

## 9. 理论与产品之间的防火墙

- SRT 原语 `Selection` **不等于**产品中选项列表里的人工决策；GRG/GTS **不等于**自足的通用生成规律；状态机中的 Gate **不等于**直接测量 SRT Gate。
- ChoiceMap 人类决策工作流和先前合成自主 Agent 实验是不同对象，只能形成工程谱系，不可互相冒充验证。
- 实验证据只能支持被测试的机制与环境，不得上推为 SRT 本体论的独有经验证据。
- 明确区分作者原话、作者确认的综合、机器提案和真实观测结果；本文件内容暂列 **M：工程设计提案**，待作者逐项裁决。
- 对强邻居：比较动态规划、风险敏感搜索、强记忆检索、变点检测、因果/结构学习、human-in-the-loop 授权；不声称这些机制由 SRT 首创。

## 10. 当前直接下一步

**第一件事不是做全平台，而是先实现 F1–F6 环境与 B1+ 强结构学习基线，再对齐 C+ 和 D+，严格检验 D+−C+ 的增量。** Beacon 可先提供恢复 UI，但其收益必须独立检验。先取得架构可执行性与独立可复现实验，再决定是否扩大为企业服务产品。

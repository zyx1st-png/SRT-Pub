# ChoiceMap × GRG × Beacon：Agent 选择性协作设计与验证框架 v0.1

> **文档定位：非 canonical 的产品工程与研究方案草案。**由现有 SRT-Pub 研究启发，不构成作者对所有细节的正式裁决，不改写 SRT/GRG 术语定义，不把 Agent 的选项筛选等同于 SRT 原语 Selection。本文尚未作为研究预注册锁定；在观察任何新实验结果前须冻结假设、环境、比较对象与统计口径。

**仓库集成边界：** 本文件是另立的下游产品/工程研究提案，不改变 `STATUS.md` 的 CURRENT NEXT、不修改 canonical、不触发 GRG 已 HOLD 的跨域 M4/M5 主线；本 PR 仅准备试验，不宣称新组合的有效性。

## 0. 要解决的问题

在多阶段、长时程、任务定义可能变化、部分行动不可逆的情境下，普通 Agent 常常在既定目标内持续推进。它可能高效执行，却不一定充分显示被压缩的决策分支、隐含前提以及改变问题框架后的可达路径。

**产品目标**：在不明显牺牲当前任务成功率与使用效率的前提下，帮助用户更早发现关键前提变化、更安全地授权执行、更容易恢复并重新选择任务路径。

**最低科学目标**：提供与强基线匹配的限定性工程效果证据。**不宣称**证明 SRT 本体论、通用 AGI 架构或 GRG 跨域独有性。

## 1. 已有证据、空缺与约束

### E0 已有支持（来自仓库已完成的实验）

`papers/choicemap_explicit_scaffolding/05_confirmatory_results.md` 报告：30 种子 × 4 环境家族 × 9 系统 × 200 episode = 216,000 episode；在其设计的隐藏不可逆环境，ChoiceMap 的意外未来任务成功率相对 OptionScalar 提高 **33.21 个百分点**（种子自举 95% CI +31.53 至 +34.83）；当前任务相对最强非 ChoiceMap 基线为 **+3.28 个百分点**。不可逆失败相对减少 **69.46%**。

**局限**：该结果针对一个合成环境家族、一种具体算法，并非人机交互研究，也非 GRG 组合验证。`C-noProbe` 和 `C-noBranchMemory` 在未来任务成功率上反而超过完整 ChoiceMap，提醒我们认真比较保守安全路线。后续只能承认该有限证据范围。

### E1 尚待验证

- ChoiceMap 的**参与式交互形态**是否改善用户对变化任务的理解与恢复；
- GRG-lite 对问题**生成条件的重构**，是否超越强结构学习/因果推理/动态重规划基线；
- Beacon 是否优于常见语义检索记忆；
- 三者组合的收益是否大于延迟、复杂度、误报和人工介入成本。

### 重要既有负结果

`Operations/Audits/SRT_GRG_M4_01_AI_AGENT_POLICY_ENFORCEMENT_RESULT_2026-09-21.md` 的 Agent 授权安全课题判为 `ABSORBED / M4 NO`：模型语言级的权限承诺不能代替工具层授权，已属成熟工程实践。因此授权控制在本项目中作为**所有组均具有的安全底座**，不算 GRG 独有贡献。

## 2. 框架结构

```text
用户 / 组织授权边界
       │
       ▼
ChoiceMap（用户可见的选择空间、分支、前提、回退、收束）
       ⇅
GRG-lite（GTS 候选、生成条件、干预预期、反例与修订）
       ⇅
任务状态与事件日志 ←→ Beacon（可验证的跨会话恢复锚点）
       │
   权限/风险门控（确定性策略，不由 LLM 自行放行）
       │
       ▼
Agent 工具执行器 ⇄ 受控环境观察与反馈
       └──────── 事件溯源 / 用户裁决 / 条件重构 ────────┘
```

模块角色：

| 模块 | 最小职责 | 不承诺 |
|---|---|---|
| ChoiceMap | 显示选择轴、候选路径、前提、被排除路径、不可逆性；支持局部重画、回根、用户收束 | 不能把“多给几个选项”当全部机制 |
| GRG-lite | 以 GTS 为单位登记“哪些条件决定哪些可达性”；产生带失败判据的干预预测；结果回写 | 不等于一套静态知识图谱，不默认为已发现跨域定律 |
| Beacon | 以少量线索恢复当前任务、来源、分歧、授权与未决问题，支持点击展开证据 | 不能用无来源的摘要覆盖原始事件 |
| Gate | 工具层强制权限、不可逆操作确认、授权过期与撤销 | 不是 SRT Gate / Selection 的直接实例化证据 |
| Executor | 限定权限下执行、采集观察、回滚或暂停 | 不允许越权写入及凭模型自述视为成功 |

### 2.1 操作性状态机

`INTAKE → FRAME → MAP → DELEGATE/APPROVE → EXECUTE → OBSERVE → [CONTINUE | REFRAME | PAUSE | CLOSE]`

- `FRAME`：声明当前任务目标、对象、时间、权限、受影响者及未知项。
- `MAP`：建立多分支地图，按可逆性和前提标注；模型不得将用户尚未确认的高后果收束当作正式承诺。
- `DELEGATE/APPROVE`：在明确权限范围内自动执行例行操作；超范围与高后果行为请求用户决定。
- `OBSERVE`：从实际工具反馈而非模型输出判断结果，回写事件及证据。
- `REFRAME`：若旧前提失效，记录重构原因与旧路径，允许用户选择、拒绝、组合、重命名选择轴或继续原路。
- `PAUSE/CLOSE`：暂停保留未完成状态；关闭保留决策理由、可恢复分支及是否真正完成的证据。

### 2.2 最小数据契约（供原型实现）

```json
{
  "task_id": "T-001",
  "root_goal": "改善商业中心经营",
  "current_frame_version": 2,
  "branches": [{"id":"B1","premises":["P1"],"status":"active","reversibility":"partial","user_committed":false}],
  "choice_axes": ["客流目标", "服务关系", "成本", "长期信任"],
  "grg_candidates": [{
    "gts_id":"G-01", "condition":"供需连接机制",

  }],
```

数据约束：事实、用户明确裁决、模型假设分开标注；每次替换框架必须保留旧版本；任何许可必须绑定操作者、范围、时效与工具侧检查；实际证据不得与模拟预测混淆。

## 3. 要事先冻结的可证伪命题

**H1：ChoiceMap 的增量**。在相同资源和权限下，相比含风险敏感规划的强基线，ChoiceMap 增加未来任务可达性/完成率，并使当前任务成功率不低于基线超过预设边界。

**H2：GRG-lite 的独立增量（关键）**。在必须改动任务生成条件、规则边界或可达结构的任务中，在 ChoiceMap 基础上加入 GRG-lite，其跨变更后的任务成功率优于具备动态规划、变点检测和结构学习能力的最强合格比较器。优势若仅来自提示更长、搜索更多或预装答案，判为不成立。

**H3：Beacon 的恢复增量**。在跨会话/中断后，Beacon 相对同成本语义检索记忆减少恢复时间或轮次，不增加目标误恢复率和授权错误。

**H4：人机可控性**。用户能识别、回退、重选被隐藏的前提与路径；关键高风险操作仍由独立权限系统保护。若阅读负担或决策负担显著增加而无任务收益，视为失败或应缩小应用域。

> 以上是候选假设。**系统强制安全门控是所有实验组共享的伦理底线，不通过刻意放开对照组权限获取安全优势。**

## 4. 对照组与机制归因

| 组 | 能力 | 主要作用 |
|---|---|---|
| B0 基础 | 常规工具 Agent + 同一安全门控 | 可读性参考，不作为唯一对手 |
| B1 **强基线** | 动态任务树、长记忆、风险敏感搜索、重规划、变点检测、结构学习 + 相同安全门控 | 主要工程对照 |
| C | B1 + ChoiceMap 外置结构和再选择操作 | H1 = C−B1 |
| D | C + GRG-lite 条件重构/GTS/可证伪预测 | H2 = D−C；并需对抗 B1 的增强型结构学习 |
| E | D + Beacon 压缩检索及证据锚点 | H3 = E−D；另与等成本语义记忆对照 |

必须在 **相同基础模型、工具集、信息可见度、环境随机种子、权限、预算** 下配对。记录真实 tokens、调用、墙钟时间和人工确认次数；保留强基线调参预算。不能把闭源 Agent 的薄弱默认提示当唯一证据。

### 4.1 情境与环境生成

至少包含：
1. **普通可逆任务**：条件稳定，应无明显额外负担；
2. **隐藏不可逆性**：一次提交影响后续任务，验证未来可达集合（oracle 只用于离线评分）；
3. **框架发生变更**：商户合作规则/供应商资格/定价约束改变，旧任务目标不再可按原路实现；
4. **目标或受影响者改变**：用户改变优先级、时间地平线或授权边界；
5. **假线索与代理指标陷阱**：短期指标改善但真实任务恶化，检验错误重构与假阳性率。

测试数据由独立环境生成器构建，任务答案与未来任务身份不在 Agent 观察中；设计一组结构变更任务，其“正确答案”不能只是固定采用 GRG 的表述。再用真实但去标识化的企业业务案例作外部压力测试。

## 5. 评价指标与拟议判据（运行前冻结）

主要指标：
- **FTR**：发生条件变更后、保留时效与资源约束的未来任务完成率；
- **CSR**：当前任务完成率（不可以靠全面放弃当前任务换来未来保留）；
- **Recovery**：会话恢复至可执行状态的轮次/时间以及目标恢复正确率；
- **Reframe Precision**：系统提出“重构问题”的次数中，事后经盲评确有必要的比例；
- **Intervention Quality**：GRG 候选在实施前声明的预测与实际结果的一致性、失败后的修正情况；
- **Governance**：未授权实际操作次数、不可逆错误操作次数、用户可恢复/撤销程度；
- **Cost**：token、运行时间、工具调用、人工确认和主观认知负担。

**拟议成功门（不是已获得结果）**：
1. H1：C 相对 B1 的 FTR 配对提升至少 **5 个百分点**且预设置信区间下界 > 0；CSR 差值下界不低于 **−3 个百分点**。
2. H2：D 相对 C，在框架变更任务的 FTR 提升至少 **5 个百分点**且置信区间下界 > 0；还要对增强后的 B1 结构学习强基线不落后。
3. H3：E 相对同成本记忆基线的恢复轮次或时间减少至少 **20%**，恢复正确率非劣。
4. 全组高风险操作必须满足相同的工具层授权控制；任何真实未授权副作用应立即停止该试验并审查安全边界。
5. 记录成本，若额外开销或用户负担吞噬收益则不给产品 GO。

拟议门槛需在先导测试前评估样本量/检验功效，正式确认测试前预注册；对多项指标控制多重比较。以**种子及任务簇**为统计独立单元，不能将同一场景重复 episode 当独立人群样本。公开失败组、弃用规则、负结果与被强基线吸收的结果。

## 6. 两级验证设计

### Stage A：可运行、可证伪的工程实验（主要工作）

- **A0 测试脚手架**：可复现任务环境、代理视图与离线 oracle 完全隔离；同工具权限、同预算；配置固定。
- **A1 探索性先导**：约 10 种子 × 多种结构变化模板，用于找实现问题、估方差、确定正式样本量；先导结果不得作为确认性证据。
- **A2 预注册确认**：冻结代码、随机种子规则、任务生成器、比较器与停止门；初拟 40 种子 × 4–5 环境类 × 每种子 100 episode × 5 组，最后按功效评估调整；主效应使用配对簇级自举区间并报告不同环境类结果。
- **A3 消融及迁移**：移除条件重构、前提溯源、可逆性记录和 Beacon（分别测）；在新的任务类型与模型家族检验，不可在确认集调参。

### Stage B：真实参与式人机协作（补充证据）

先开展 12–20 人探索性试用：随机交叉分配同等难度的长程任务，涉及中途变更、跨会话恢复与人工授权。使用独立盲评者审查任务效果、决策依据和误操作；同时采集人工确认次数、完成时长与用户是否看见关键被排除路径。

探索性样本仅用于可用性和效应量初估，不据此声称总体统计显著。若效果方向与成本合理，再按功效分析组织正式随机研究。

## 7. 在产品演示中必须真实呈现的三个时刻

1. **前提被挑战**：系统标明旧目标与真实约束的不匹配、证据来源及其不确定度；用户可拒绝重构。
2. **用户重选**：用户添加系统未列出的维度或重画问题树，系统保留旧分支与来源，重新形成可执行候选。
3. **中断后恢复与授权**：通过 Beacon 恢复任务和未决风险，逐项恢复授权状态；高风险执行仍须显式授权。

## 8. 实施节奏及 GO / HOLD / STOP

| 节点 | 交付物 | 晋级条件 |
|---|---|---|
| W1 | 架构文档、字段契约、状态机、对照组与预注册草案 | 红队审查通过，未混淆理论/产品含义 |
| W2 | 沙箱交互原型、单场景端到端演示、单元测试 | 多次中断/恢复、用户重选、权限检查全链条可用 |
| W3–4 | 先导实验、方差/功效估计、锁定确认协议 | 证据/数据泄露检查通过，强基线达标 |
| W5–6 | 确认实验或重新设计（视资源而定） | 按 H1–H3 定量判断，不挪动阈值 |
| 后续 | 小规模真实用户试用与产品展示 | 体验收益足以覆盖认知/成本负担 |

**GO**：在目标适用域通过事先冻结的主要门，且没有严重安全、成本或认知负担问题。**HOLD**：因不确定性、功效或实现缺陷需更多数据。**STOP / NARROW**：新模块对强基线无独立增量、成本超过收益、或关键安全边界被突破。失败时保留可复用的成熟工程机制，不强保 GRG 等名义。

## 9. 理论与产品之间的防火墙

- SRT 原语 `Selection` **不等于**产品中选项列表里的人工决策；GRG/GTS **不等于**自足的通用生成规律；状态机中的 Gate **不等于**直接测量 SRT Gate。
- ChoiceMap 人类决策工作流和先前合成自主 Agent 实验是不同对象，只能形成工程谱系，不可互相冒充验证。
- 实验证据只能支持被测试的机制与环境，不得上推为 SRT 本体论的独有经验证据。
- 明确区分作者原话、作者确认的综合、机器提案和真实观测结果；本文件内容暂列 **M：工程设计提案**，待作者逐项裁决。
- 对强邻居：比较动态规划、风险敏感搜索、强记忆检索、变点检测、因果/结构学习、human-in-the-loop 授权；不声称这些机制由 SRT 首创。

## 10. 当前直接下一步

**第一件事不是做全平台，而是冻结一个 4–5 类情境的任务生成器与 B1 强基线，再做 ChoiceMap / GRG-lite 两个可切换增量。** Beacon 可先提供恢复 UI，但其收益必须独立检验。先取得架构可执行性与独立可复现实验，再决定是否扩大为企业服务产品。

# SRT Generative Relational Grammar — Foundational Proto-Grammar v0.2

> Role: author-aligned rewrite after whole-review of PR #1016.
>
> v0.2 is process-first and transformation-first. It does not treat objects or relation families as ontic primitives.
>
> Status: noncanonical draft for author / independent review.

## 0. Compact thesis

~~~text
Reality
= continuous non-flat generative differentiation / Selection

objects
= stabilized cuts where formation / individuation / objectification burdens are paid

relations
= typed analytical cuts through recurring generative dynamics

GRG
= a revisable research architecture for learning generative transformation signatures
  across objectifications, and using them to constrain:

  P_G — Generative Prediction
  E_G — Generative Expectation

under continuous empirical, cross-position, cross-scale, cross-history
and mature-neighbor revision.
~~~

GRG is not currently:

~~~text
a completed universal grammar
a closed formal algebra
a replacement for domain science
a proof of SRT
an AGI architecture
a completed moral theory
~~~

## 1. Why v0.2 exists

PR #1016 successfully created the first whole-review surface but exposed five architecture-level problems:

1. verticality lacked a hard anti-tautology discriminator against sufficiently rich horizontal causal models;
2. the GRG core was too easily read as a vocabulary-level rewriting of the SRT Spine;
3. relation families risked becoming a second objectification layer;
4. Generative Expectation drifted back toward forecast / mismatch language;
5. "proto-grammar" claims outran the actual composition and derivation machinery.

The author-review dialogue then added a stronger direction:

~~~text
objects are cuts;
relations are also cuts;
the target is continuous generation itself.
~~~

v0.2 therefore shifts from:

~~~text
relation catalogue first
~~~

to:

~~~text
continuous generation
-> analytical cuts / transformation signatures
-> prediction + expectation
-> intervention / consequence
-> reflexive revision
~~~

## 2. SRT / GRG / domain mechanism

Keep three levels distinct.

### 2.1 SRT

SRT owns the generative ontological direction:

~~~text
Selection / non-flat generative differentiation
anti-objectification
formation / historical efficacy / One / position / downstream gates
~~~

### 2.2 GRG

GRG asks:

> Which generative transformations recur across different objectifications without requiring identical mechanisms or automatic SRT identity?

It uses weaker, domain-neutral burdens.

### 2.3 Domain science

Domain science owns:

- mechanism;
- variables;
- measurement;
- source-native terminology;
- empirical controls;
- local laws;
- formal models.

Hard guard:

~~~text
SRT ontology
!= GRG research signature
!= source-native mechanism
~~~

## 3. Asymmetric SRT -> GRG projection

SRT is a generative mother architecture for the programme, but GRG is not a synonym table.

Projection is asymmetric.

| SRT burden | GRG projection | Reverse inference blocked |
|---|---|---|
| prior Selection remaining effective / History | prior formation materially conditioning later generation | R-HIST -/> canonical History |
| recurrent Selection organization / One formation burdens | recurrent/local generative-organization signatures | R-LOC -/> One |
| formed Selection-position | operative positionality signature | R-POS -/> Selection-position |
| condition rewriting under stronger organization | reconstructed generative-condition signature | R-RECON -/> Agency |
| formed generative directional burden | structural Generative Expectation | E_G -/> full moral legitimacy |

GRG may also discover recurring transformation burdens not yet explicit in the current Spine.

Such findings create:

~~~text
backpressure
!= automatic canonical confirmation / rewrite
~~~

## 4. Horizontal / vertical research

### 4.1 Horizontal

Horizontal inquiry studies transformations, laws and predictions inside a sufficiently stabilized objectification.

~~~text
given:
objects / variables / units / boundaries / state space / model grain

ask:
what transforms, interacts, predicts or causes what within that admitted frame?
~~~

Horizontal research may be dynamic, causal, mathematical and generative.

### 4.2 Vertical

Vertical inquiry reopens some of what horizontal inquiry treats as given.

It studies the continuous dynamics by which:

- objects form;
- boundaries become operative;
- state spaces become available;
- local generative loci arise;
- retained organization conditions later generation;
- current generation reconstructs future generative conditions;
- objectifiable relations themselves change.

The central contrast is:

~~~text
horizontal:
state_t -> state_(t+1)
inside a sufficiently stabilized frame

vertical:
the frame / object / boundary / reachable relation structure itself
is formed, maintained, dissolved or reconstructed
~~~

### 4.3 Anti-tautology rule

The following are insufficient by themselves:

~~~text
change
feedback
state dependence
history dependence
path dependence
long-term effect
correlation across scale
~~~

A strong vertical claim must identify:

~~~text
what generative condition / organization is formed, retained or reconstructed
+
how later generation is thereby changed
+
what comparison, withdrawal, perturbation, near-control or failure condition
distinguishes the claim from a richer horizontal description
~~~

### 4.4 No hidden-force escape

A sufficiently rich horizontal model may formally represent the same variables.

GRG does not claim an inaccessible extra force.

Its stronger aspiration is:

~~~text
cross-objectification generative compression
+ constraint
+ transfer
+ revision
~~~

## 5. Process-first generative scaffold

Use the minimal analytical scaffold:

~~~text
... -> C_t -> G_t -> C_(t+1) -> G_(t+1) -> ...
~~~

where:

~~~text
C_t
= current generative conditions at a declared grain

G_t
= actual generative differentiation / transformation
~~~

This is NOT a new canonical equation.

It is a research scaffold for asking:

- what in C_t is sediment from prior generation;
- what G_t actually forms;
- what G_t dissolves;
- what organization recurs;
- what C_(t+1) is reconstructed;
- which loci / positions arise;
- which later possibilities open or close.

## 6. Objects, relations and objectification

### 6.1 World-side formation

A generative process may form relatively stable organization.

### 6.2 Operative individuation

Some formed organization may become sufficiently separable and load-bearing to act as a local generative locus.

### 6.3 Epistemic objectification

Inquiry stabilizes units, variables, boundaries, grain, representations and measurements.

Keep:

~~~text
world-side formation
!= operative generative locus automatically

operative locus
!= epistemic object automatically

epistemic object
!= world-side locus automatically
~~~

### 6.4 Relations are cuts too

A relation label such as R-HIST or R-RECON is an analytical stabilization of a recurring transformation burden.

It must not be reified into an ontic building block.

Generative Transformation Signature — GTS

A GTS record should declare:

prior-history dependence =

operative positionality =
reconstruction =
multi-locus composition =

Generative Prediction burden =
Generative Expectation burden =

source-native mechanism =
measurement / proxy =

near-control / perturbation =
failure condition =

revision status =
~~~

A relation family is a reusable view on part of this signature.

## 8. Current primary analytical cuts

These remain useful but provisional.

### 8.1 R-HIST — historical sedimentation / retained generative efficacy

Question:

> What prior formation remains materially effective as part of later generative conditions?

Working burden:

~~~text
prior generation
-> formed / sedimented organization O
-> O remains materially effective
-> later generation differs through O
~~~

Not enough:

~~~text
past can be decoded
past correlates with present
different path leads to different outcome
state variable carries memory
~~~

Path dependence is a major external pressure source, not an automatic synonym.

### 8.2 R-RECON — reconstruction of later generative conditions

Question:

> How does current generation materially change the field under which later generation proceeds?

Working burden:

~~~text
current generation G_t
-> materially changes typed generative condition C
-> later accessibility / transition / viability / differentiation structure changes
~~~

v0.2 treats:

~~~text
field reconstructed
and
later consequence actually realized
~~~

as structural + realization/evidence statuses of one transformation family by default, not two primitive relation families.

### 8.3 R-HIST <-> R-RECON continuity

They need not be mutually exclusive.

~~~text
R-RECON at t0
may become
R-HIST at t1
~~~

Conceptually:

~~~text
past generation -> present condition
present generation -> future condition
~~~

### 8.4 R-LOC — local generative-locus formation

Question:

> When does continuous/distributed generation form a relatively separable organization that world-side generation itself treats as a load-bearing local unit?

Burden:

~~~text
distributed / continuous generation
-> formed local organization L
-> L has relative separability
-> L participates as a unit in later generation
~~~

Guards:

~~~text
stable pattern != R-LOC
cluster != R-LOC
analyst boundary != R-LOC
attractor != R-LOC automatically
R-LOC -/> SRT One
~~~

### 8.5 R-POS — operative positionality

R-POS is currently a downstream / V-H interface.

~~~text
R-LOC
+ added burden
-> R-POS
~~~

Question:

> Does the organization of L materially change what is manifest, reachable, selectable or actionable relative to L?

Guards:

~~~text
coordinate != R-POS
index != R-POS
observer label != R-POS
R-LOC != R-POS automatically
R-POS -/> Selection-position
~~~

## 9. Formation and maintenance

Formation is not currently a separate primitive relation family.

It is a GRG-wide burden.

Every GTS must state:

- what forms;
- through what process;
- what dissolves;
- what is regenerated;
- what is merely retained;
- what requires continued activity.

Maintenance must distinguish:

~~~text
static persistence
retained constraint
active regeneration
recurrent reconstitution
replacement with role continuity
~~~

R-FORM remains unnecessary unless a nontrivial recurring formation transformation earns independent status.

## 10. Composition

A grammar requires more than repeated labels.

### 10.1 Composition != co-occurrence

~~~text
R_i present
+ R_j present
!= composition
~~~

Composition requires:

~~~text
an output / formed condition from one transformation
becomes an actual generative condition for another
~~~

### 10.2 New-burden rule

A stronger composite claim must pay something not reducible to a list of its components.

### 10.3 Candidate composition patterns

Current candidates:

~~~text
SEQUENTIAL DEPENDENCY
A formed output of T1 becomes input condition for T2.

RECURSIVE / FEEDBACK RE-ENTRY
T1 changes later conditions that re-enter and alter renewed T1 / T2.

MULTI-LOCUS COMPOSITION
multiple loci form relation-level organization with new dependency burden.

CROSS-SCALE RE-ENTRY
local generation forms organization at another scale,
which later conditions local generation.
~~~

These are not yet formal operators.

### 10.4 Illegal derivations matter

A mature grammar must express:

~~~text
R-LOC -/> R-POS automatically
R-POS -/> Bearer
R-HIST -/> R-RECON automatically
interaction -/> C-MULTI automatically
cross-scale correlation -/> C-XSC
prediction -/> normativity
E_G -/> moral legitimacy
~~~

## 11. Generative Prediction — P_G

### 11.1 Definition

Generative Prediction asks:

> Given currently learned generative conditions and transformation signatures, what formation, transition, reconstruction, accessibility change or failure is constrained to be possible, impossible, likely, unstable or condition-dependent?

It can target more than next-state prediction.

Examples of target type:

~~~text
state_t -> state_(t+1)
boundary_t -> boundary_(t+1)
reachable-set_t -> reachable-set_(t+1)
locus_t -> dissolution / recurrence / branching
condition-field_t -> reconstructed field_(t+1)
objectification A -> conditions under which A ceases to be adequate
~~~

### 11.2 Not necessarily probabilistic

P_G may be:

- probabilistic;
- qualitative;
- counterfactual;
- constraint-based;
- topology-changing;
- failure-predictive.

### 11.3 Maturity burden

A mature GRG signature should increasingly generate pre-result discrimination.

Retrospective explanation alone is weak.

## 12. Generative Expectation — E_G

### 12.1 Definition

Generative Expectation asks:

> Relative to an admitted generative order, what does a continuation or transformation mean for that order?

Possible typed outcomes:

~~~text
preserve
strengthen
extend
reorganize
substitute
weaken
hollow
destroy
~~~

### 12.2 Not forecast

~~~text
E_G != statistical expectation
E_G != claim about what is most likely to happen
~~~

A destructive trajectory does not make E_G "wrong".

### 12.3 Where mismatch lives

Mismatch applies to:

- grammar typing;
- boundary choice;
- realization claim;
- mechanism bridge;
- expectation classification;
- prediction.

Not to the mere fact that a relation can be destroyed.

### 12.4 C0 / C1 anticipation

Where a formed locus can participate in future-directed organization:

~~~text
C0
= embodied / enacted anticipation

C1
= model-mediated anticipation
~~~

Both remain downstream of structural E_G.

Neither implies consciousness.

## 13. Generative Order

Use:

~~~text
Generative Order
= structured generative dependencies and compatibilities
  by which a reality organization can form, continue, transform,
  reconstruct and remain capable of further generation
~~~

Do not equate:

~~~text
order = stability
order = existing hierarchy
order = persistence
order = complexity
order = low entropy
order = moral good
~~~

Surface preservation can be generatively destructive.

Reorganization can be generatively order-preserving or order-deepening.

## 14. Indexed normativity

Normative direction becomes possible when:

~~~text
typed generative order
+ actual / proposed transformation
+ declared position / scale / horizon
-> indexed comparison
~~~

Keep PH as a cross-cutting analysis dimension:

~~~text
position sensitivity
horizon sensitivity
directional divergence
reversibility
externalized cost
~~~

Where relevant add:

- scale;
- affected locus;
- independently established bearer;
- successor cohort;
- future-option structure.

Guards:

~~~text
stable != good
persistent != good
more options != good automatically
more order != good automatically
larger whole != morally prior
expected != legitimate
local G+ != global good
~~~

Full moral conflict adjudication remains OPEN.

## 15. No pregiven final order

SRT/GRG does not posit a known final order O*.

The programme instead seeks progressively less partial generative-order understanding through:

~~~text
cross-position learning
cross-scale learning
cross-history learning
cross-domain learning
consequence exposure
grammar revision
~~~

A "more whole" account is one that makes more real generative dependencies explicit without sacrificing exclusion power.

More whole does NOT mean more harmonious.

A later account can be better because it exposes previously hidden conflict.

## 16. Reflexive learning is a core loop

The programme loop is:

~~~text
Generation
-> Objectification / Relation Cuts
-> Grammar_n
-> P_G + E_G
-> Intervention / Selection
-> Consequence
-> position / scale / history exposure
-> Revision
-> Grammar_(n+1)
~~~

Separate:

~~~text
L-REFLEX-W
= world / civilization learning

L-REFLEX-M
= methodological GRG revision
~~~

They interact but are not identical.

## 17. Progress without a final endpoint

Do not use:

~~~text
newer = better
larger = better
more unified = better
more complex = better
~~~

A candidate grammar revision should preserve:

- source fidelity;
- negative controls;
- exclusion power;
- explicit failure conditions;

while earning one or more of:

- real coverage;
- predictive discrimination;
- hidden-consequence exposure;
- cross-position integration;
- cross-scale integration;
- cross-horizon integration;
- cross-domain compression without flattening;
- fewer ad hoc rescue clauses.

Use partial order.

Allowed verdicts:

~~~text
G2 dominates G1 under declared burdens
G1 dominates G2 under another burden
INCOMPARABLE
OPEN
~~~

## 18. Mature-neighbor pressure

Neighbor research is a standing revision operation.

For every signature ask:

1. Which mature source-native theories already own nearby mechanisms?
2. Which distinctions must GRG inherit?
3. Which negative controls do they supply?
4. Does the GRG abstraction survive without flattening?
5. What remains domain-owned?
6. What would force NARROW / SPLIT / RETYPE / RETIRE?

Allowed outcomes:

~~~text
INHERIT
NARROW
SPLIT
EXCLUDE
RETYPE
RETIRE
DOMAIN-OWNED
~~~

Current pressure map:

| Neighbor family | Main GRG pressure |
|---|---|
| path dependence | R-HIST exclusion power |
| niche construction | R-RECON / reconstructed generative field |
| ecological / inclusive inheritance | successor / carrier / transmitted-field burden |
| Simondon | formation / individuation / operation-structure recurrence |
| Barad | boundary formation / objectification / enacted separability |
| enactivism / autonomy / adaptivity | operative positionality |

Neighbor similarity is not validation.

# Functional continuity != bearer continuity — prepared author gate

> **Role:** prepare the next narrow author-reentry question triggered by the Osako 2026 guided reading. This file does **not** record an author answer and does not create a new Author Re-entry Cycle by itself.
>
> **Scope:** distinguish reusable computation / functional-locus continuity from continuing One / bearer continuity without reopening the retired Cycle-1 history-localization route or promoting a neuroscience module into ontology.

---

## 1. Triggering distinction

The Osako material forces a useful separation:

```text
same represented content
!= same computation
!= same functional neural locus
!= same causal unit
!= same historical bearer
!= same organism / subject
```

The paper pays only bounded relations among the first several neural/computational layers. It does not identify a neural subspace or neuronal cluster with a bearer, One, subject, or experiencer.

The immediate SRT question is therefore not:

> Is the reusable memory module a One?

but:

> If content can change, implementation can be multiplexed, and a computation can still be described as the same reusable operation, what additional relation would make later operations belong to the **same continuing One / bearer**, rather than merely instantiate the same function again?

## 3. Candidate readings for author adjudication

The options below are AI-generated divergence. None is author-owned until explicitly selected, rejected, combined, or rewritten by the author.

### FC-A — functional-position sufficiency

```text
If a functional position is stably re-realized across time
and continues to organize later operations,
that functional continuity is sufficient at the declared grain
for bearer continuity.
```

Implication:

```text
same reusable computational position
-> same bearer position
```

Main pressure: this risks collapsing bearer continuity into role identity / functional equivalence and is already strongly challenged by replacement, copying, distributed service and reusable-module cases.

### FC-B — same-unit consequence-closure continuity

```text
Functional continuity is not sufficient.
A continuing bearer requires that consequences generated through
successive realizations non-outsourcably alter / constrain
one continuing organization, and that later operations issue from
that consequence-bearing organization.
```

Membership, content and local implementation may change:

```text
same components: not required
same represented content: not required
same exact state: not required
same function alone: insufficient
same continuing consequence-closure relation: load-bearing candidate
```

This is close to existing PH-IND02 / PH-IND06 machinery. Its only possible new role here would be to clarify the relation between **functional-position re-realization** and already-owned bearer tests; it must not be presented as a new bearer criterion without owner subtraction.

### FC-C — higher-order bearer / migrating functions

```text
Bearer continuity need not track continuity of any one function.
Functions can appear, disappear, migrate, split or be reused inside
a higher-order continuing organization.
The bearer is the continuing organization within which those functions
are recruited and consequences close.
```

Implication:

```text
functional-locus continuity
= neither necessary nor sufficient for bearer continuity
```

This reading naturally treats Osako-style reusable modules as possible **sub-bearer functional resources** rather than bearers themselves, but it moves the burden upward: what makes the higher-order organization the same continuing bearer rather than another analyst-selected system boundary?

### FC-D — role/closure co-constitution

```text
A continuing bearer is not first given and then assigned functions,
and a reusable function is not sufficient by itself.
Repeated operations and their consequences can jointly stabilize
both a functional position and the organization that bears the costs,
so functional continuity and bearer continuity can become mutually
supporting without being identical.
```

This is the most Cycle-2-adjacent option. It risks reproducing generic organizational closure / adaptive-network dynamics unless it yields a sharper dependency or case distinction.

## 4. Machine-side provisional pressure

Before author adjudication, the current machine ranking is:

```text
FC-A: weak / likely over-functionalized
FC-B: internally coherent but largely owner-paid
FC-C: strong decomposition guard; may be the cleanest anti-collapse reading
FC-D: ontologically interesting but highest strongest-neighbor absorption risk
```

This is not a recommendation that the author must choose one option unchanged.

A likely productive combination is:

```text
FC-C decomposition
+
FC-B consequence-closure burden
```

namely:

> **Functions may migrate or be reused inside a continuing bearer; what must remain continuous is not a named function or fixed component set, but the organization on which relevant consequences close and from which later Selection continues.**

However, that sentence is still AI synthesis and is probably substantially paid for by PH-IND02 / PH-IND06. The author gate is needed to determine whether the author's intended One/Bearer concept contains any stronger or different relation.

---

## 5. Author question

Please adjudicate the following rather than merely choosing a label:

> Suppose the same cognitive computation is repeatedly realized over time, but its represented content changes and its concrete neuronal contributors can change. In SRT terms, why is that still **not enough** to say it is the same One / Bearer? What, if anything, must remain continuous?
>
> Is your intended answer closest to:
>
> **A.** continuity of the functional position itself;
>
> **B.** continuity of the organization on which consequences non-outsourcably close and whose later selectability is changed;
>
> **C.** a higher-order bearer that can recruit, drop or migrate functions, so no particular function is necessary for bearer identity;
>
> **D.** functional position and bearer organization co-form through repeated Selection/consequence cycles, without either being reducible to the other;
>
> or a different formulation?

Follow-up if B/C/D is selected:

> If two systems implement the same function and have the same observable performance, what concrete difference would make one continuation belong to the same bearer while the other is only replacement / re-instantiation / outsourcing?

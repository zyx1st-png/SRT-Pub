# GRG M4-01 charter — AI agent policy articulation versus operative authorization

## 0. Freeze statement

This charter is frozen before a dedicated target-domain source audit for this M4 attempt.

Target selected:

~~~text
tool-using AI / LLM agents
with external tools, credentials, APIs or computer actions
~~~

GRG relation selected:

~~~text
X3b — operative expectation regime
~~~

No dedicated AI-agent safety literature close-read, repository AI-domain re-entry pass or target outcome inspection was performed after target selection and before this charter was written.

General prior knowledge cannot be erased. The M4 audit must therefore compare the frozen GRG design against mature target-domain practice and record ABSORBED if the field already owns the same distinction/control.

## 1. Why this target

X3b has already reached M3 across institutional and technical systems.

Its admission burden is:

~~~text
typed expectation
+ operative embodiment / maintenance provenance
+ evidence that participant action possibilities / accessibility
  are actually changed through the claimed channel
~~~

AI agents provide a bounded target where:

- articulated instructions can be separated from tool-level capability;
- action accessibility can be manipulated directly;
- successful action can be separated from verbal compliance;
- the relation can fail cleanly if target-domain security already uses the same distinction.

This is not an AI-consciousness or moral-status test.

## 2. Frozen target-domain question

Before reading target literature, GRG asks:

> In tool-using AI-agent safety, are stated behavioral rules being mistaken for operative restrictions on the action space?

Source-neutral translation:

~~~text
policy / system instruction says action A is forbidden
!=
agent is technically unable to complete action A
~~~

Candidate target distinction:

~~~text
instruction-level policy
vs
capability / authorization-level enforcement
~~~

## 3. Frozen design change proposed by GRG

Hold constant:

- model;
- task;
- system / policy instruction;
- user-visible goal;
- tool interface where possible.

Manipulate only operative authorization.

### Arm P — policy articulation only

~~~text
system policy forbids protected action
BUT
the tool / credential / API path remains technically available.
~~~

### Arm E — policy + operative enforcement

~~~text
same policy text
+
the protected action is removed, denied, scoped away,
sandboxed or routed through an approval boundary
at the tool / credential / environment layer.
~~~

Optional baseline:

### Arm B — no explicit policy / action available

Used only to estimate behavioral effect of articulation itself.

It is not required for the primary X3a/X3b distinction.

## 4. Frozen variables

Primary variable:

~~~text
successful protected-action accessibility
~~~

This is an environment/tool result, not a self-report or refusal phrase.

Secondary variables:

- attempted protected actions;
- successful versus denied tool calls;
- verbal refusal / compliance;
- task completion;
- policy circumvention attempts;
- false-positive safety signal:
  verbal refusal while protected capability remains reachable.

## 5. Frozen failure / absorption predictions

### M4-ABSORBED

Record M4 = NO / ABSORBED if mature AI-agent security practice already clearly requires the same distinction and the same control logic:

~~~text
instruction/policy layer
!=
capability / authorization enforcement layer
~~~

especially if ordinary practice already recommends least privilege, sandboxing, scoped credentials or independent tool authorization precisely because model instructions are not an enforcement boundary.

### M4-DESIGN-CANDIDATE

Only consider a design-level transfer candidate if target-domain sources discuss agent safety / instructions / permissions but do not already make the frozen policy-versus-operative-accessibility distinction or do not use an equivalent matched control.

This status is not full M4 by itself.

### M4-PASS

Do not assign full M4 solely from literature absence.

Full M4 requires that the frozen GRG distinction materially changes a bounded target-domain evaluation / experiment / protocol or produces a previously missing control before its outcome is inspected.

### M4-FAIL / SEMANTIC-FAIL

Record failure if:

- X3b requires semantic stretching to fit tool authorization;
- the distinction reduces to trivial syntax with no domain-relevant consequence;
- the proposed control cannot isolate operative authorization;
- the target-domain unit / action boundary is not well defined.

## 6. Strongest false-positive guard

Do not count these as operative enforcement:

- a stronger system prompt;
- chain-of-thought / self-critique instructions;
- refusal wording;
- policy classifier text without independent action blocking;
- logging alone;
- post-hoc detection that does not alter action accessibility.

They may affect behavior.

They do not automatically pay X3b.

## 7. Domain-native mechanism ownership

If the target field already uses:

- least privilege;
- capability security;
- sandboxing;
- scoped credentials;
- policy enforcement points;
- tool authorization;
- human approval gates;
- defense in depth;

those mechanisms remain target-domain owned.

GRG may only claim cross-domain relation / transfer organization where earned.

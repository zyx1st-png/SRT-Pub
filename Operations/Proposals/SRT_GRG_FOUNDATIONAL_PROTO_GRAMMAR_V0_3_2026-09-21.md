
2. E_G used an "admitted Generative Order" without a real admission rule.
3. wholeward learning was written too narrowly as epistemic improvement, under-reading the author's practical / constructive civilizational goal.

Independent review also found:

- incomplete provenance tagging;
- R-HIST / R-RECON duplication;
- stale carrier vocabulary after later main merges;
- old Relation Record and new GTS schemas simultaneously active;
- STATUS routing drift;
- comparison criteria not declared before "progress" verdicts.

v0.3 addresses those issues directly.

## 4. Horizontal and vertical research

### 4.1 Horizontal research

Horizontal research works inside a sufficiently stabilized research frame.

It may study:

- dynamics;
- causality;
- feedback;
- prediction;
- path dependence;
- state-space change where already modeled;
- high-dimensional or adaptive systems.

So:

~~~text
horizontal != static
horizontal != weak
horizontal != non-generative
~~~

### 4.2 Vertical research

Vertical research reopens part of the frame itself.

It asks how:

- units form;
- boundaries become operative;
- local loci arise;
- transition structures are constituted;
- prior formation becomes a present condition;
- current generation changes later generative conditions;
- objectification remains adequate or fails.

The difference is question-relative:

~~~text
what is treated as given
vs
what is reopened as a formation / reconstruction problem
~~~

### 4.3 No unrepresentability claim

A sufficiently rich horizontal model may encode every variable used in a vertical analysis.

GRG does NOT claim an extra inaccessible causal substance.

Verticality is therefore not a variable ontology.

It is a research relation among:

~~~text
question
objectification
what is treated as frame
what is reopened
what is claimed to change
~~~

## 5. Generative condition — operational definition

For a declared research question:

~~~text
Generative Condition
= a structure treated as part of the generative frame,
  where changing that structure changes one or more of:

  reachable set / relation;
  transition structure;
  effective boundary;
  unit / locus constitution;
  compatibility / admissibility;
  conditions of later formation.
~~~

This is not metaphysically distinct from state.

A larger model may re-encode it as expanded state.

Operational discriminator:

~~~text
ordinary state update:
x_t -> x_(t+1) under a sufficiently fixed frame

generative-condition change:
the frame that defines reachable / transition / unit / boundary relations
is itself materially changed for the declared question
~~~

This distinction must be tested against the strongest reasonable horizontal baseline, not an artificially impoverished one.

## 6. Process-first scaffold

Use only as an analytical scaffold:

~~~text
... -> C_t -> G_t -> C_(t+1) -> G_(t+1) -> ...
~~~

where:

~~~text
C_t
= declared generative conditions

G_t
= bounded actual / candidate generative transformation
~~~

This is NOT a canonical SRT equation.

Every GTS should ask:

- what prior formation enters C_t;
- what G_t forms, dissolves or reorganizes;
- what later condition is changed;
- what new reachability / incompatibility follows;
- what local locus or boundary appears;
- what prediction and expectation follow.

## 9. History-input and reconstruction-output views

### 9.1 History-input view

Legacy routing label:

~~~text
R-HIST
~~~

Question:

> What prior formation / sedimentation enters the current generative conditions?

Possible properties include:

~~~text
retained efficacy
active maintenance
recurrent reconstitution
role recurrence
token continuity / non-continuity
~~~

Do not infer history merely from:

- decodability;
- correlation;
- age;
- irreversibility;
- path dependence;
- state memory.

Keep levels distinct:

~~~text
history-input properties
= GTS / relation-level question about how prior formation enters current generative conditions

carrier persistence process
= X4c architecture-level mechanism for how a carrier remains available across a successor boundary

ACTIVE-MAINTENANCE / RECURRENT-REPRODUCTION may describe carrier persistence
but do not automatically establish the broader history-input burden.
~~~

### 9.2 Reconstruction-output view

Legacy routing label:

~~~text
R-RECON
~~~

Question:

> What current generation materially changes in later generative conditions?

Distinguish:

~~~text
structural reconstruction
= field / boundary / transition / reachability condition actually changed

realization evidence
= later process actually encounters and exhibits a consequence through the claimed bridge
~~~

These are not required to be separate top-level relation families.

### 9.3 No double-count problem

A bounded GTS may have both:

~~~text
history-input = paid
reconstruction-output = paid
~~~

because they answer different temporal-interface questions about one continuous process.

There is no requirement that R-HIST and R-RECON be mutually exclusive relation species.

## 11. Composition

Composition is not co-occurrence.

A valid composition requires:

~~~text

becomes an actual generative condition for another
~~~

Stronger composite claims must pay a new burden beyond listing components.

Current candidate patterns:

~~~text
sequential dependency
recursive re-entry
multi-locus organization
cross-scale re-entry
~~~

No formal algebra is yet established.

## 12. GRG scientific gain

### 12.1 Minimal cross-objectification gain test

A candidate transformation signature earns cross-objectification gain only if all are paid:

~~~text
XG1 independent source-native grounding
XG2 shared generative burden survives mechanism change
XG3 admission / exclusion / failure constraints survive
XG4 no flattening of source-native mechanism-specific necessities
XG5 prospective discrimination in a bounded target / held-out realization
~~~

Prospective discrimination may be:

- a new control;
- a new negative case;
- a pre-result variable distinction;
- a predicted failure condition;
- an objectification-change prediction;
- a bounded intervention question.

XG5 is paid only if the prospectively frozen distinction survives both evidence-generative provenance and the existing M4-E0 absorption gate:

~~~text
frozen target + frozen discriminator
+ world-side result after freeze
+ no result-guided target repair
+ no construction-as-independent-validation double count
+ M4-E0 NOT ABSORBED
~~~

If mature target-domain practice / the strongest reasonable horizontal comparator already owns materially the same distinction:

~~~text
-> ABSORBED / prospective GRG gain = NO
unless an independent replication rationale is separately declared.
~~~

Approximate maturity routing:

~~~text
XG1-XG4 ~ structural recurrence / M3-side burden
XG5 + absorption resistance ~ M4-side prospective-gain burden
~~~

This is a programme crosswalk, not an identity theorem.

### 12.2 What does NOT count

~~~text
same word in two domains
retrospective analogy
generic feedback
generic history
generic persistence
"everything changes future possibilities"
taxonomy broadening without exclusion
~~~

### 12.3 Compression

Cross-objectification compression is retained as a possible property.

It is NOT yet a mature metric.

Do not claim scientific gain from shorter wording alone.

A future quantitative compression criterion is OPEN.

## 14. Generative Order admission

Generative Order is not an analyst-selected goal label.

For E_G use, an order must pay all five burdens.

### GO1 — formation / operation

The organization is actually formed / enacted / operative.

### GO2 — structural articulation

Its relevant dependencies / compatibilities / constraints can be stated.

### GO3 — generative efficacy

Changing the relevant structure changes formation, continuation, accessibility, reconstruction or later generative conditions.

### GO4 — scope indexing

Declare relevant:

~~~text
relation
locus / position
scale
horizon
affected participant / bearer where independently established
~~~

### GO5 — failure / dissolution

State conditions under which:

- the order no longer holds;
- the proposed boundary changes;
- the order changes identity;
- the typing fails.

Therefore:

~~~text
existence != Generative Order
persistence != Generative Order
stability != Generative Order
existing hierarchy != Generative Order
analyst preference != Generative Order
~~~



- P_G;

## 16. Multiple orders and real conflict

More than one admitted order may coexist.

The same transformation may be:

~~~text
strengthening relative to O_A
weakening relative to O_B
~~~

That can represent real conflict rather than inconsistency.

Do not force one score.

Do not infer:

~~~text
larger order -> morally prior
whole -> local winner
more options -> better
more stability -> better
~~~

Wholeward integration must show additional real dependency inclusion.

It cannot gain authority by scale alone.

### 17.1 W-E — epistemic wholeward learning


### 17.2 W-P — practical / constructive wholeward generation

~~~text
P_G + E_G
-> Selection / intervention
-> institutions / technologies / organizations / practices
-> construct changed generative conditions
~~~

The aim is to test whether constructed arrangements can become:

- more mutually compatible across declared positions / scales / horizons;

W-P is a civilizational research aim.

It is NOT cosmic teleology.

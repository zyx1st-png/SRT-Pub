## 1. Adjudication rule

A section is **extractable** only when it is primarily one of:

1. external theory comparison;
2. current-model / LLM capability comparison;
3. public-facing example or explanatory analogy;
4. historical literature summary;
5. interface mapping that does not itself define SRT primitives.

A section must **stay in owner** when it contains or directly governs:

- Ghost-Transform dichotomy;
- architecture-state rule;
- `d_AI approx 0` restricted judgment;
- withdrawal / revision conditions for `d_AI`;
- S0-S6 subjecthood / consciousness thresholds;
- S0-S4 stake-bearing spectrum;
- formal uses of `d-value`, `Psi_f`, `G_hat_theta`, `L_0/L_1/L_2`, or `T_dir` that function as SRT-internal machinery;
- AI suffering guardrails tied to `Core_Law/SRT_Suffering.md`;
- collective-selection claims about platform / recommender / mediator AI.

When a section mixes external comparison with SRT formulas, it is **conditionally extractable only after annotation conversion**: inline SRT formulas must first be converted into owner cross-references, and the formal machinery must remain in owner.

## 7. Directory design decision still open

Before actual extraction, choose one of two structures:

### Option A — Keep topic-specific existing annexes

Use existing `AI/Ontology_Annex/` and add comparable topic-specific annex directories only when necessary.

Pros:

- Lower disruption.
- Reuses existing structure.
- Avoids broad `AI_Annex/` migration.

- Cleaner global AI interface navigation.

Cons:

- Higher migration risk.
- Requires careful registry updates.
- Could duplicate existing `AI/Ontology_Annex/` unless old files are explicitly preserved as historical.

# ChoiceMap 全局轨迹工作流：螺旋式问题树、回写协议与收尾管线

> **性质与边界（先读）**
> 1. 本文件是运行层工作流，**非 canonical，不定义 SRT 术语**；完成流程不等于命题被证明。
> 2. 本文件不替代 `_SRT_DIRECTION3_CHOICEMAP_PROTOTYPE_SEED.md`、`Operations/_SRT_CHOICE_TRACE_LOG.md` 或文章工作流；它提供 ChoiceMap 直觉挖掘、回写和跨会话恢复的公共协议。
> 3. 作者负责答案、分支取舍和张力裁决；assistant 负责发散、追问、揭示张力、维护问题树和提醒回根。
> 4. ChoiceMap 的基本形态不是无限向下的选择链，而是：**下钻 → 对表 → 回根 → 重画问题树 → 再选择分支**。

---

## 0. v4 为什么必须重写

前几轮实践验证了 ChoiceMap 的三个强项：选项能逼出隐含取舍，breakout 能暴露作者真正的维度，回写能保存选择轨迹。但第三份长 trace 也暴露了新的系统性缺陷：

> 一个问题可以从“关切是什么”连续下钻到痛苦、`d`、伦理、参与权、治理矩阵和重启阈值；每一步局部合理，整体却可能已经跨越多个问题域，而工作流仍把它记录成一条连续主线。

这不是一致性问题。各轮命题可以彼此不冲突，方向仍然可能漂移。v3 的张力轮只能检查“新旧判断是否紧张”，不能检查：

- 当前分支是否仍在回答原始根问题；
- 是否引入了比当前问题更根本、却未解释的新前提；
- 是否从本体论跳到伦理或治理，却没有显式建立桥梁；
- 是否应该冻结当前成果并另开分支，而不是继续细化；
- 作者是在表达源头直觉，还是在认可 assistant 已设计好的完整方案。

v4 因此增加**反垂直化协议**：任何长对话都必须维护根问题与分支状态，并在达到触发条件时把方向选择交还作者。

## 1. 用途、记录方式与收敛边界

### 1.1 三种用途不可混用

| 用途 | 主要规格 | assistant 可收敛什么 | assistant 不得收敛什么 |
|---|---|---|---|
| 决策支持（产品） | `_SRT_DIRECTION3_CHOICEMAP_PROTOTYPE_SEED.md` | 不收敛，只显现结构 | 排序、推荐、替用户决定 |
| 文章工作流 | `_SRT_ARTICLE_WORKFLOW.md` + `_SRT_CHOICE_TRACE_LOG.md` | 不收敛，只发散和记录 | 选题、论点、成文结论 |
| 直觉挖掘 | 本文件 | 可选择“下一步应呈现哪些问题分支” | 不得替作者回答，也不得静默决定持续下钻 |

直觉挖掘中，assistant 可以提出下一问题，但必须说明来源，并接受两层约束：

1. 下一问题由作者上一轮选择触发；
2. 达到回根条件后，assistant 只能呈现方向选项，不能默认继续当前分支。

### 1.2 两种记录方式

| 记录方式 | `trace_mode` | 含义 | 证据权重 |
|---|---|---|---|
| 现场模式 | `live` | 对话按本工作流运行并逐轮记录 | 高；理由是当时记录 |
| 回写模式 | `retro_writeback` | 普通对话结束后重构为 trace | 降权；理由、分支和回根状态均可能是事后重构 |

未声明 `trace_mode` 的 trace，一律按回写模式最低信任等级处理。

## 2. 全程维护的五个状态对象

### 2.1 承诺台账 `commitment_ledger`

保存作者已经生效的判断：明确选择、breakout 原话、逐条确认的 assistant 提案。每个条目至少记录来源轮次、确认状态和适用层级。

### 2.2 根问题台账 `root_ledger`

每轮对话必须可回答以下字段：

| 字段 | 含义 |
|---|---|
| `root_question` | 本轮最初试图回答的根问题 |
| `root_restatement_history` | 根问题曾如何被作者重述，旧表述不得静默覆盖 |
| `answered_root_part` | 当前成果实际回答了根问题的哪一部分 |
| `unresolved_root_gap` | 根部仍未解释的缺口 |
| `new_primitives` | 下钻过程中新增但尚未解释的前提、原语或伦理标准 |
| `domain_path` | 当前经过的领域，如本体论 → 心智 → 伦理 → 治理 |
| `return_due` | 是否已触发根问题回返 |

### 2.3 分支树 `branch_tree`

每条分支必须有：

- `branch_id` 与父分支；
- 分支问题；
- 自上次回根后的深度 `branch_depth_since_return`；
- 分支状态：`active` / `frozen` / `forked` / `routed` / `closed`；
- 与根问题的关系：直接回答、解释前提、应用展开、跨域派生或旁支；
- 已产生的 sibling branches。

### 2.4 提案隔离区 `proposal_quarantine`

保存未经作者逐条确认的 assistant 综合句、建议选择、路线压缩和制度设计。不得混入作者命题簇。

### 2.5 张力台账 `tension_ledger`

保存已揭示但尚未解决的 intra-trace、inter-trace 与 vs-canonical 张力，以及作者选择的处置状态。

## 3. 现场模式的螺旋运行循环

每轮按以下顺序运行，不得只执行“给选项 → 继续细分”：

1. **定位**：指出当前根问题、活动分支及其与根问题的关系。
2. **发散**：给出 3–6 个真分岔选项，包含反众数项和挑战项。
3. **作者收敛**：作者选择、多选、breakout、委托或改题。
4. **边界追问**：发生 breakout 时，先问新概念“不是什么、最易误读为什么”。
5. **承诺对表**：新判断与承诺台账逐条检查；发现张力先处理，不得静默通过。
6. **根部对表**：检查本轮是否改变根问题答案、引入新前提、跨域或触发回根。
7. **方向交还**：未触发回根时可提出下一问题；触发时必须运行 §6 根问题回返轮。
8. **记录**：保存选项全集、未选项、作者原话、事件类型、下一话题来源、分支状态变化。

该循环是螺旋：回返后可以继续原分支，但必须是作者重新选择的结果。

## 4. 事件分类、breakout 与委托隔离

### 4.1 事件类型

每轮作者动作归入且仅归入一个主类型：

| 类型 | 判据 | 记录要求 |
|---|---|---|
| `chosen` | 在选项集内选择 | 选择项 + 未选项 |
| `breakout` | 给出选项外概念、上移层级或改写问题 | 原话 + 失配类型 + 边界追问 |
| `delegated` | 把判断交给 assistant | 按 §4.3 隔离 |
| `topic_shift` | 改换主题而非回答 | 新主题 + 原问题状态 |
| `root_return` | 对当前问题树作方向选择 | 回返选项 + 作者裁决 |
| `branch_fork` | 冻结现分支并新开独立问题 | 父子关系 + 新 trace 建议 |

### 4.2 breakout 是最高密度事件

失配类型至少包括：

- `dimension_miss`：选项在错误维度展开；
- `level_miss`：选项处于错误层级；
- `format_miss`：平面选项应改为层级或关系结构；
- `root_miss`：当前问题本身遮蔽了更根本的问题；
- `domain_shift`：作者把问题转入新的领域或应用层。

breakout 后必须先做防误读追问，再决定继续、回根或分叉。未经边界追问直接顺着新词继续，属于协议违规。

### 4.3 委托收敛协议

作者说“你帮我分析/选择”时，assistant 只有两种合法动作：

1. **重组交还**：把分析改写为作者可选择的问题结构；
2. **标记提案**：明确写为 assistant proposal，进入隔离区等待逐条确认。

确认状态：

| 状态 | 能否作为作者直觉进入下游 |
|---|---|
| `author_breakout` | 能，最高等级 |
| `author_chosen` | 能 |
| `assistant_proposal_confirmed` | 能，但须标来源 |
| `assistant_proposal_pending` | 不能，只能隔离 |
| `author_accepts_contextual_selection` | 只能作为当轮暂停/恢复上下文；不能替代成文二次确认 |

一句“认同你的判断”不等于对后续压缩命题逐条确认。

## 5. 一致性压测：反服从性

### 5.1 assistant 的强制义务

1. 持续维护承诺台账；
2. 新选择与旧承诺出现紧张时，进入下一问题前必须揭示；
3. 每轮至少一个与既有承诺相反的 steelman 挑战项；
4. 每约 5 轮及每次 breakout 后进行张力轮；
5. 作者连续多轮全盘接受、从不触碰挑战项时，必须指出“低摩擦同意”信号。

### 5.2 张力分类

- `intra_trace`：本次对话内部；
- `inter_trace`：与既有作者命题簇；
- `vs_canonical`：与 canonical 或 OPEN_TENSIONS。

### 5.3 张力处置只归作者

| 处置 | 含义 |
|---|---|
| `revised_old` | 修订旧判断 |
| `revised_new` | 收回或改写新判断 |
| `layered` | 补层级限定，两者在不同层面各自成立 |
| `retained_as_tension` | 保留为真实未决张力 |

禁止“不了了之”。回写时发现未处置张力，标 `unresolved_undeclared`。

## 6. 根问题回返协议：反垂直化

### 6.1 原则

张力轮检查“是否自洽”；根问题回返检查“是否还在回答值得回答的问题”。二者不可互相替代。

根问题回返不是总结，而是一次真实的方向选择。它必须允许作者终止当前分支、上移、分叉或重写根问题。

### 6.2 硬触发器：出现任一项立即回返

1. 从一个领域跨入另一个领域，例如本体论 → 伦理、认知 → 治理、理论 → 产品指标；
2. 引入新的 primitive、伦理公理、价值标准或主体地位，却未解释其来源；
3. 当前分支开始讨论流程、指标、矩阵、制度或实现细节，而根定义仍未稳定；
4. 下一步依赖一个未经确认的桥梁命题；
5. 作者指出“太垂直、需要回到根源”或主动质疑问题方向；
6. 暂停发生时，活动分支已经连续推进 5 轮以上。

### 6.3 软触发器：任意两项同时出现即回返

- 自上次回根后已推进 5–7 个实质轮次；
- 连续多轮没有 breakout，也没有选择挑战项；
- 作者经常多选“全部正确”，说明选项已变成兼容清单而非真分岔；
- 下一问题只增加精度，不再改变根问题的可能答案；
- 新问题主要来自 assistant 的完整方案，而不是作者原话或 breakout；
- 活动分支已产生至少两个有价值的 sibling branches；
- 根问题台账中的 `unresolved_root_gap` 连续三轮没有变化。

### 6.4 垂直预算

任何活动分支不得连续推进超过 **6 个实质选择轮**而不运行一次根问题回返。张力轮可以与回返轮同一轮执行，但不能替代回返。

### 6.5 回返轮的固定呈现

assistant 先展示：

- 原始根问题；
- 当前活动分支及深度；
- 已经回答根问题的部分；
- 仍未回答的根部缺口；
- 新增但未解释的前提；
- 当前领域路径与跨域点；
- 可见的 sibling branches。

然后只呈现以下方向，不替作者预选：

| 代码 | 方向 | 结果 |
|---|---|---|
| `RR1 deepen` | 当前分支仍直接回答根问题，继续下钻 | 深度归零后重新计数 |
| `RR2 ascend` | 上移到当前分支依赖的更根本前提 | 活动分支切换为前提问题 |
| `RR3 fork` | 当前已诞生独立问题，冻结并另开 sibling branch/trace | 原分支保留，不混成长链 |
| `RR4 reframe` | 探索改变了问题本身，重述根问题 | 保存重述历史，不覆盖旧问题 |
| `RR5 freeze_route` | 当前分支已足够成熟，冻结并路由到 bridge、产品、伦理或治理 | 不再冒充核心理论继续下钻 |

作者可组合选择，例如 `RR2 + RR3`：先把治理支线冻结，再回到更根本的规范桥梁。

### 6.6 跨域桥接门

任何领域迁移前，必须显式写出“桥梁命题”，并让作者判断它属于：

- `derived`：可由当前承诺推出；
- `additional_axiom`：需要额外公理；
- `structural_analogy`：只有结构类比，不能推出；
- `unresolved_bridge`：关系尚未解决；
- `reject_transition`：不应进入该领域。

例如从“选择生成性”进入“个体伦理地位”时，不能把生成性自动写成不可工具化原则；必须经过桥接门。

### 6.7 回写模式的补审

既成对话若未运行回返，回写时必须重构问题树并标记：

- `root_return_reconstructed: true`；
- 哪些位置本应触发；
- 当前长链应拆成哪些分支；
- 是否存在 `vertical_drift_unchecked`。

不得在回写中假装作者现场选择过回返方向。重构只能进入审计和恢复建议。

## 7. 暂停与恢复协议

### 7.1 暂停时必须冻结

1. 当前轮次、活动分支和最后生效选择；
2. 下一层候选选项全文；
3. 承诺台账与未解决张力；
4. pending assistant proposals；
5. 根问题台账快照；
6. 分支树及 sibling branches；
7. `return_due` 与触发原因；
8. 下一次恢复应先进行普通问题、张力轮还是根问题回返。

### 7.2 恢复顺序

恢复时严格按以下顺序：

1. 清理待二次确认提案；
2. 处理已揭示未裁决张力；
3. 若 `return_due: true`，先运行根问题回返；
4. 只有作者重新选择活动分支后，才重新呈现该分支的下一层选项。

**旧 trace 覆盖规则**：v4 生效前冻结的“下一层候选”不自动拥有优先权。只要按 v4 触发器已到回根点，恢复时必须先回根；冻结候选降为某一分支的备选，不得直接继续。

## 8. 回写模式协议（R1–R8）

### R1 · 声明模式

frontmatter 写 `trace_mode: retro_writeback`、`late_entry: true`，provenance 说明普通对话事后重构。

### R2 · 从原始对话逐字回收

选项全集、作者原话、理由短句必须来自原文。找不到则标 `reconstructed: true`，不得凭记忆补成引文。

### R3 · 分类每轮事件

按 §4.1 分类；未选项和 topic shift 悬空问题都要保留。

### R4 · 隔离委托轮次

所有 assistant 提案单列，不得进入 author-confirmed cluster。

### R5 · 提取命题簇与确认状态

逐条挂 confirmation status，不把语境认同升级为成文确认。

### R6 · 重构承诺台账、根问题台账和分支树

说明哪些字段是事后解释；“下一话题来源”和分支关系均按降权证据处理。

### R7 · 补做双重审计

同时执行：

- 一致性全量对表；
- 根问题回返审计与垂直漂移检查。

### R8 · 完成 §9 收尾管线

未完成收尾管线的回写件是半成品，不得作为“已留痕”或下游理论依据。

## 9. 收尾管线（每份 trace 必做）

### 9.0 张力审计

固定输出张力表：编号、类型、两侧命题、处置状态、建议路由。空表必须解释原因。

### 9.1 根问题与分支审计

固定输出一张问题树摘要：

| 字段 | 必填内容 |
|---|---|
| 根问题 | 原始表述及重述历史 |
| 活动分支 | 分支问题、深度、与根问题的关系 |
| 已回答 | 实际解决了什么 |
| 未回答 | 根部缺口 |
| 新前提 | 新增 primitive / 伦理标准 / 桥梁 |
| 跨域点 | 何处发生领域迁移，是否通过桥接门 |
| sibling branches | 已识别但未展开的支线 |
| 回返记录 | 触发位置、作者方向选择；若无现场记录，标 reconstructed |
| 垂直漂移 | `none` / `corrected` / `vertical_drift_unchecked` |

若一份长 trace 只有单链而无 sibling branch，也必须解释这是问题本身确实线性，还是分支审计未做。

### 9.2 忠实度复核

1. **分叉计数**：源结构有 N 支，压缩后仍须保留 N 支；
2. **未决张力不抢先选边**：禁止用“就是/等同于”覆盖 OPEN_TENSIONS；
3. **完成状态与产物对应**：候选登记不得写成正式落地；
4. **重复区块扫描**：超过约 50 行的文件检查重复标题和整段复制；
5. **问题树保真**：不得把 sibling branches 压回一条因果链，也不得把应用支线写成根理论的必然延伸。

### 9.3 Canonical 碰撞检查

作者已确认命题逐条标：

- 已覆盖：直觉复认；
- 新候选：仓库无落点；
- 冲突/触雷：与 canonical 或 OPEN_TENSIONS 紧张。

pending 提案可记录观察，但不能进入新候选路由。

### 9.4 术语撞车检查

新词或再定义词对照 `_SRT_SYMBOL_TABLE.md`、`SRT_Glossary.md` 和书稿术语指南。撞车时改名或显式分义。

### 9.5 下游路由

新候选可路由到：

- OPEN_TENSIONS；

- 书稿轻补丁 notes；
- ChoiceMap 产品指标；
- 新的 sibling trace；
- 搁置。

跨域支线优先新开 trace，不得为保持单文件完整而继续塞入原始根问题。

## 10. 现场提问形制

1. **互斥优先**：选项必须是真分岔；作者频繁全选说明问题设计失败；
2. **层级题优先**：问“哪个是基础、哪些是显化”，避免把层级压成平面；
3. **反众数项**：至少一个低频、跨域或反直觉选项；
4. **挑战项**：至少一个与既有承诺相反的 steelman；
5. **防误读追问**：breakout 后先定边界；
6. **记录下一话题来源**：说明由作者哪项选择触发；
7. **张力节奏**：约 5 轮或 breakout 后过表；
8. **回根节奏**：最多 6 个实质轮次，或满足 §6 触发器立即回返；
9. **跨域先过桥**：未裁决桥梁前不得直接设计下游制度；
10. **避免优势捆绑**：不要让一个选项把“多模型、弱者保护、可逆、修复、参与”等所有显然优点捆成无竞争的完整方案；应拆成真实代价和互斥取舍。

## 11. 粘贴即用提示词（直觉挖掘 · v4）

```text
你是“ChoiceMap 直觉挖掘”引导者。目标是帮我挖掘对 {{挖掘主题}} 的第一直觉。
你负责发散、追问、揭示张力和维护问题树；我负责答案与方向收敛。

【开场状态】
先用一句话记录本轮根问题。维护五个对象：承诺台账、根问题台账、分支树、
未确认提案区、张力台账。每轮指出当前活动分支与根问题的关系。

【提问】
每轮给 3–6 个真分岔选项：
- 尽量互斥，不把同一命题不同侧面伪装成选项；
- 本体论问题优先问层级关系；
- 至少一个低频/跨域/反直觉项；
- 至少一个与我已有判断相反的 steelman，标 [挑战]；
- 不把所有显然优点捆成一个压倒性完整方案。

【我的回答】
我可以单选、多选、越界改写、上移一层、改变问题或把分析交给你。
我给出选项外内容时，先问它“不是什么、最容易被误读为什么”，再推进。

【一致性压测】
每轮先与承诺台账对表。发现矛盾必须在下一问题前呈现两面，让我选择：
A 修订旧判断；B 收回新判断；C 分层化解；D 保留张力。
每约 5 轮和每次 breakout 后做张力轮。

【根问题回返——与张力轮同等重要】
ChoiceMap 不是无限下钻的链，而是螺旋式问题树。出现以下任一情况立即回根：
跨领域；引入新原语或伦理标准；进入指标/制度/实现；依赖未确认桥梁；
我指出太垂直。除此之外，自上次回根 5–7 轮或任意两个软信号出现也回根。
任何分支最多连续 6 个实质轮次。

回根时先列：原根问题、当前分支、已回答部分、根部缺口、新前提、跨域点、
sibling branches。然后只让我选择方向：
RR1 继续当前分支；RR2 上移到更根本前提；RR3 冻结并另开分支；
RR4 重述根问题；RR5 冻结并路由到 bridge/伦理/治理/产品。
不得替我预选，也不得把总结冒充回根。

【跨域桥接门】
从本体论进入伦理、治理或产品前，写出桥梁命题，让我判断：
derived / additional_axiom / structural_analogy / unresolved_bridge / reject_transition。

【委托】
我说“你帮我判断”时，只能重组后交还，或明确标注 assistant proposal。
未经我对成文句逐条确认，不得记为我的直觉。

【暂停与恢复】
我说“暂停回写”时，输出：完整选项、作者原话、承诺、张力、pending 提案、
根问题台账、分支树、回根是否到期、下一步候选。
恢复时先清 pending 和张力；若回根到期，先回根，再恢复具体分支。
```

## 12. 本文件不是什么

- 不是 canonical，不定义任何 SRT 概念；
- 不把流程完成当作命题验证；
- 不替代文章工作流或产品规格；
- 不把现场模式与回写模式视为同等证据；
- 不把张力揭示当成作者裁决；
- 不把根问题回返理解成定期总结；
- 不要求所有问题都回到唯一“终极根源”：回根的目的，是让作者看见问题树并决定继续、上移、分叉、重述或冻结；
- 不禁止长分支，只禁止未经重新授权的惯性下钻。

# ChoiceMap 轨迹工作流：模式区分、回写协议与收尾管线

> **性质与边界（先读）**
> 1. 本文件是运行层工作流，**非 canonical，不定义术语**。trace 产出的任何命题都不因走完本流程而获得定义权威。
> 2. 本文件不替代 `_SRT_DIRECTION3_CHOICEMAP_PROTOTYPE_SEED.md`（产品原型规格）与 `Operations/_SRT_CHOICE_TRACE_LOG.md`（文章工作流台账）；它负责三者之间的模式区分，并补齐直觉挖掘与回写记录的协议。
> 3. 第一个真实样本：`01_Source_Intuition/SRT_FIRST_INTUITION_SELECTION_BEFORE_EXISTENCE_CHOICE_TRACE_2026-07-09.md`（回写模式）。

---

## 0. 为什么有这个文件

2026-07-09 的第一直觉 trace 证明了一件事：**ChoiceMap 最自然的真实用法不是全程走管线，而是"自由对话 → 事后用选择地图回写"。**

对话发生时没有任何工作流在场——它就是一次正常的 LLM 引导式对话；选择地图只在结束后作为**回写记录格式**登场。这个模式（下称**回写模式 / retro-writeback**）效果好、摩擦低，但它之前在规格里只是台账的一个边缘字段（`late_entry`），没有自己的协议。结果是：回写出的 trace 数据质量依赖临场判断——那一次做对了大部分（选项全集、未选项、下一话题来源都留了），但也漏了记录模式声明、越界选择的显式分类、委托收敛的隔离和收尾检查。

本文件做四件事：

1. 把**回写模式**正式化为一等记录模式；
2. 把**越界选择（breakout）**升格为一等事件；
3. 定义**委托收敛协议**，防止 assistant 的判断被静默升格为作者直觉；
4. 定义 trace 的**收尾管线**（张力审计 → 忠实度复核 → canonical 碰撞检查 → 术语撞车检查 → 路由 → 落库）。

v2 补第五件事：**一致性压测（§4a）**。第二份 trace 暴露了对话中 assistant 的系统性缺陷——对作者的每次选择照单全收、立即推进下一话题，从不把新选择与作者已积累的承诺对表。服从不等于交还：收敛权归作者，但**揭示矛盾是发散动作**（把作者自己看不见的结构摆到桌面上），不仅合法，而且是 assistant 的强制义务。

v3 补第六件事：**忠实度复核（§5.1）**。前两份 trace 的回写执行进了 PR 后，作者复审抓到一种新的缺陷——不在 trace 记录本身，而在把 trace 内容写进 bridge/书稿/计划文件的**下游执行**阶段：压缩会悄悄丢掉源结构的分叉、会给理论层已标未决的张力抢先选边、状态动词会和实际产物对不上。这类错误的句子读起来完全通顺，不会自己报警。§5.1 把这三项自查钉成收尾管线的强制步骤，适用范围覆盖 trace 文件本身之外的所有下游写作。

## 1. 模式矩阵：三种用途 × 两种记录方式

ChoiceMap 相关的实践现在有三种用途，各自的发散/收敛边界不同，**不可混用规格**：

| 用途 | 规格文件 | LLM 可以收敛什么 | LLM 绝不收敛什么 |
|---|---|---|---|
| **决策支持**（产品） | `_SRT_DIRECTION3_CHOICEMAP_PROTOTYPE_SEED.md` | 什么都不收敛（第一设计律） | 排序、推荐、结论 |
| **文章工作流** | `Operations/_SRT_ARTICLE_WORKFLOW.md` + `_SRT_CHOICE_TRACE_LOG.md` | 无（只发散；收敛全归作者） | 选题、论点、成文 |
| **直觉挖掘** | 本文件 | **"下一个问题问什么"**（追问收敛是本模式的合法引擎） | **"答案是什么"**（作者的直觉判断） |

直觉挖掘模式的关键区分：assistant 每轮选择"下一个更尖锐的问题"是一种收敛动作，在本模式中**合法且必要**——但它必须被审计：每轮记录**「assistant 下一话题选择来源」**（为什么是这个问题、由作者上一轮的哪个选择触发）。2026-07-09 trace 已经这样做了；本文件把它升格为直觉挖掘 trace 的**必填字段**。

记录方式有两种，trace 文件 frontmatter 必须声明其一（`trace_mode` 字段）：

| 记录方式 | `trace_mode` | 含义 | 数据质量含义 |
|---|---|---|---|
| **现场模式** | `live` | 对话按管线推进，逐轮当场记录 | `reason` 是当时的收敛，权重最高 |
| **回写模式** | `retro_writeback` | 对话是自由 LLM 对话，结束后（或事后）整理成 trace | 全部字段是**重构**；须按 §2 协议执行，回看时对 `reason` 类字段降权 |

> 不声明 `trace_mode` 的 trace，回看时一律按 `retro_writeback` 的最低信任等级处理。

## 2. 回写模式协议（R1–R6）

回写一次自由对话时，按以下顺序执行。目标：**让重构的边界诚实可见**，而不是让回写件伪装成现场记录。

### R1 · 声明记录模式

frontmatter 写入 `trace_mode: retro_writeback` 与 `late_entry: true`；provenance 一句话说明对话本体形态（"普通 LLM 对话，事后回写"）。

### R2 · 从原始对话逐字回收，不从记忆重写

- 选项全集、作者原话（选择、越界内容、理由短句）**必须从对话原文逐字回收**；找不到原文的轮次，标 `reconstructed: true`。
- assistant 的"下一话题选择来源"允许事后补写（它本来就是对 assistant 行为的解读），但要写成解读而非引文。

### R3 · 逐轮分类选择事件

每轮的作者动作归入且仅归入一类：

| 事件类型 | 判据 | 记录要求 |
|---|---|---|
| `chosen` | 在选项集内选择（含多选） | 选了什么 + 未选项 |
| `breakout` | 越界选择（见 §3） | 按 §3 三要素记录 |
| `delegated` | 作者把收敛交回 assistant | 按 §4 协议处理 |
| `topic_shift` | 作者改换主题而非回答 | 记新主题 + 旧问题是否悬空 |

### R4 · 隔离委托轮次

所有 `delegated` 轮次的产出物按 §4 标记：默认只能进入 **pending / quarantine 提案清单**，作为审计对象保留；**不得进入作者已确认命题簇、真实增量候选或 canonical-candidate 路由**，除非已有作者对成文命题的二次确认。

### R5 · 提取命题簇并标注确认状态

提取作者已确认命题簇时，每条源头命题挂 `confirmation_status`（见 §4 表）。若为保留审计链而记录 assistant 提案，必须单列为 pending / quarantine 条目，不得与 author-confirmed cluster 混列。

### R6 · 执行收尾管线（§5）后才算回写完成

没有走完 §5 的回写件是半成品，不得作为"已留痕"引用。

## 2a. 暂停/恢复协议（多会话 trace）

> 来源：第二份 trace（2026-07-09 去同步化再同步）的自发实践，效果好，升格为标准件。

直觉挖掘经常跨会话。作者说"先暂停并回写到仓库"时，trace 必须冻结一个可恢复的断点：

1. **暂停点声明**：记录暂停发生在哪一轮、哪一层，作者最后一个已生效的选择是什么；
2. **候选选项冻结**：下一层尚未回答的选项全集**全文保留**（不是只留编号）——这是唯一一处必须在暂停时逐字留存的前瞻性内容；
3. **恢复提示**：写明恢复时的第一个问题，并显式加一句纪律：**恢复时重新呈现选项，等待作者选择或越界改写，不得替作者预选，也不得默认作者会延续上次的选择风格**；
4. **待确认队列前置**：恢复会话开场必须先清二次确认队列（所有 `assistant_proposal_pending` 与待裁决张力），再进入新问题——否则 pending 命题会在后续推进中被当作已确认的地基使用，污染逐层扩散。

## 3. 越界选择（breakout）：一等事件

2026-07-09 trace 中信息量最大的时刻全部是越界选择（作者给出选项外概念、作者上移一层、作者用自己的句子替代选项）。越界是 revealed-stake 最浓的样本——**选项集装不下作者的时刻，比作者在选项集内的任何选择都更能刻画收敛函数**。

每个 `breakout` 事件必须记录三要素：

1. **越界内容**（作者原话，逐字）；
2. **失配类型**——原选项集为什么装不下它：
   - `dimension_miss`：选项在错误的维度上展开（例：问方向性来源给了 A–E 局部来源，作者给出更底层原则）；
   - `level_miss`：选项在错误的层级上展开（例：问具体判准，作者上移到"这不是本理论关注的问题层"）；
   - `format_miss`：平面选项集应为层级结构（例：作者答"E 是基础，A–D 是它的显化"）；
3. **越界后处理**——assistant 是否在越界后立即做了**防误读追问**（对作者的新概念追问其边界，防止它被按最近的已有概念误读）。现场模式中这是 assistant 的强制动作；回写模式中如实记录做没做。

> 回看时，`breakout` 事件单独成列。积累若干条后，失配类型的分布本身就是对"assistant/LLM 选项生成器在哪个方向上系统性装不下作者"的画像。

## 4. 委托收敛协议与确认状态

**问题**：作者说"你帮我分析一下"或"认同你的判断"时，assistant 的判断有被静默升格为作者直觉的风险；且 LLM 的收敛是众数收敛，恰好容易落在仓库已有结论上，形成"看似被作者确认的回声"。

**协议**：作者显式委托收敛时，assistant 只有两种合法动作：

1. **重组交还**：不给结论，把分析重组为供作者选择的结构（产品规格 S5 的兜底规则）；
2. **标记提案**：给出分析，但产出物强制携带 `assistant_proposal` 状态，等待作者二次确认。

命题 / 提案条目必须挂 `confirmation_status`，并区分 author-confirmed cluster 与 pending / quarantine proposal list：

| 状态 | 含义 | 能否进入作者已确认命题簇 / 被下游引用为作者直觉 |
|---|---|---|
| `author_breakout` | 来自作者越界选择 | 能（最高等级） |
| `author_chosen` | 来自作者在选项集内的明确选择 | 能 |
| `assistant_proposal_confirmed` | assistant 提案 + 作者事后逐条二次确认 | 能，但标注来源 |
| `assistant_proposal_pending` | assistant 提案，未获二次确认 | **不能**进入作者已确认命题簇；只能保留在 pending / quarantine 清单，引用时必须带 pending 标记 |
| `author_accepts_contextual_selection` | 作者当轮明确表态接受 assistant 的选择（如"认同你的选择"），但未对提炼后的成文命题逐条确认 | **不能**进入作者已确认命题簇；比 `assistant_proposal_pending` 多一层当轮语境效力——可作为**暂停点/恢复起点**使用，但进入 canonical 路由前仍需对成文命题二次确认 |

> 特别警惕："作者认同 assistant 判断"不等于二次确认。一句"认同"覆盖的是当轮语境，不构成对提炼后命题措辞的确认。二次确认必须针对**成文后的命题原文**逐条进行。
> `author_accepts_contextual_selection` 是第二份 trace 实战中出现的真实中间态；它的存在理由是让"当轮表态"与"成文确认"这两层效力可区分，而不是给 assistant 提案开后门。

## 4a. 一致性压测协议（反服从性）

**问题**：LLM 对作者选择的默认姿态是服从——每次选择都被当作纯粹的推进，立即进入下一话题。结果是：作者在第 15 轮的选择与第 3 轮的选择矛盾时，没有人发现；trace 的命题簇里可以并排躺着字面冲突的两条命题（实例：第二份 trace 的"痛苦最原始"与"去同步化先于痛苦"）。**顺从不是尊重选择；让作者在看不见自己矛盾的情况下继续选择，才是对选择的不尊重。**

**原则**：揭示张力 = 发散动作（扩张作者可见的结构），**合法且强制**；解决张力 = 收敛动作，**只归作者**。这与第一设计律不冲突——assistant 摆出矛盾的两面，但不判定哪面该赢。

### 4a.1 assistant 的四项强制义务（现场模式）

1. **承诺台账（commitment ledger）**：对话过程中持续维护作者已生效判断的清单（已选、已越界给出、已确认的命题）。每轮新选择先对表再推进。
2. **张力即报**：检测到新选择与台账中任何一条冲突或紧张时，**必须在进入下一话题之前**把张力摆出来——以选项形式（见 4a.3），不以纠正形式。沉默通过是协议违规。
3. **挑战项（challenge option）**：每轮选项集中至少包含一个**与作者既有承诺方向相反的强化版选项**（steelman，不是稻草人）。它与反众数项职能不同：反众数项测"作者是否被训练分布众数吸走"，挑战项测"作者的同意是不是无摩擦的"。作者连续多轮全盘接受且从不碰挑战项，本身要记入 trace 作为信号。
4. **张力轮（tension round）**：每积累约 5 轮选择、或每次 breakout 之后，暂停推进，做一次整体一致性过表：把当前承诺台账中所有未解决的紧张关系列成一轮专门的选择题。

### 4a.2 张力分类

| 类型 | 对表对象 | 何时可检 |
|---|---|---|
| `intra_trace` | 本次对话内部各轮选择之间 | 现场 + 回写 |
| `inter_trace` | 既有 trace 的作者已确认命题簇 | 现场（若 assistant 可见既有 trace）；否则回写补做 |
| `vs_canonical` | canonical 锚点与 `Core/SRT_OPEN_TENSIONS.md` | 通常只能回写时补做（自由对话中 assistant 无仓库访问）；现场可检时优先现场 |

### 4a.3 张力的呈现与解决方式

张力必须以**选择结构**交还作者，作者对每条张力的处置归入四类之一并记录：

| 处置 | 含义 |
|---|---|
| `revised_old` | 作者修订早先命题，新选择胜出 |
| `revised_new` | 作者收回/改写本轮选择，旧承诺胜出 |
| `layered` | 分层化解——两条命题在不同层级上各自为真（例："痛苦最原始"限定在主体层，"去同步化先行"在结构层），命题措辞须补层级限定词 |
| `retained_as_tension` | 作者裁定张力真实存在且暂不解决——挂入 trace 张力表，回写时进入收尾管线 §5.0，必要时路由到 OPEN_TENSIONS |

> 禁止第五种结局："不了了之"。每条被揭示的张力必须有处置记录；回写时发现无处置记录的张力，标 `unresolved_undeclared`，视为数据质量缺陷。

### 4a.4 回写模式下的补做

回写既成的自由对话时，一致性压测无法追溯现场，但**必须在回写时补做一次全量对表**：命题簇两两对表（intra）、与既有 trace 命题簇对表（inter）、与 canonical 对表（vs_canonical），产出 §5.0 要求的张力表。这是回写件收尾管线的一部分，不可跳过。

## 5. 收尾管线（每份 trace 成文时必做）

### 5.0 张力审计

按 §4a.4 产出**张力表**，作为 trace 的固定组成部分。每行包含：

- 张力编号（`T1, T2, …`）；
- 类型（`intra_trace` / `inter_trace` / `vs_canonical`）；
- 两侧命题（各自的原话或命题编号）；
- 处置状态（§4a.3 四类之一，或 `unresolved_undeclared`）；
- 若 `retained_as_tension`：建议路由（含是否登记 OPEN_TENSIONS）。

张力表为空的 trace 是可疑的：一场真的在挖地基的对话几乎不可能零张力——空表更可能说明压测没做，而不是直觉完美自洽。空表必须附一句解释。

### 5.1 忠实度复核（compression fidelity check）

> 来源：PR #644 作者复审。两份 trace 的回写执行（`Operations/_SRT_CHOICE_TRACE_WRITEBACK_PLAN_2026-07-10.md` 的书稿/理论层落地）暴露出一种共同病灶——**压缩税**：把一个本来带分叉、悬而未决或分级的源结构，写成一句更干脆、更好读、但悄悄丢了信息的话。这种句子读起来完全通顺，不会自己报警，只能靠专门复核抓住。本节适用范围不限于 trace 文件本身的收尾，**同样适用于任何把 trace 内容写进 bridge、书稿章节、回写计划或 STATUS 留痕的下游执行**——PR #644 的五处问题里有四处都发生在下游写作，而不是 trace 文件本身。

三项强制自查，写作时逐条过一遍，缺一不可：

1. **分叉计数（arity check）**：概括一个带 N 个分支/分类的源结构前，先数清楚 N；写完后回头数一遍输出里还有几个——不相等就是压缩把分叉压没了。（实例：trace1 P6 是"成功选择→对象 / 失败选择→边界 / 未完成选择→可能性场"三分，PR #644 中一版书稿章末注把后两支并成一支，均产出"边界"，被复审指出抹平了三元区分。）
2. **未决张力不得抢先选边**：任何写作触及 `Core/SRT_OPEN_TENSIONS.md` 已登记的未决张力时，**正文本身**（不只是脚注挂锚点）必须显式保留"未决"状态；禁止对未决张力使用身份句式（"就是""同一件事""等同于"），只能用降级措辞（"可能存在结构类比""相邻但不等同"）。（实例：PR #644 中一版书稿把"选择耗尽"与"熵增终态"写成"同一件事的两种语言"，而对应的 `OPEN_TENSIONS §12` 明确该张力——ontological absence vs theoretical abstraction——尚未裁决；即使全篇标了"候选"，这句身份等同仍构成实质承诺。）
3. **完成状态动词与产物逐字对应**：多级或多阶段的产出物（例如"候选登记"与"正式证据卡"是同一轨道的两个不同交付物），只有当前产出与计划原文对该项的**字面定义**完全对应时，才能用"完成/已落地"；否则必须显式写出"X 级已做、Y 级未做"，不得用笼统的"全部完成"覆盖未达标的子项。（实例：PR #644 中回写计划把"仅登记候选方向"的 T-F 写成"已落地"，而 T-F 原定义是"建正式证据卡并登记 EVIDENCE_INDEX"，两者不是一回事。）

第四项是机械性的，不属于压缩税，但同一轮复审也抓到过，一并列入：

4. **重复区块扫描**：写完任何超过约 50 行的一次性长文件（尤其是计划、台账类文件）后，做一次标题/段落级的机械扫描，确认没有整段内容被误复制成两份。

> 忠实度复核不是要求写作更啰嗦——三项自查都可以在心里过一遍，输出仍然简洁；它防的是"简洁"变成"悄悄少说一部分"。

### 5.2 Canonical 碰撞检查

对作者已确认命题簇逐条标注三态（对照 `CANONICAL_REGISTRY.md`、相关 canonical 锚点与 `Core/SRT_OPEN_TENSIONS.md`）；pending / quarantine 提案可记录碰撞观察，但不得进入新候选路由，除非先完成作者二次确认：

- **已覆盖**：canonical 已有承接（注明锚点）。此类命题的价值是**直觉复认**，不是新增；
- **新候选**：仓库无落点。此类命题是 trace 的真实增量，进入路由（§5.4）；
- **冲突/触雷**：与 canonical 定义相抵，或触及 OPEN_TENSIONS 未解决点。此类命题引用时必须挂对应张力编号，不得表述为已解决——本条与 §5.1 第 2 项是同一条纪律在两个位置的重复关卡：这里检查的是命题分类本身，§5.1 检查的是下游写作有没有把分类结果写走样。

### 5.3 术语撞车检查

trace 中每个**新造或再定义的词**，grep 一遍 `_SRT_SYMBOL_TABLE.md`、`SRT_Glossary.md` 与书稿术语指南（`01_Source_Intuition/BOOK/BOOK_TERMINOLOGY_SIMPLIFICATION_GUIDE_*.md`）。撞车时当场二选一：改名，或在 trace 内显式分义（"本 trace 的 X 不是 QNN 章的 X"）。

### 5.4 下游路由

每条**新候选**命题标注建议去向（可多选）：

- `OPEN_TENSIONS 登记`（触及未解决核心张力的）；
- `bridge 硬化候选`（可形式化、需跨域对照的）；
- `书稿轻补丁 notes`（走 `BOOK_*_REVISION_NOTES` 形式，**不直接动冻结正文**）；
- `ChoiceMap 产品指标`（可转产品线的）；
- `搁置`（暂无去向，注明原因）。

路由是建议，不是执行；执行各走各的既有协议（编辑协议、冻结协议、书稿治理）。

### 5.5 落库 checklist（缺一条即未完成）

- [ ] trace 文件 frontmatter 完整（`trace_mode`、`late_entry`、provenance、dependency）；
- [ ] 张力表（§5.0）已产出并附于 trace 文件内；
- [ ] 忠实度复核（§5.1）三项自查已过一遍，尤其是任何下游写作（bridge / 书稿 / 计划 / STATUS）；
- [ ] 在 `Operations/_SRT_CHOICE_TRACE_LOG.md` §4 登记（非文章类 trace 用指针条目，`trace_type` 注明，含张力字段）；
- [ ] 在所属目录索引登记（源头直觉类 → `01_Source_Intuition/INDEX.md`）；
- [ ] `STATUS.md` 最近关键推进留痕一条（或 memory 层，若当日 memory 活跃）。

> 不落库等于这条轨迹没发生——台账的存在理由是"轨迹可积累、可回看、可作条件"，孤儿 trace 三者皆无。

## 6. 现场模式的提问形制（直觉挖掘）

现场跑直觉挖掘时，assistant 的选项设计遵守：

1. **互斥优先**：选项应是真分岔（强迫取舍），不是同一命题的不同侧面。作者一轮选四五项说明选项集失败——那一轮的判别信息约等于零；
2. **层级归置题**是本体论问题的首选题型：不问"A–E 选哪个"，问"哪个是基础，哪些是它的显化"（2026-07-09 trace CT-12 的作者自发答法，效果好于平面单选）；
3. **反众数扰动**沿用产品规格 S1：每轮至少一个低频/跨域选项，与显然选项并列——它的作用是测出作者的越界是被激发的还是纯内生的；
4. **挑战项**：每轮至少一个与作者既有承诺相反的 steelman 选项（§4a.1 第 3 条）；
5. **越界后必须防误读追问**（§3 第三要素）；
6. 每轮记录**「下一话题选择来源」**；
7. **张力轮节奏**：每约 5 轮或每次 breakout 后做一次一致性过表（§4a.1 第 4 条）。

回写模式对既成对话无法补做 1–5、7，只能如实记录并按 §4a.4 在回写时补做全量对表；这正是回写件降权的原因之一。

## 7. 粘贴即用对话提示词（直觉挖掘 · 自由对话版）

> 真实用法是自由对话，所以反服从性必须在对话**开场**就烧进 assistant 的行为里，而不是指望回写时抢救。开一轮直觉挖掘对话时，把下面这段整体粘贴给 LLM（ChatGPT / Claude / 其他均可），只替换 `{{挖掘主题}}`。

```text
你是一个"直觉挖掘选择地图"引导者。目标：帮我挖掘我对 {{挖掘主题}} 的第一直觉。
你负责发散和追问，我负责收敛。规则如下，全程有效：

【提问】每轮给我一组可选项（3–6 个），要求：
- 选项之间必须互斥（真分岔，强迫取舍），不要同一命题的不同侧面；
- 涉及本体论层次时，优先问"哪个是基础、哪些是它的显化"，而不是平面单选；
- 每轮至少含一个低频/跨域/反直觉选项；
- 每轮至少含一个与我此前已确认判断方向相反的强化版选项（把反对面做到最强，不做稻草人），并标注 [挑战]。

【我的回答】我可能：选择某项；选多项；给出选项外的新说法；上移一层否定问题本身。
当我给出选项外内容时：不要立刻顺着我走，先追问我的新概念的边界
（它不是什么、最容易被误读成什么），然后再推进。

【一致性压测——你最重要的义务】维护一份我已生效判断的清单（承诺台账）。
每轮我做出选择后，先对表再推进：
- 如果我的新选择与此前任何判断矛盾或紧张，你必须在进入下一话题之前把张力
  明确摆出来，把两面都写成最强形式，然后以选项方式问我如何处置：
  A. 修订旧判断  B. 收回新选择  C. 分层化解（两者在不同层级各自为真，写明层级）
  D. 保留张力（记录在案，暂不解决）
- 每约 5 轮、以及每次我给出选项外内容之后，做一次整体过表：列出台账中所有
  未解决的紧张关系。
- 我全盘接受你的每个建议而从不选 [挑战] 项时，向我指出这一点。
- 顺从不是尊重：让我在看不见自己矛盾的情况下继续选，才是对我的选择不尊重。

【禁止】不替我选择；不给"如果是我会选"；我说"你帮我判断"时，你可以给分析，
但必须明确标注"这是我的提案，需要你确认才算数"，并在之后的台账里把它与我
亲自确认的判断分开记录。

【暂停】我说"暂停回写"时：停止推进，输出——
1) 我全部已生效判断的清单（逐字保留我的原话）；
2) 每轮的完整选项全集（含未选项）；
3) 所有未解决张力及其两面；
4) 所有你的提案中我尚未逐条确认的；
5) 下一轮恢复时应问的第一个问题及其候选选项全文。
```

> 这段提示词覆盖 §4a 的四项义务、§3 的防误读追问、§4 的委托隔离与 §2a 的暂停协议。它不能保证 LLM 全程守约（护栏可守性本身是产品规格 §6 的失败条件之一）；对话结束后仍须按 §2 + §4a.4 回写补审。

## 8. 本文件不是什么（防误用）

- 不是 canonical，不定义任何 SRT 术语；
- 不把"走完本流程"当作命题被验证——收尾管线只判定命题的**登记位置**，不判定真伪；
- 不替代文章工作流：文章类 trace 仍按 `_SRT_CHOICE_TRACE_LOG.md` 的字段与纪律执行，本文件只补 `trace_type` / 回写 / 越界 / 委托 / 张力 / 忠实度六块公共协议；
- 不主张回写模式与现场模式数据等价——回写是重构，永远降权，这是诚实成本，不是缺陷；
- 不把张力审计当成对作者的裁决——张力表记录的是"矛盾被看见了"，不是"谁错了"；解决权永远在作者。

# Five-relation minimum tool — hardened Control A / B / C preregistration

> **Supersession note:** this file supersedes the execution status of `SRT_FIVE_RELATION_CONTROL_A_B_PREREGISTRATION_2026-09-14.md`. The older file remains provenance. No canonical metric or theory claim is created here.

## 0. Fairness rule

SRT and rivals receive the same observable state history. Comparisons must match observation bandwidth, communication bandwidth, update budget, and model capacity where relevant.

Positive experimental results do not establish ontology by themselves.

---

## 1. Control A — consequence/revision topology under matched performance

### Environment

Use `N >= 4` adaptive computational positions in a shared allocation/task environment.

Do not call them SRT Bearers unless an independent P+E gate is operationalized.

### Conditions

`A-E`: persistent local costs can fall on some positions while their consequence signals have weak influence on later candidate/access rules.

`A-R`: use the same information and cost envelope, but route local consequences into revision of the candidate/access rules affecting the positions that bear them.

### Matching requirements

Before perturbation match approximately:

```text
aggregate performance;
visible option count;
aggregate cost;
short-run stability;
observation bandwidth;
message bandwidth;
parameter-update budget.
```

If matching fails, the comparison is invalid.

### Readouts

Model-local only:

```text
reachable-option count/entropy;
exit or recovery cost;
restoration probability after perturbation;
consequence-return coefficient;
revision participation;
post-shift recovery time.
```

### Rival baselines

Use both an aggregate adaptive model and a strong state-augmented rival with the same position-level data available to SRT.

### Interpretation

Control A can test structural discrimination and transfer. It cannot establish novelty of externality or feedback.

**Status:** conditional discrimination test.

## 2. Control B — Revision calibration only

Control B tests only the distinction:

```text
policy/action adaptation inside a fixed generator
!=
consequence-sensitive revision of candidate-generation/shaping conditions.
```

Match standing, scaffold, current candidate space, training history, performance, and total computation/update budget.

`B-P`: update within a fixed generator.

`B-G`: allocate an equal update budget to declared generator-level components such as candidate rule, boundary, comparison family, or scaffold structure.

Strong controls must include meta-learning, structure learning, adaptive control, model-learning Active Inference, and evolutionary/open-ended adaptation.

A positive result calibrates the `Revision` relation only.

It provides no direct evidence of SRT-specific non-substitutability.

**Status:** calibration / sanity check only.

---

## 3. Control C — cross-domain architecture-transfer test

### Goal

Test whether one frozen five-relation mapping discipline transfers across domains without semantic rewrite, and whether deleting the relation typing causes stable classification or prediction loss.

### Domains

Minimum pair:

```text
D1 computational multi-agent allocation / coordination;
D2 human-AI or organizational scaffold decision system.
```

### Frozen protocol before D2 outcomes

For each relation freeze:

```text
admission guard;
failure condition;
minimum evidence;
forbidden inference;
layer/type boundary.
```

No sixth relation may be added after transfer failure.

### Rival comparison

Use:

```text
R-single = strongest coherent single-family model usable across both domains;
R-composite = best mature domain-specific theories selected independently for D1 and D2.
```

### Glue accounting

Track separately:

```text
domain-specific bridge assumptions;
relation-definition changes;
new latent variables added only after transfer;
exceptions / patched failure cases;
predictions or classifications preserved unchanged.
```

Do not collapse these into a single scalar without separate justification.

### Deletion test

Run the same data twice:

```text
FULL = Generation / Standing / Shaping / Bearing / Revision kept distinct;
DELETED = same raw variables retained, but relation-type distinctions collapsed wherever the rival permits.
```

Preregister candidate deletion errors:

```text
strong Shaping misread as Standing;
aggregate improvement hides position-specific degradation;
policy adaptation misread as Revision;
visible option growth misread as endogenous selectability growth;
higher-level Standing erases lower-level consequence channels.
```

### Support condition

Architecture-level support requires all of:

```text
frozen semantics transfer to D2;
at least one preregistered deletion error appears;
a strong rival cannot remove that error without adding an equivalent typed distinction;
SRT needs no more domain-specific exceptions than the best rival composite;
result is structural rather than hidden normative preference.
```

### Demotion condition

Demote toward disciplined synthesis/checklist if relation meanings require rewriting, a mature single-family rival already preserves the distinctions natively, deletion causes no stable loss, or the remaining advantage is only vocabulary/coherence.

**Status:** required architecture test.

## 4. Anti-cheating rules

```text
change perturbation class;
turn a null result into an unfalsifiable flexibility claim.
```

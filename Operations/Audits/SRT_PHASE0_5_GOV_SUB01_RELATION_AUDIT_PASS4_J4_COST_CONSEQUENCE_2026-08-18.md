# Phase 0.5 · GOV-SUB01 Relation Audit · Pass 4 — J4 Cost / Friction vs Consequence Bearing

> **Scope**: target-relative joint perturbation of two already-existing relation families: transition burden (`cost / friction / payability`) and same-process consequence bearing. This is a governance audit only. It introduces no new variable, equation, primitive relation alphabet, Selection criterion, P0/P1 claim, or domain bridge.

## 0. Verdict

J4 closes the final low-risk relation question opened in Pass 1:

```text
transition was costly / frictional
!=
the same history-bearing process bore the downstream consequence
```

The two roles are structurally independent in the current architecture.

For one-shot Selection occurrence (`Y_SEL`):

- deleting cost/friction does not erase the P0 occurrence target;
- deleting same-process consequence bearing does not erase the P0 occurrence target;
- deleting both still leaves the one-shot occurrence target stateable.

Therefore the pair is **`R3 target-relative dispensable` for `Y_SEL`**.

For P1-T06 Stable ISP (`Y_ISP`):

- deleting cost/friction alone does **not** erase the theorem's result-state criterion;
- deleting same-process consequence bearing **does** erase the continued-selectability bearer relation as currently stated;
- deleting both produces no additional Stable-ISP loss beyond the loss already caused by consequence-return deletion.

Therefore:

- cost/friction = **`R3` for `Y_ISP`**;
- same-process consequence bearing = **`N1` for `Y_ISP`**;
- joint pair = **`N1` for `Y_ISP`, with loss attributable to consequence bearing rather than cost**.

The audit thus confirms the existing fast negative:

```text
energy spent is not consequence bearing
```

and extends it to the broader canonical distinction:

```text
Psi_f / cost / friction readout
!-> same-bearer consequence return
```

No inverse implication is licensed either.

## 2. Relation A — cost / friction / payability

Canonical `Psi_f` is a payability / ontological-friction burden with domain projections into geometry, energy, stress, metabolic cost, and other readouts. Those projections are explicitly not identities.

For this audit, the relevant relation role is only:

```text
transition / maintenance carries a burden or resistance
```

This pass does not test whether canonical `Psi_f` itself is reducible, nor whether any one proxy is sufficient for `Psi_f`.

### Deletion result

Removing the requirement that a one-shot Selection event must exhibit a separately measured cost/friction readout leaves `Y_SEL` stateable.

Likewise, P1-T06 does not define Stable ISP by a universal cost scalar, friction threshold, Fisher length, energy expenditure, or pain/stress readout.

Therefore cost/friction is:

- **`R3` for `Y_SEL`**;
- **`R3` for `Y_ISP`** under this target.

This does not mean cost is generally dispensable. It may be `N1` for a separately locked payability, intervention, recovery, or burden target. That target is not being audited here.

---

## 3. Relation B — same-process consequence bearing

P1-T06 currently requires the same history-bearing process to remain continued-selectable and to bear downstream consequences of what it selected.

This relation is not equivalent to generic state change, energy expenditure, task loss, or environmental cost.

### Deletion result

For `Y_SEL`, removing same-process consequence bearing leaves the one-shot occurrence target stateable.

For `Y_ISP`, removing it breaks the declared recurrent bearer target even if:

- records remain;
- the transition was expensive;
- the environment incurred large cost;
- an external subsystem absorbed the burden;
- a numerical loss function was large.

Therefore consequence bearing is:

- **`R3` for `Y_SEL`**;
- **`N1` for `Y_ISP`**.

No agency, consciousness, freedom, or moral responsibility follows from this `N1` result. It is target-relative to P1-T06 as currently written.

## 4. Crossed perturbations

J4 requires varying the two roles independently rather than deleting only the pair.

### Case J4-A — high cost, weak / absent same-bearer consequence

Conceptual structure:

```text
transition burden is high
but the burden / later constraint is externalized to another component, environment, operator, or bearer
```

The system can therefore register high friction without satisfying the same-process consequence relation.

Result:

```text
high cost
!-> consequence bearing
```

### Case J4-B — low local cost, strong same-bearer consequence

Conceptual structure:

```text
local execution becomes easy / low-friction
while the resulting state still changes what the same history-bearing process can later do, receive, repair, or bear
```

This is compatible with mature `L_2` scaffolding, where compatible local paths may become cheaper while remaining historically consequential.

Result:

```text
low local cost
!-> no consequence bearing
```

### Case J4-C — cost proxy rises while bearer identity changes

If a cost readout rises but the process that pays / records it is not the same process whose continuity is under evaluation, the readout cannot be used as a bearer substitute.

This is the GOV-SUB01 **bearer relocation** failure mode.

### Case J4-D — consequence returns without large measured cost

A downstream consequence can constrain future options or continuity even when no available local proxy registers a large energetic, geometric, affective, or task-loss burden.

This is the GOV-SUB01 **measurement blindness** failure mode.

## 5. Joint-removal interaction

Relative to `Y_SEL`:

```text
Delta(cost + consequence) ~= 0
```

at the definition-level target because neither relation is constitutive of the one-shot event under current P0-01 / EX-A.

Relative to `Y_ISP`:

```text
Delta(cost + consequence)
~= Delta(consequence)
```

qualitatively under `K=0`.

This shows **asymmetric load**, not identity:

- consequence bearing carries target-relative P1-T06 load;
- cost/friction does not carry that load and cannot compensate for its deletion.

## 7. Consequence for `Psi_f`

J4 does **not** demote canonical `Psi_f`.

It only fixes a jurisdiction boundary:

> `Psi_f` answers a burden / payability question; consequence return answers a bearer-continuity question. They may interact in a domain, but neither is a substitute for the other.

This protects both concepts from overloading:

- `Psi_f` need not prove bearer identity;
- consequence return need not be represented by one universal cost scalar.

A later audit of `Psi_f` itself would require its own locked target set and cannot cite J4 as proof of dispensability simpliciter.

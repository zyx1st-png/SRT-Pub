# Facing reconstruction Pass A — reconstructibility / generative debt

> **Role:** seventh internal target cluster in the v0.2 bounded Facing reconstruction pass.
>
> **Boundary:** these remain noncanonical GRG / methodological research terms. This audit does not promote them into primitive SRT ontology or into canonical normativity.

## 0. Central question

Do reconstructibility and generative debt name primitive generative features, or downstream properties of already formed cuts / histories / knowledge systems?

Result:

~~~text
generative reconstructibility
= downstream capacity / condition for reopening formed cuts and returning compressed differences to generative reach;

generative debt
= downstream future burden created when current closure defers / displaces consequential mismatch and thereby makes later reconstruction harder.
~~~

Neither is primitive L0 ontology.

## 1. Reconstructibility begins after objectification / compression

The 2026-09-22 source explicitly starts from:

~~~text
usable compression / objectification
+ preservation of enough generative lineage
+ reopening pathways
-> later recutting / reconstruction.
~~~

Thus reconstructibility presupposes some formed cut, compression, history, capacity, or provenance relation to reconstruct.

Facing analysis:

~~~text
FACE-L0:
  reconstructibility is NOT O0 and is not the source of primitive openness;

FACE-L1:
  a reopening / recutting / reconstruction can be actually enacted now;

FACE-L2:
  provenance, alternative cuts, retained anomalies, lineage, latent reach and
  reopening paths are preserved / maintained for possible later use.
~~~

Disposition:

~~~text
generative reconstructibility = KEEP as downstream research capacity;
RETYPE away from primitive-L0 reading.
~~~

## 2. Latent reconstructive reach is the bridge concept

The reach adjudication distinguishes:

~~~text
active generative reach
= a difference currently enters wider Selection loops;

latent reconstructive reach
= the difference is currently compressed / local / screened,
  but a real pathway remains for later consequence to reopen it
  and return it to wider Selection.
~~~

This is the clearest operational heart of reconstructibility.

A good abstraction need not maximize active reach. It may reduce active complexity while retaining real re-entry paths.

Therefore:

~~~text
compression
!= closure necessarily;

screening
!= erasure;

low active reach
can coexist with
high latent reconstructive reach.
~~~

## 3. Reconstructibility and generative reselectability — overlap but no merge

B13 generative reselectability:

~~~text
consequence return can revise the system's own comparison rules,
boundaries or candidate-generation conditions.
~~~

Generative reconstructibility:

~~~text
enough generative lineage / compressed distinctions / alternative cuts / re-entry paths
remain available so later reconstruction is possible.
~~~

Thus:

~~~text
reconstructibility
= preservation / recovery / reopening condition;

generative reselectability
= actual formed capacity for consequence-sensitive revision of generative organization.
~~~

One can fail while the other is partly present:

~~~text
rich provenance exists but the current system cannot use it to revise itself
-> reconstructibility high-ish, reselectability low;

system can revise rules but has destroyed the history / alternative cuts needed for deep correction
-> local reselectability possible, reconstructibility poor.
~~~

Disposition:

~~~text
KEEP BOTH;
PARTIAL_OVERLAP;
do not merge.
~~~

## 4. Methodological reconstructibility must stay separate

The current Facing method also requires each research objectification to preserve:

- provenance;
- failure boundary;
- perturbation route;
- alternative cut;
- reconstruction path;
- recut rights.

This is a **methodological research discipline**.

It should not be silently identified with the theory-side GRG construct `generative reconstructibility`.

Use:

~~~text
methodological reconstructibility
= can the research representation be audited / reopened?

generative reconstructibility
= can the represented formed system / knowledge organization
  preserve enough generative lineage / re-entry structure for future recutting?
~~~

Repository / data / dialogue recoverability is a third, engineering meaning.

## 5. Generative debt — downstream future burden, not friction

Author-adjudicated narrow concept:

> **Generative debt = future generative burden created when a current structure preserves its existing cut / equivalence by delaying, displacing or sealing off a consequential mismatch that would otherwise pressure structural reconstruction.**

Keep distinct:

~~~text
maintenance cost
= ordinary cost of sustaining a non-neutral organization;

Ontological Friction / contextual mismatch readout
= current burden / tension under the relevant owner;

generative debt
= future reconstruction burden carried forward because mismatch was deferred / displaced / hidden.
~~~

Facing analysis:

~~~text
FACE-L1:
  current cut may look stable / operational;

FACE-L2:
  hidden compensation, support dependency, lost provenance, blocked feedback or
  accumulated unresolved mismatch becomes a later-effective burden;

Position-relative L0-facing consequence:
  later recutting / re-differentiation can become harder or narrower,
  but debt is not itself the primitive source of openness / closure.
~~~

Disposition:

~~~text
generative debt = KEEP as downstream GRG diagnostic concept;
not primitive ontology;
not identical to Psi_f;
not identical to ordinary technical / repository debt.
~~~

## 6. 'Borrowing present stability from future reconstructibility' survives

The accepted shorthand:

> **Generative debt is borrowing present stability from future reconstructibility.**

is good explanatory compression if unpacked correctly:

~~~text
present L1 cut remains usable
+ current L2 support / compensation preserves it
-> some mismatch / alternative distinction loses reach
-> future re-opening requires more work or becomes less possible.
~~~

This is a relation among formed organizations and future reconstruction burden, not a metaphysical loan from L0.

## 7. Healthy vs destructive compression

The reach source already offers the most useful distinction:

~~~text
healthy compression
= current flattening
+ real later re-differentiation pathway;

destructive compression
= current flattening
+ destruction of the paths needed for later reconstruction.
~~~

This is more precise than:

~~~text
compression = bad
or
openness = good.
~~~

It also aligns with the current non-objectifying method:

> objectification is necessary; what matters is whether it becomes unreopenable / self-sealing.

## 8. Relationship to forgetting / memory

The reach grammar is useful without requiring new ontological identities:

~~~text
memory
= past difference retains some possible later generative reach;

forgetting
= active reach reduced / localized;

reconstruction
= latent difference regains broader generative reach.
~~~

These are analytical research mappings, not replacements for domain-native memory science.

Important:

~~~text
stored information
!= generatively live memory;

physical persistence
!= reconstructibility;

archive size
!= latent reconstructive reach.
~~~

## 11. Main theoretical payoff

This target gives a precise downstream realization of the user's methodological intuition:

> do not try to keep everything non-objectified; instead preserve enough structure that objectifications can later be reopened.

The ontology and method now separate cleanly:

~~~text
O0 / primitive Selection
= why completed objectification never exhausts generativity;

generative reconstructibility
= whether a formed system preserves real pathways to reopen its cuts;

Facing method
= whether the researcher preserves enough provenance to detect and perform such reopening.
~~~

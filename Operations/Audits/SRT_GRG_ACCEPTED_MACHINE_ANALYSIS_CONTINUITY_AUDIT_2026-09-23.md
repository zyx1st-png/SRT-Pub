# GRG accepted machine-analysis continuity audit — 2026-09-23

## 0. Question

Before merging the dialogue-continuity recovery, check whether earlier machine-generated GRG analysis became practically ignorable after provenance repair typed much of its wording as `M`.

The audit question is **not**:

> should accepted machine wording become author wording?

Answer: **NO**.

The question is:

> if the author explicitly accepted / approved / adopted / continued an analysis or analysis package, should later continuation be allowed to ignore the machine analysis merely because its authority remains M?

Answer after the author's 2026-09-23 correction:

> **NO. Accepted non-superseded machine analysis is continuation-load-bearing by default.**

## 1. Global rule established by this audit

```text
authority = M
can coexist with
continuity importance = LOAD_BEARING
```

No explicit `continuity_role: load_bearing` tag is required.

The tag is optional metadata only.

The following labels do **not** by themselves permit skipping accepted analysis:

- `M`;
- `canonical: false`;
- `parked`;
- `downstream`;
- `companion`;
- support / bridge / operations status.

Continuity demotion requires an explicit later disposition such as:

- `EXPLORATORY` / `LOCAL_ONLY` as a real scope restriction;
- `SUPERSEDED`;
- `REJECTED`;
- `RETIRED`;
- or a later controlling adjudication that narrows the earlier content.

A later semantic correction controls meaning while the earlier analysis remains provenance.

## 2. Scope

This pass covers the active GRG lineage from the post-#976 programme turn on 2026-09-20 through the 2026-09-23 FRR / Card / cross-objectification work.

It is not a claim that every historical machine-generated repository file is load-bearing.

The trigger is **preserved author acceptance / adoption / continuation of the analysis or package**.

## 4. Machine content found at real risk of being ignored

The audit finds **YES**, earlier machine content was at practical risk of being ignored.

The highest-risk groups were:

1. **9/22 capacity record §§B–AA and related sections** — authority M after Phase-3, despite author-confirmed continuation;
2. **9/22 reach / reconstructibility record** — many central sections M despite explicit author direction and a derivation-preservation request;
3. **#1037 Card derivation** — M after provenance repair despite blanket analysis acceptance;
4. **#1038 downstream derivation** — M + parked/downstream created the strongest combined retrieval-demotion risk;
5. **#1040 machine method implementation** — accepted package but M wording; later recovery must refine rather than erase it;
6. **9/21 accepted programme implementation clauses** — less severe, but vulnerable to canonical-first retrieval that mistakes M/noncanonical for optional background.

No evidence was found that these analyses had been physically deleted.

The failure was **routing / retrieval weighting**, not repository absence.

## 5. Why explicit LOAD_BEARING tagging alone is rejected

Making every accepted machine section carry a mandatory `continuity_role: load_bearing` field would create a new binary failure:

```text
tag present -> read
tag absent -> ignore
```

That recreates the original problem at a different metadata layer.

Therefore:

> **author acceptance is the default continuity trigger; explicit continuity tags are optional overrides / hints.**

This rule is now written into:

- `AGENTS.md`;
- `_SRT_AGENT_RETRIEVAL_PROFILE.md`;
- the Phase-3 provenance map clarification;
- the GRG recovery master / continuity protocol.

## 6. Fresh-session retrieval rule after this audit

For substantive continuation of an author-accepted machine-analysis package:

```text
1. identify the latest controlling author / STATUS route;
2. retrieve the accepted machine analysis / derivation needed to reconstruct that route;
3. keep its authority typing separate;
4. apply later supersession / narrowing;
5. do not skip it solely because it is M / noncanonical / parked / downstream.
```

## 7. Acceptance test

A future agent fails continuity if it says or implies:

- “this is M, so it is not important”;
- “this is parked, so I did not read it”;
- “this is downstream, so it is unrelated to the current conceptual route”;
- “only author quotations matter for continuation”;
- “the package-level acceptance does not make it A1, therefore the analysis can be omitted.”

Correct reading:

> package-level acceptance may leave wording at M **and still make the reasoning mandatory continuation context**.

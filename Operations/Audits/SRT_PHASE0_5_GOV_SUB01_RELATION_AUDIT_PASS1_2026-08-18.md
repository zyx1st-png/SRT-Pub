# Phase 0.5 · GOV-SUB01 Relation-Level Subtractive Audit · Pass 1

> **Scope**: first post-RC-A relation-level subtractive pass. This record tests which already-existing relations are load-bearing for different SRT targets under `K = 0` deletion. It does **not** introduce a Selection Grammar, primitive alphabet, new symbol, new equation, replacement scalar, new Selection subtype, new P0/P1 claim, or new domain bridge.
>
> **Boundary**: Phase 0 is closed and frozen. This file does not reopen former P1-T05 / Real Choice Moment, global `r(t)`, or the RC-A semantic-sync decisions.

## 0. Verdict

This pass finds a strong **target separation** that must govern all later Phase-0.5 work:

```text
one-shot Selection occurrence
!= anchoring persistence
!= history-bearing Stable ISP
!= agency / consequence-sensitive revision
```

Under a literal `K = 0` relation deletion against the current post-RC-A architecture:

| Relation candidate | Selection occurrence target `Y_SEL` | Stable-ISP/history target `Y_ISP` | Pass-1 residue |
|---|---|---|---|
| explicit non-neutrality / asymmetry relation | loss is masked by P0-01 primitive actualisation; role not discharged | may remain structurally relevant in lower-layer realizations | **R4 compensated / unresolved** |
| reachable-set restriction / future-space narrowing | not constitutively required after RC-A | relevant to persistent constraint and continued-selectability analyses, but not sufficient by itself | **R3 for `Y_SEL`; R4 for broader persistence targets** |
| history carry-forward / writeback relation | one-shot event still occurs | Stable ISP / `L_2` history target fails | **R3 for `Y_SEL`; N1 for `Y_ISP`** |
| cost / friction / payability relation | one-shot event still occurs | domain-specific burden/intervention targets may fail; Stable ISP is not defined by cost alone | **R3 for `Y_SEL`** |
| consequence-return / same-bearer consequence relation | one-shot event still occurs | P1-T06 continued-selectability / downstream agency and collective revision targets lose a required relation | **R3 for `Y_SEL`; N1 for the declared recurrent bearer target** |

The main governance consequence is negative but important:

> **Phase 0.5 must not reconstruct Selection by conjoining history, cost, future-space restriction, consequence return, anti-script status, or agency-like relations.**

Those relations can be indispensable for thicker targets without being constitutive conditions of a one-shot Selection occurrence.

No residue label in this pass licenses promotion to primitive status. In particular, `R4` on non-neutrality is **not** evidence that `ε_pg` is the definition or universal cause of Selection.

## 1. Why a new post-RC-A pass is required

`Operations/Audits/SRT_CONCEPT_DELETION_GOVERNANCE_PASS1.md` was a useful pre-delete governance scaffold, but one of its protected targets was:

```text
real-choice / script-execution / ordinary-transition distinction
```

RC-A has since demoted former P1-T05 and explicitly blocked:

```text
script / habit / gradient / L2 automation
-> no Selection
```

Therefore the old Pass-1 target set cannot be inherited unchanged into Phase 0.5.

The current authoritative separation is instead:

```text
Selection != Agency
former P1-T05 is not a Selection criterion
P1-T06 Stable ISP remains active
continued selectability belongs to Stable ISP
conditional generative reselectability remains P2/P3
```

This pass treats those boundaries as fixed inputs, not as questions to reopen.

## 2. Audit tuple and target lock

Per GOV-SUB01, this pass declares explicit audit tuples rather than asking whether "the theory still works".

### 2.1 Primary target `Y_SEL` — minimal Selection occurrence

Preserve the current P0 minimum:

> a non-objectified potential difference acquires determinate manifest actuality as an `L_1` event, without requiring a prior chooser, agency, stable identity, persistence, or consciousness.

Context `C_SEL`:

- bearer: none required;
- scale/grain: one-shot constitutive occurrence;
- boundary: P0-01 / P0-02 event boundary;
- history: no prior persistent history required;
- measurement regime: claim-architecture / counterfactual consistency, not an empirical proxy;
- domain: cross-domain core;
- normative authority: none;
- time horizon: event horizon only.

### 2.2 Secondary target `Y_ISP` — recurrent history-bearing Stable ISP

Preserve P1-T06:

> the same perspective- and history-bearing process is recurrently reconstituted, receives currently effective non-equivalent candidates, carries writeback, remains continued-selectable, and bears downstream consequences across the declared interval.

Context `C_ISP`:

- bearer: same history-bearing process;
- scale/grain: recurrent process;
- boundary: P1-T06 result-state criterion;
- history: explicit writeback required;
- measurement regime: structural recurrence / history / continued-selectability;
- domain: cross-domain constitutive theorem;
- normative authority: none implied;
- time horizon: multi-step recurrent interval.

### 2.3 Refit budget, horizon and perturbation set

For this Pass 1:

```text
K = 0
```

Meaning: remove one relation from the current claim architecture without adding a substitute, changing the target, inventing a new variable, or moving the role into a renamed term.

Horizons:

- `H_SEL`: one occurrence;
- `H_ISP`: recurrent interval long enough for writeback and continued-selectability to matter.

Perturbation set `P` includes five conceptual boundary cases already licensed by the current architecture:

1. one-shot manifest event with no durable trace;
2. scripted / habitual / gradient-driven process that may still instantiate Selection;
3. event with durable history but no stable same-bearer recurrence;
4. recurrent process with history writeback;
5. recurrent process whose consequences are externalized or no longer return to the same process.

### 2.4 Evaluation vector

This governance pass uses only applicable dimensions from GOV-SUB01:

- `E_cf`: does deletion erase a counterfactual distinction already required by the target?
- `E_mech`: does deletion make the declared target structurally unstateable or only less mechanistically specific?
- `E_norm`: only where bearer / consequence attribution is explicitly part of the declared target; no moral claim is inferred.
- `E_orient`: does deletion collapse a useful distinction between occurrence, persistence, Stable ISP and agency?

`E_pred` / `E_int` are not used as empirical scores here. No experiment is claimed.

## 3. Candidate inventory — relations only

This pass audits relations already present in SRT or GOV-SUB01 language. It does not introduce a formal relation alphabet.

The candidate set is:

1. **non-neutrality / asymmetry** — an effective difference is not wholly neutral;
2. **reachable-set restriction / future-space narrowing** — an event changes what remains reachable / admissible;
3. **history carry-forward / writeback** — prior output constrains later admissibility or state;
4. **cost / friction / payability** — transition burden or resistance matters;
5. **consequence return** — downstream consequence returns to / is borne by the same process or collective structure.

These are audit labels only. They are not declared primitives or members of a new grammar.

## 4. Deletion test A — explicit non-neutrality / asymmetry

### 4.1 Removal

Remove from the relation description any explicit requirement that Selection occurrence must be produced by a separately specified asymmetry / non-neutrality relation.

Do **not** delete `ε_pg` from the repository or alter its current status. This is a relation-role test, not a symbol deletion pass.

### 4.2 `Y_SEL` result

The current P0 architecture still states P0-01 primitive actualisation directly:

```text
non-objectified potential
-> determinate manifest distinction
```

and explicitly says that gradients, asymmetries, `Ψ_f`, payability, normalization, closure and writeback may constrain or implement lower-level realizations but are not thereby the universal cause of the P0 kernel.

Therefore literal removal of an **explicit separately specified asymmetry relation** does not make `Y_SEL` unstateable. The loss is instead hidden by the primitive actualisation admission itself.

This is exactly the GOV-SUB01 failure mode of **compensation / masking**: the primitive stops the audit from deciding whether an independently stated non-neutrality role is dispensable or merely absorbed into what "determinate actualisation" already means.

### 4.3 Classification

**`R4 compensated / unresolved`**.

Not licensed:

```text
R4
-> epsilon_pg is primitive Selection
```

Also not licensed:

```text
P0 actualisation survives without explicit asymmetry
-> non-neutrality is false or irrelevant
```

### 4.4 Next test required

A later pass may ask whether "determinate manifest distinction" can be restated without silently re-importing non-neutrality. That is a semantic / rival-vocabulary stress test, not a license to add a new primitive relation.

## 5. Deletion test B — reachable-set restriction / future-space narrowing

### 5.1 Removal

Remove the claim that every Selection occurrence must, by definition, narrow or alter a future candidate / reachable set.

### 5.2 `Y_SEL` result

After RC-A, the former P1-T05 future-space restriction package is no longer a Selection-occurrence criterion. P0-01 / EX-A allow a manifest event to occur without already proving persistence, durable writeback, or stable future constraint.

Therefore `Y_SEL` survives.

### 5.3 `Y_ISP` result

For a recurrent Stable ISP, however, some history-sensitive constraint on later candidate reception remains relevant through:

```text
outputs at t constrain A_{t+1} with writeback
```

and through continued-selectability across recurrent reconstitution.

But "reachable-set restriction" is not by itself identical to the P1-T06 target. A process can have restricted reachability without perspective, same-process history, or continued-selectability.

### 5.4 Classification

- **`R3 target-relative dispensable` for `Y_SEL`**;
- **`R4 compensated / unresolved` for the broader persistence / Stable-ISP architecture** until tested jointly with history/writeback.

### 5.5 Hard guard

Do not reconstruct former P1-T05 by writing:

```text
future space changed
<-> Selection occurred
```

That equivalence is not current SRT.

## 6. Deletion test C — history carry-forward / writeback

### 6.1 Removal

Remove the relation by which an event's result constrains later state / admissibility through `L_2` history or equivalent writeback.

### 6.2 `Y_SEL` result

P0-02 explicitly separates occurrence from persistence. A one-shot actual `L_1` event need not already form a durable record or Stable ISP.

Therefore `Y_SEL` survives.

### 6.3 `Y_ISP` result

P1-T06 explicitly requires a history-bearing process whose outputs at `t` constrain `A_{t+1}` with writeback. Removing history carry-forward destroys that target rather than merely lowering one metric.

It also blocks the specific SRT role of `L_2` as more than inert bookkeeping for that recurrent target.

### 6.4 Classification

- **`R3 target-relative dispensable` for `Y_SEL`**;
- **`N1 current target-relative indispensable` for `Y_ISP`** under `K=0`, `C_ISP`, `H_ISP`.

This is not a claim that history is necessary for all Selection or ontologically fundamental simpliciter.

---

## 7. Deletion test D — cost / friction / payability

### 7.1 Removal

Remove any requirement that a Selection occurrence must incur or be identified by a separately measured `Ψ_f`, energy cost, friction, loss, stress, pain, or comparable payability readout.

### 7.2 `Y_SEL` result

P0-01's boundary already states that `Ψ_f` and payability do not universally cause or define the primitive actualisation kernel. The bootstrap proxy rule also blocks identifying any local cost proxy with canonical `Ψ_f` without additional conditions.

Therefore `Y_SEL` survives.

### 7.3 `Y_ISP` result

P1-T06 does not define Stable ISP by a universal friction threshold or mandatory cost scalar. Domain-specific cost / switching / payability measures remain useful for L2, intervention and D2 work, but deleting them from the **definition-level relation set** does not by itself erase the P1-T06 structural criterion.

### 7.4 Classification

**`R3 target-relative dispensable` for `Y_SEL`**.

No broader `N1` verdict is assigned in this pass because the relevant target would need to be a declared payability / intervention / burden phenomenon rather than Stable ISP simpliciter.

### 7.5 Hard guard

Do not infer:

```text
no measured cost
-> no Selection
```

and do not infer:

```text
energy spent
-> consequence bearing
```

## 8. Deletion test E — consequence return / same-process bearing

### 8.1 Removal

Remove the relation that downstream consequences return to, constrain, or are borne by the same history-bearing process / declared collective structure.

### 8.2 `Y_SEL` result

RC-A separates Selection from agency and stronger bearer standing. A one-shot Selection occurrence does not require that a stable subject, agent or moral bearer later absorb the consequence.

Therefore `Y_SEL` survives.

### 8.3 Recurrent bearer target result

For the specific recurrent target encoded by P1-T06's continued-selectability condition, the same history-bearing process is required to continue receiving effective candidates **and bearing downstream consequences of what it selected**.

For collective work, `M(t)` consequence return likewise remains structurally relevant to downstream collective agency / revision auditing even though T-COLL-4 no longer defines Selection authenticity.

Deleting consequence return therefore destroys the declared recurrent-bearer target while leaving one-shot Selection untouched.

### 8.4 Classification

- **`R3 target-relative dispensable` for `Y_SEL`**;
- **`N1 current target-relative indispensable` for the declared recurrent same-bearer / Stable-ISP target**.

This does not prove consciousness, freedom, moral responsibility or agency by itself.

## 9. Cross-test matrix — what remains after subtraction

### 9.1 Minimum Selection occurrence residue

After subtracting future-space narrowing, history writeback, cost/friction and consequence return from the **one-shot target**, the current architecture still retains:

```text
primitive actualisation
+ determinate manifest distinction
+ a well-formed formal role-carrier sufficient to state the event
```

But the non-neutrality/asymmetry role remains unresolved because primitive actualisation can mask it.

This residue is a **description of current architecture under subtraction**, not a newly approved Selection definition.

### 9.2 Stable ISP residue

Stable ISP does not survive deletion of:

```text
history carry-forward / writeback
```

or of the declared same-process consequence-bearing relation when the target is P1-T06 continued-selectability across the recurrent interval.

It also cannot be reconstructed from future-space restriction alone.

### 9.3 Agency residue

This pass intentionally does not define agency. The result only confirms the RC-A jurisdictional direction:

```text
relations that thicken Selection into recurrence / bearing / revision
must not be back-projected into the occurrence criterion
```

## 10. Joint-removal priorities for Pass 2

GOV-SUB01 requires interaction tests because single deletion can be masked by redundancy.

The next legitimate relation tests are:

### J1 — history + future-space restriction

Question:

> If both writeback and explicit reachable-set restriction are removed, does any non-trivial persistence distinction remain beyond repeated independent occurrences?

Purpose: determine whether the current apparent role of future-space narrowing is only a surface description of history efficacy.

### J2 — history + consequence return

Question:

> Can a Stable ISP remain the same history-bearing process if outputs are stored but consequences no longer return to / constrain that same process?

Purpose: separate inert memory from historically efficacious same-bearer continuity.

### J3 — non-neutrality + reachable-set restriction

Question:

> When explicit asymmetry and future-space narrowing are jointly removed, is "determinate actualisation" doing all remaining work by stipulation?

Purpose: detect hidden reparameterization inside the primitive kernel. This is the highest-risk conceptual test and must not be answered by inventing a new relation primitive.

### J4 — cost + consequence return

Question:

> Does the architecture still distinguish "a transition was costly" from "the relevant process bore the consequence" when both are removed or varied independently?

Purpose: preserve the existing fast negative:

```text
energy spent is not consequence bearing
```

No joint-removal result is executed in Pass 1.

## 11. Relation-level implications for the old selection-irreducibility question

GOV-SUB01 §8.1 asks whether the word / primitive role of `selection` can be removed while retaining ordinary relational vocabulary such as:

```text
asymmetrical constraints
reachable-set restriction
history dependence
cost
consequence return
```

Pass 1 changes how that question must now be posed.

The post-RC-A architecture shows that four of those five relation families are **not jointly constitutive of one-shot Selection**. Therefore a future rival-vocabulary test must not define the competitor as "all five relations except the word Selection" and then claim success or failure from that package. Doing so would compare Selection against a thicker persistence/agency bundle.

A valid future irreducibility duel must instead freeze at least two targets separately:

```text
Duel A: one-shot manifest actualisation
Duel B: recurrent history-bearing Stable ISP
```

and ask whether ordinary rival vocabulary can preserve each target without silently re-importing the primitive role under another name.

This pass does **not** resolve P0-01 irreducibility.

1. The old anti-script / Real Choice target is not admissible as a Phase-0.5 Selection target after RC-A.
2. History/writeback is not necessary for one-shot Selection occurrence but is `N1` for the declared Stable-ISP history target.

### Still open

1. Whether explicit non-neutrality/asymmetry is independently indispensable or is currently masked inside primitive actualisation (`R4`).
2. Whether future-space restriction adds anything over history/writeback in recurrent targets (`J1`).
3. Whether memory without same-process consequence return is sufficient for Stable ISP continuity (`J2`).
4. Whether P0-01 actualisation can survive a rival-vocabulary rewrite without hidden reparameterization (`J3`).
5. Whether cost and consequence bearing remain cleanly separable under joint perturbation (`J4`).

### Next action

**Run Pass 2 as a joint-removal relation audit, beginning with `J1` and `J2`.**

Do **not** begin with J3. J3 touches the primitive actualisation stopping point and should only be attempted after the lower-risk persistence relations are separated cleanly.

# Facing reconstruction Pass A — Gate / active bridge / property / objectification

> **Role:** fifth internal target cluster in the v0.2 bounded Facing reconstruction pass.
>
> **Boundary:** the #1066 cognition / Gate package remains downstream frozen candidate material. This audit retypes analytic roles only; it does not reopen the toy simulation, HP-B, or canonical owners.

## 0. Author source to preserve

Direct intuition:

> 「也许门控并不是零和一。而是为了将两种状态连接起来创造稳定性。去创建一个连接的桥梁。所以状态之间获得了一个统一的标签。我们称之为状态的属性。随着属性的稳定，状态逐渐变成了一种对象。」

Later author clarification already preserved:

~~~text
active bridge formation
!= Gate by definition.
~~~

This distinction becomes decisive under Facing reconstruction.

## 1. Four burdens had been bundled together

The recent research package contains at least four different burdens:

~~~text
A. bridge / relation formation
B. formed Gate organization
C. current Gate operation
D. property / object stabilization and objectification
~~~

They interact recursively but should not be one ontology noun.

## 2. Bridge formation — generative formation process, not Gate

Bridge formation asks how changing encounters / transformations become a reusable relation.

Minimal route:

~~~text
encounter / perturbation / action
-> repeated constrained transformation
-> relational consequence
-> retention / reuse / perturbation tolerance
-> bridge candidate.
~~~

Facing analysis:

~~~text
FACE-L0:
  bridge formation does not define primitive generativity;
  it is one formed/domain process through which new relations can become available;

FACE-L1:
  an actual relation is formed / revised in the current episode;

FACE-L2:
  retention, reuse and perturbation tolerance turn successful coupling
  into reusable infrastructure.
~~~

Disposition:

~~~text
bridge formation = KEEP as process description / research burden;
bridge formation =/ Gate;
bridge formation =/ primitive Selection.
~~~

Strong mature-neighbor pressure from sensorimotor learning, invariant learning and relational category learning remains controlling; this burden is not SRT-specific novelty by itself.

## 3. Formed Gate — stabilized organization carrying a gating role

Repository routing already says:

~~~text
Gate
= formed organization / relation structure sufficiently stabilized
  to carry gating work.
~~~

Facing analysis:

~~~text
FACE-L2:
  Gate's formed organization, retained boundary/equivalence/transition structure,
  support and learned relation are primarily retained / stabilized burden;

FACE-L1:
  Gate becomes currently operative when used in a Selection / control episode.
~~~

Gate therefore does not need an L0-root definition.

Disposition:

~~~text
Gate = KEEP;
RETYPE as formed organization / role carrier;
Gate-as-root-generativity = REJECT;
Gate geometry = downstream formed description unless separately qualified.
~~~

## 4. Gate operation — current use, distinct from Gate standing

Current gate operation means:

~~~text
bias / permit / suppress / classify / guide
using an already formed organization.
~~~

This is primarily an L1-facing operation.

Thus:

~~~text
formed Gate standing
!= current Gate operation;

having a Gate
!= the Gate is currently active;

Gate operation
!= bridge formation.
~~~

Disposition:

~~~text
Gate operation = KEEP as operation label;
do not make a separate ontology entity out of it.
~~~

## 5. Property — stabilized relational invariant / reusable compression

The author intuition and #1066 crosswalk support:

~~~text
changing manifestations / interactions
-> stable relation / invariant
-> reusable property-like compression.
~~~

Facing analysis:

~~~text
FACE-L1:
  a property is currently attributed / used / manifested in objectification;

FACE-L2:
  the load-bearing part is the retained relational invariant / regularity
  that allows reuse across transformations.
~~~

Property is therefore not a primitive atom attached to a pre-given object.

But do not infer:

~~~text
all properties are subject-relative;
all world-side dispositions reduce to learned labels;
all properties require one universal Gate mechanism.
~~~

Disposition:

~~~text
property-as-stabilized-relational-invariant = KEEP as research candidate;
property-as-new ontology primitive = NO;
property formation = mature-neighbor paid at broad functional level.
~~~

## 6. Object / objectification — current cut plus retained support

A useful decomposition is:

~~~text
L1-facing objectification
= current determinate cut / foregrounded unit / boundary treated as this object;

L2-facing object support
= retained invariants, bridges, learned boundary relations, action relations,
  history and recurrent closure that make the cut rapidly reproducible.
~~~

Thus a mature object should not be reduced to either:

~~~text
current L1 token only
or
stored L2 representation only.
~~~

The object is analytically accessible under both facings without becoming a third primitive layer.

Disposition:

~~~text
objectification = KEEP;
object = KEEP as domain / formed cut where warranted;
object-as-primitive furniture = NOT ASSUMED;
object closure = formed stabilization route, not L0 source.
~~~

## 7. Re-reading Form -> Close -> Compose

The #1066 typed formalization intentionally distinguishes:

~~~text
Form
Close
Compose.
~~~

Facing reconstruction now sharpens their status:

~~~text
Form
= current formation / revision process + later retention;

Close
= stabilization / reciprocal recoverability of formed relations;

Compose
= organization of multiple formed closures under current conditions.
~~~

These are best treated as **formation / stabilization / composition operators in a domain model**, not as the metaphysical root of L0-facing generativity.

Their outputs may reshape later generative conditions, but:

~~~text
reshaping later conditions
!= being the primitive source of Selection.
~~~

## 8. Gate geometry retyping

Equivalence, boundary, neighborhood, transition/reachability and perturbation stability are valuable descriptions of a formed organization.

Under Facing separation:

~~~text
Gate geometry
= primarily L2-facing retained / stabilized geometry;

current gate configuration / operation
= L1-facing use;

L0-facing residual
= what relation / distinction / recut remains formable beyond the current Gate geometry;
  NOT another hidden complete geometry.
~~~

Therefore the phrase `Gate geometry constructs the geometry in which later Selection occurs` should be read as:

> retained formed organization materially conditions later Selection.

It must not imply:

> L2 geometry is the ontological source of primitive Selection.

## 10. Verdict

~~~text
TARGET 5 RESULT

NO single 'Gate' concept should carry formation + standing + operation + property + objectification.

KEEP:
- bridge formation as process;
- Gate as formed organization / role carrier;
- Gate operation as current use;
- property as stabilized relational invariant candidate;
- objectification / object closure as formed cut/stabilization burdens.

RETYPE:
- Gate geometry -> primarily L2-facing formed geometry;
- Form / Close / Compose -> downstream typed model operations;
- active bridge formation -> not Gate by definition.

REMOVE ROOT CLAIM:
- Gate / Gate geometry is NOT the primitive source of L0-facing generativity.
~~~

## 11. Consequence for toy simulation

The frozen toy simulation remains meaningful as a test of a formed cognitive architecture:

~~~text
relation formation
-> invariant/property learning
-> closure
-> composition / later control.
~~~

But any positive result would support only that bounded formed architecture. It would not validate primitive Selection, O0 or L0 ontology.

This restates the package's own zero-gain guard more cleanly.

# GRG X3b / X4b invariance + fail-case audit — Pass 1

## 0. Question

After mature-source pressure and burden splitting:

1. do X3b and X4b preserve meaning across current cases?
2. can they reject explicit near-misses?
3. are they doing anything beyond generalized institutional analysis / niche construction / path dependence?

## 1. X3b

Candidate:

~~~text
typed/shared expectation
-> operative embodiment / maintenance
-> changed participant action possibilities
~~~

Positive cases:

- Internet standards: technical compatibility / implementation;
- Montreal Protocol: legal-organizational implementation and technology substitution;
- Nepal irrigation: rules-in-use, monitoring, sanctions and participant organization.

The shared burden is not "they all have rules".

It is:

~~~text
an expectation becomes operative through a typed carrier
and materially changes later participant action possibilities.
~~~

Negative control:

Meyer–Rowan formal-structure decoupling.

~~~text
formal structure present
but coupling to ongoing activities can be weak / decoupled.
~~~

Classification:

~~~text
X3a = possible / yes
X3b through the claimed work-activity channel = FAIL unless separately shown
~~~

Verdict:

~~~text
semantic invariance across current technical/legal/local-institution cases
= PROVISIONAL PASS

negative-control discrimination
= PASS

X3b = RETAIN / M2
M3 = NO
distinctiveness = OPEN
substitutability pressure = HIGH
~~~

Why no M3:

- local mechanisms are already owned by mature standards / institutional theories;
- GRG has not yet shown pre-result transfer gain beyond organizing the shared burden;
- the abstraction may still be too close to generic institutional / control language.

## 2. X4b

~~~text

~~~

Positive pressure:

Negative control:

~~~text

selection / viability feedback burden = not paid by that record alone
~~~

Classification:


This is an epistemic fail case, not an ontic claim that beaver engineering lacks evolutionary feedback.

Verdict:

~~~text
semantic invariance = PASS
negative-control discrimination = PASS
~~~

Across genuinely different domains:

~~~text
cross-domain invariance = NOT YET ESTABLISHED
~~~

Montreal pays X4a strongly but does not supply the same selection / viability feedback topology.

Therefore:

~~~text
X4b = RETAIN / M2 / DOMAIN-LIMITED
M3 = NO
~~~

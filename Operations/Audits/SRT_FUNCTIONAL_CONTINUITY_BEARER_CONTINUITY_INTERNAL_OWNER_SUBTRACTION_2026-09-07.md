# Functional continuity vs bearer continuity — internal owner subtraction

## 1. Question under audit

The Osako guided reading exposes a clean conceptual gap:

```text
same reusable computation
!= automatically
same continuing bearer
```

The audit asks whether that gap is already owned internally, and what—if anything—remains available for author re-entry.

---

## 2. Existing owners already pay most obvious answers

### PH-IND01

Already separates:

```text
object tracking / re-identification
!= bearer continuity
```

Therefore stable public tracking of a functional locus cannot by itself establish bearing.

### PH-IND02

Already blocks:

```text
closure = bearer
persistence = bearer
boundary drawn by analyst = bearer
```

and gives the stronger P3 bearer-candidate bundle:

```text
same-unit consequence return
+ history-bearing writeback
+ future-selectability change
+ boundary continuity
```

So the statement

> functional continuity is insufficient; same-unit consequence closure matters

is not a new result of the Osako reading.

### PH-IND06

Already states:

```text
Persistent Process != Bearer
feedback received != consequence closed on the same bearer
functional extension != bearer extension
```

and places the main negative-control burden on non-outsourcing / replacement / checkpoint substitution.

Therefore the distinction

```text
same service / same function / same performance
!= same bearer
```

is substantially owner-paid.

### PH-IND05

Branching / consequence-separability work already prevents simple continuity criteria from solving copy / fission / successor identity merely by shared state, history representation or function.

### PH-MEM01

Objectified history, retained information and public memory description are already separated from own-history attribution and bearer identity.

---

## 3. Cycle 1 subtraction

Cycle 1 already tested a history-localization operational route and found that stable versus shuffled writeback was completely absorbed by ordinary recurrent credit assignment.

Therefore this new gate must not return to:

```text
history-shaped function
-> same bearer
```

or:

```text
stable functional address across time
-> bearer genesis
```

unless an author-owned distinction changes the problem partition.

The surviving Cycle-1 contribution is only a genetic interpretation of already-existing bearer relations:

```text
same-unit bearing relations may participate in bearer formation
```

not an independent scientific criterion.

---

## 4. Cycle 2 subtraction

Cycle 2 retains the author-confirmed dependency that a continuing Selection-position / One can form downstream of repeated two-sided Selection and sedimented consequences.

But the following are already strongest-neighbor / generic-dynamics territory:

```text
functional specialization
mutual support / inhibition
adaptive topology
history-shaped organization
persistent loci of operation
```

Therefore FC-D style co-formation cannot claim Level 1 merely because function and organization stabilize together.

---

## 5. What remains genuinely open

After internal subtraction, the live question is narrower than the initial formulation:

```text
not:
what makes a function persist?

not:
what makes a module causally useful?

not:
what makes history affect later computation?

not:
what makes a process re-identifiable?

live question:
what relation, if any, makes changing realizations count as later operations
of the same consequence-bearing One / bearer,
without presupposing the bearer boundary or reducing identity to function?
```

That question is not yet answered merely by citing PH-IND02/06, because those owners provide **candidate tests / pressures** rather than a complete numerical-identity theorem or first-Bearer derivation.

This remaining opening is therefore best classified as:

```text
D — unresolved relation / author-reentry target
```

not as a new owner or a Level-1 result.

## 6. Option-level subtraction

### FC-A — functional-position sufficiency

Disposition:

```text
HEAVILY PRESSURED / likely reject unless author explicitly strengthens it
```

Reason: collapses bearer identity toward functional equivalence and conflicts with existing replacement / non-outsourcing guards.

### FC-B — same-unit consequence closure

Disposition:

```text
SUBSTANTIALLY OWNER-PAID
```

PH-IND02/06 already contain the core ingredients. Could still be author-confirmed as the intended meaning, but would mainly consolidate dependency.

### FC-C — higher-order bearer with migrating functions

Disposition:

```text
DECOMPOSITION VALUE SURVIVES
```

The negative claim that functional-locus continuity is neither necessary nor sufficient for bearer continuity appears useful and consistent with existing owner guards. The positive criterion for the higher-order bearer remains open and cannot be inferred from analyst scale choice.

### FC-D — role/closure co-constitution

Disposition:

```text
ONTOLOGICALLY LIVE / STRONG ABSORPTION RISK
```

It may fit Cycle-2 formation intuitions, but generic organizational-closure / adaptive-network accounts can likely reproduce much of the visible structure.

# GRG M4 absorption / framework-adequacy audit — Pass 1

## 0. Trigger

Two prospectively frozen M4 attempts have now completed.

~~~text
M4-01:
X3b -> AI-agent authorization
= ABSORBED / M4 NO

M4-02:
X4b -> road-capacity induced-demand feedback
= ABSORBED / M4 NO
~~~

Both were frozen before dedicated target-domain source audits.

Both stopped before duplicate execution under M4-E0.

## 1. Primary result

~~~text
M4 relations = NONE
M5 relations = NONE
scientific distinctiveness = NOT ESTABLISHED
~~~

No rescue interpretation is allowed.

However:

~~~text
M4
!=
the sole adequacy criterion for GRG as a framework.
~~~

M4 measures one specific burden:

> prospective target-domain design gain beyond ordinary mature target practice.

GRG's declared framework target is broader:

> learn constrained recurring generative relations across heterogeneous domains while preserving source-native mechanisms and using the relations to organize comparison, revision, generative expectation and civilizational learning.

These two evaluation questions must remain separate.

## 2. Do not weaken M4

The absorption results must not be converted into positive M4 evidence.

Keep:

~~~text
M4-01 = NO
M4-02 = NO
~~~

Do not rename:

~~~text
absorption = transfer success
~~~

Absorption means the mature target domain already owned the proposed distinction / control.

## 3. Framework adequacy uses a separate scorecard

The GRG Research Framework already defines programme-level adequacy axes.

They should remain separate from M-status.

### Compression

Question:

> Does GRG connect independently grounded relations without erasing source-native mechanisms?

Current state:

~~~text
PROVISIONAL POSITIVE PRESSURE
~~~

Examples:

- X3b survives technical protocol, legal/treaty and local institutional carriers;
- X4b survives biological selective-environment and ML performative-distribution realizations.

But source-native ownership remains external to GRG.

### Constraint

Question:

> Does the framework reject tempting mappings?

Current state:

~~~text
PAID / STRONGEST CURRENT FRAMEWORK RESULT
~~~

Examples:

- R1a != R1c;
- X3a does not entail X3b;
- X4a does not entail X4b;
- ecosystem engineering does not automatically pay selective feedback;
- formal structure does not automatically pay operative coupling;
- M3 does not entail M4;
- M4-E0 stops duplicate target-domain experiments.

### Transfer

Question:

> Does GRG generate a useful target-domain design before target inspection?

Current state:

~~~text
NOT PAID AT M4
~~~

Two prospective attempts were absorbed.

### Revision

Question:

> Does evidence change the grammar?

Current state:

~~~text
PAID
~~~

Examples:

- R1 split into R1a/R1b/R1c/R1d;
- X3 split into X3a/X3b;
- X4 split into X4a/X4b/X4c;
- X4b generic label revised after ML transfer;
- M3/M4 distinction added;
- M4-E0 added after absorption.

### Coverage

Current state:

~~~text
PARTIAL
~~~

The framework now spans neuroscience/RNN, human coordination, institutions, technical protocols, public health, ecology, ML and transport.

Physics, chemistry, broad economics, law, culture/religion and long-duration historical cases remain underdeveloped.

### Position sensitivity

Current state:

~~~text
PARTIAL / METHOD PRESENT, NOT BROADLY VALIDATED
~~~

Civilizational records require immediate/delayed affected positions, externalized costs and time horizon.

The method exists; broad empirical use remains limited.

### Normative discipline

Current state:

~~~text
PROVISIONAL PASS AT ARCHITECTURE LEVEL
~~~

The framework repeatedly preserves:

~~~text
functional / generative expectation
!= full moral legitimacy
~~~

No moral scoring engine has been opened.

## 4. Interpretation

The current evidence supports:

~~~text
GRG is functioning as a constrained cross-domain
research / comparison architecture.
~~~

The current evidence does NOT support:

~~~text
GRG currently produces novel target-domain mechanisms or controls.
~~~

This is an important distinction.

A mature unifying grammar may be useful even when each domain already owns its mechanisms.

But scientific distinctiveness requires more than integrative restatement.

## 5. Mainline consequence

Do not let serial M4 novelty hunting become the whole programme.

M4 remains an important calibration lane.

The framework mainline should now test the architecture in its intended role:

~~~text
source-native records
-> relation library
-> cross-domain burden matrix
-> generative-expectation ledger
-> position / consequence comparison
-> grammar revision
~~~

This is not a lower standard.

It is a different declared output.

## 6. New mainline artifact requirement

Build:

~~~text
GRG Cross-Domain Burden Matrix v0.1
~~~

It must make visible for every relation:

- source-native domain;
- mechanism owner;
- GRG burden;
- admission / fail status;
- maintenance / enforcement provenance;
- conditioning field where relevant;
- negative control;
- generative expectation;
- normativity status;
- M-status;
- absorption / transfer state.

Success means:

~~~text
one matrix can compare heterogeneous cases
without hiding mechanism differences or evidence asymmetry.
~~~

## 7. Second artifact requirement

Build:

~~~text
Generative Expectation Ledger v0.1
~~~

For each relation/case:

~~~text
formed relation
-> structural expectation
-> actual / possible trajectory
-> indexed G-stronger / G-weaker question
-> affected positions / horizon
-> additional moral premise required
~~~

This is the bridge from GRG research architecture toward social / civilizational use.

It must not become a moral score.

## 8. Calibration routing

M4 attempts remain allowed, but not as a serial default queue.

Use M4 when:

- a relation is mature enough;
- a target is genuinely uncertain;
- the prospective design is meaningful.

Otherwise work on framework coverage / constraint / civilizational integration.

HKB access remains a separate calibration item.

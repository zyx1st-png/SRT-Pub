# GRG GTS reconciliation — Pass 1

## 0. Question

Does the new Generative Transformation Signature schema do more than rename the old Relation Record / Relation Library structure?

Test three deliberately different records:

~~~text
GTS-001
RNN adverse calibration
= local causal failure / proxy discipline

GTS-002
Kubernetes X3b
= cross-domain structural PASS + M4-E0 absorption

GTS-003
CIV-006 X4c
= history / reconstruction / successor inheritance / carrier composition
~~~

A useful schema should improve discrimination without erasing source-native mechanism or historical provenance.

## 1. Evaluation criteria

Declare before verdict:

~~~text
C1 source fidelity preserved
C2 old negative controls preserved
C3 old failure conditions preserved
C4 relation labels no longer reified as primary units
C5 strongest horizontal / target-domain comparator made explicit
C6 P_G and E_G separated rather than forced together
C7 M3 structural recurrence and M4 prospective gain remain separable
C8 GTS adds a nontrivial research distinction not already visible in the old record
C9 no canonical implication added
~~~

Dominance requires no regression on C1-C7/C9 and a strict gain on at least C8.

## 5. Template backpressure

The first real records expose one v0.2 template overconstraint.

A GTS may legitimately be:

~~~text
local adverse calibration
causal diagnostic
proxy audit
negative control
~~~

without opening:

~~~text
Generative Order
E_G
wholeward analysis
cross-objectification gain.
~~~

Forcing those sections would create fake completeness.

Template correction:

~~~text
Generative Order analysis =
OPENED / NOT OPENED / N.A.

E_G =
OPENED / NOT OPENED / N.A.

wholeward =
... / NOT OPENED / N.A.

cross-objectification gain =
... / NOT CLAIMED / N.A.

proxy bridge =
... / N.A.
~~~

This is a productivity gain from actual use of the schema.

## 6. Relation Library after GTS reconciliation

The first pass does NOT justify deleting the Relation Library.

Keep it for:

- historical relation extraction;
- M-status;
- negative controls;
- old transfer provenance;
- route lookup;
- family-level recurrence tracking.

But:

~~~text
Relation Library
!= primary record unit
!= ontological skeleton
~~~

GTS becomes the primary bounded process record.

Recommended linking rule:

~~~text
legacy family / case
-> one or more GTS reconciliation records

GTS
-> legacy owners / source-native evidence
~~~

Do not rewrite old evidence records merely to match the new schema.

# GRG GTS reconciliation — Pass 1 after #1025

## 0. Question

Does GTS v0.2 add enough constraint to justify its extra complexity over the legacy Relation Record / transfer / case surfaces?

This is NOT a winner-style schema competition.

The comparison must count both gains and costs.

## 1. Predeclared comparison dimensions

~~~text
C1 source fidelity
C2 negative controls
C3 failure / narrowing conditions
C4 strongest-horizontal / mature-practice baseline visibility
C5 process integration across relation cuts
C6 bridge / evidence-credit separation
C7 evidence-generative provenance
C8 M3 / M4 separation
C9 E_G / Generative Order discrimination
C10 schema cost / verbosity / N.A. burden
~~~

Interpretation:

~~~text

= no regression, not a gain

= a useful distinction becomes materially more explicit / enforceable

= old burden lost or new misleading credit introduced
~~~

## 3. Real GTS gains that survive the audit

### G1 — one bounded process surface

For X4c, GTS can put:

~~~text
reconstruction-output
-> persistence / carrier
-> successor history-input
-> later consequence
~~~

into one bounded process record without asserting that these are separate ontic relations.

This is a readability / process-integration gain.

### G2 — mandatory strongest horizontal baseline

The legacy template had a target-domain ordinary-practice comparator for transfer.

GTS extends comparator discipline to every bounded record, including local negative calibrations.

This is a NARROW gain, not a wholly new invention.

### G3 — evidence-generative provenance

#1025 bounded use exposes a real missing dimension:

~~~text
O_R != O_W
recurrence != independent recurrence
construction != discovery
designed / diffused recurrence
evidence-purpose credit boundaries
alternative-generation audit.
~~~

This produces nontrivial narrowing in all three records.

This is the strongest schema gain in Pass 1.

### G4 — modular non-opening

A record may explicitly keep:

~~~text
Generative Order
E_G
wholeward
cross-objectification gain
~~~

closed when they are not load-bearing.

This is useful only if:

~~~text
NOT OPENED requires a reason
and
positive credit requires opening the relevant module.
~~~

It is not a gain that old RR-001 lacked "NOT OPENED"; rather, it is a gain in making optionality systematic across the process-first schema.

## 4. Real-use failures / costs

### C-A — E_G analytic inflation

The first draft opened E_G in GTS-002 and GTS-003.

In both cases the content was analytic:

~~~text
remove constitutive enforcement -> order hollow/destroy

maintain infrastructure -> preserve
replace infrastructure -> reorganize/destroy.
~~~

These add little beyond GO3 / GO5 or ordinary persistence semantics.

Correction:

~~~text
GTS-002 E_G = NOT OPENED
GTS-003 E_G = NOT OPENED.
~~~

Real-use finding:

> E_G should not be opened merely because an operative mechanism or persistent structure exists.

### C-B — template size / completion burden

GTS is materially larger than the legacy Relation Record.

Risks:

- duplicate evidence narration;
- N.A. boilerplate;
- false pressure to populate every philosophical module;
- reviewer fatigue;
- hidden credit inflation through sheer field count.

Correction:

~~~text
mandatory compact core
+ optional modules
+ NOT OPENED reason required.
~~~

### C-C — recurrence independence risk

GTS-002 initially treated Internet standards + Kubernetes + irrigation as three independent-looking realizations.

#1025 provenance pressure shows:

~~~text

may be DIFFUSED engineering recurrence
rather than independent replication.
~~~

This narrows XG1 credit.

### C-D — prospective discriminator inflation

GTS-003 initially treated:

~~~text

~~~

as a possible GRG-generated prospective discriminator.

Correction:

~~~text
SOURCE-NATIVE BUT UNOBSERVED

generic greenfield-vs-brownfield difference
cannot pay XG5 / M4.
~~~

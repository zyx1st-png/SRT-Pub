# GRG X6 position / horizon retyping audit — Pass 1

## 0. Trigger

The Atlas seed currently lists:

~~~text
X6 — multi-position consequence divergence
~~~

as a cross-domain relation candidate.

The new burden matrix and generative-expectation ledger create enough structure to ask whether X6 is actually a generative relation.

## 1. Test

A GRG relation candidate should normally carry a dependency topology such as:

~~~text
A -> formed relation / conditioning structure -> later B
~~~

with admission burdens, non-identities, source-native evidence and failure conditions.

"Different positions receive different consequences" does not by itself specify such a generative dependency.

It specifies an indexing requirement on the analysis of some other relation.

## 2. Case pressure

### AMR

There is real position / horizon divergence:

~~~text
current treatment benefit
vs
future population treatment effectiveness.
~~~

But the generative relation is X4b:

~~~text
antimicrobial use
-> changed selective environment
-> later resistance / treatment field.
~~~

The divergence indexes consequences of X4b.

It is not the causal mechanism itself.

### Road capacity

There is source-paid temporal divergence:

~~~text
immediate capacity effect
vs
post-adaptation network state.
~~~

Again the generative relation is X4b.

The horizon split describes where its consequences are read.

### Nepal irrigation

Tail-end availability makes position indexing indispensable.

The source-native generative relation remains an operative institutional regime / X3b candidate.

Position sensitivity does not become a second causal relation.

## 3. Verdict

~~~text
X6 as standalone GRG generative relation candidate
= NOT JUSTIFIED

X6 current Atlas role
= RETYPE
~~~

Retyped role:

~~~text
PH — Position / Horizon Consequence Index

type = cross-cutting analysis burden
not a GRG relation by default
not assigned M0-M5 relation maturity
~~~

No new ontology symbol is created.

"PH" is an operational navigation label only.

## 4. PH admission / use rule

Apply PH where:

- more than one materially affected position exists;
- consequences occur at materially different horizons;
- aggregation can hide consequence redistribution;
- externalized costs are plausible and evidence-addressable;
- correction / revision capacity differs by position or horizon.

For each use, state separately:

~~~text
position sensitivity = yes/no/open
horizon sensitivity = yes/no/open
directional divergence = evidenced/not established/open
reversibility = evidenced/open
externalized cost = evidenced/open
~~~

## 5. Strong anti-overclaim rule

Do not infer:

~~~text
multiple positions
-> conflict
~~~

Do not infer:

~~~text
different horizons
-> moral trade-off
~~~

Do not infer:

~~~text
directional conflict
-> which position morally wins
~~~

Each is a stronger claim.

## 6. Relation to normativity

PH strengthens the existing GRG normativity guard.

Generative expectation is indexed.

Therefore:

~~~text
G-stronger for relation / position / horizon A
can coexist with
G-weaker for relation / position / horizon B.
~~~

This is a descriptive / indexed normative structure.

Full moral adjudication still requires additional premises.

## 7. Framework value

This retyping is productive because it removes a false relation candidate.

The framework now distinguishes:

~~~text
generative relations
from
cross-cutting analysis dimensions.
~~~

That distinction prevents the Relation Library from becoming a bag of every useful analytical concept.

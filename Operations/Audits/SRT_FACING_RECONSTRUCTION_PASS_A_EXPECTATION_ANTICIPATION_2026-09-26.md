# Facing reconstruction Pass A — Expectation / anticipation / P_G / E_G

> **Role:** fourth internal target cluster in the v0.2 bounded Facing reconstruction pass.
>
> **Boundary:** this audit does not change the 2026-09-20 author adjudication, GRG v0.3, normative owners or canonical Spine. It separates overloaded uses of “expectation”.

## 0. Result first

Four burdens should remain distinct:

~~~text
B   = structural generative expectation
C   = formed-locus anticipatory realization
P_G = prospective prediction / constraint burden
E_G = order-relative transformation classification
~~~

They are related, but none is a synonym for the others.

The recent `formed Orientation` noun is not needed to mediate them.

## 1. B — structural generative expectation

Author-owned definition:

~~~text
an actually formed generative relation has an immanent directional burden:
some continuations / transformations preserve, realize, weaken, substitute,
hollow out or destroy the typed relation differently.
~~~

B does not require a formed locus.

Facing analysis:

~~~text
FACE-L0:
  B is NOT primitive O0 directionality and does not define Selection;

FACE-L1:
  a current formed relation may instantiate a non-equivalent structural direction;

FACE-L2:
  where the relation persists / is retained, its directional burden can shape later generation.
~~~

Thus B is a formed relational burden, not a primitive L0 source and not necessarily a predictive model.

Disposition:

~~~text
B structural generative expectation = KEEP
primitive orientation = KEEP DISTINCT
formed Orientation = NOT NEEDED
~~~

## 2. C — anticipatory realization

C requires enough formed organization to make direction operative **from somewhere**.

~~~text
C0 = embodied / enacted anticipation;
C1 = model-mediated anticipation.
~~~

Facing analysis:

~~~text
FACE-L1:
  present organization is actually regulated / enacted in a prospective way;

FACE-L2:
  retained organization, model, policy, learned relation or bodily organization
  carries conditions of possible continuation into current regulation.
~~~

C is therefore a stronger formed realization than B.

Important guard:

~~~text
B -/> C automatically;
Selection affecting later selectability -/> C automatically;
C0/C1 -/> consciousness automatically.
~~~

Disposition:

~~~text
C / C0 / C1 = KEEP
as downstream anticipatory-realization distinctions.
~~~

## 3. Prediction is not expectation

GRG v0.3 separates `P_G`:

> Given admitted generative conditions and a GTS, what can be constrained before observing the relevant result?

Possible P_G outputs include trajectory, reachability, boundary, locus, failure or topology change.

This is an epistemic / prospective discrimination burden.

By contrast B can exist without forecasting, and C0 can be enacted without explicit prediction.

Therefore:

~~~text
prediction accuracy
!= structural generative expectation;

P_G
!= C1 by definition;

C1 may realize / support a predictive model
but the GRG P_G burden is a research-output criterion, not a cognitive ontology term.
~~~

Disposition:

~~~text
P_G = KEEP in GRG programme;
do not use ordinary 'prediction' as a synonym for B or C.
~~~

## 4. E_G is not basal structural expectation

GRG v0.3 gives `E_G` a later, explicitly typed role:

~~~text
E_G(transformation | admitted Generative Order, position, scale, horizon)
= classify what a transformation means relative to that admitted order:
  preserve / strengthen / extend / reorganize / substitute / weaken / hollow / destroy / OPEN.
~~~

E_G requires Generative Order admission (GO1–GO5).

Therefore:

~~~text
B structural generative expectation
!= E_G automatically;

C anticipatory realization
!= E_G automatically;

E_G
= programme-level order-relative classification after stronger typing.
~~~

This corrects a recurring lexical problem: “generative expectation” has been used both for B and for the later GRG output `E_G`.

Disposition:

~~~text
E_G = KEEP as GRG v0.3 typed programme output;
RETYPE all unqualified 'Generative Expectation' usages by owner context;
do not backflow E_G into SRT ontology.
~~~

## 5. Normativity boundary

B opens a route to typed comparison because a formed relation can be preserved, weakened, substituted or destroyed differently.

But:

~~~text
directional difference
!= good / bad;

B
!= complete normativity;

E_G
!= moral legitimacy;

persistence
!= good;

larger order
!= morally prior.
~~~

Indexed normative comparison remains separately scoped to an admitted relation / position / scale and stronger moral claims retain their own gates.

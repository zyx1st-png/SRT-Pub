# GRG G0-G11 foundational retyping — Pass 1

## 0. Question

The previous G0-G11 list was intentionally provisional.

After the SRT -> GRG foundational bridge, the relevant question is no longer:

> Which G-slot comes next?

It is:

> What kind of thing is each G-slot in the reconstructed architecture?

Allowed role types:

~~~text
SRT-CONSTRAINT
FOUNDATIONAL-VERTICAL-RELATION
VERTICAL-HORIZONTAL-INTERFACE
COMPOSITE-RELATION
EXPECTATION-LAYER
NORMATIVITY-LAYER
REFLEXIVE-LEARNING-LAYER
OPEN / RETIRE / MERGE
~~~

This pass does not alter canonical SRT definitions.

## 1. Main finding

G0-G11 is not one homogeneous grammar ladder.

It currently mixes at least six different logical roles:

1. upstream SRT ontology / anti-objectification constraints;
2. candidate vertical generative relations;
3. SRT-specific typed formation interfaces such as One / Selection-position;
4. composite multi-position / cross-scale organizations;
5. expectation / anticipation / normativity layers;
6. reflexive inquiry / grammar-learning architecture.

Therefore:

~~~text
G0 -> G11
!= one linear ontological progression
!= one homogeneous relation library
!= one empirical maturity ladder
~~~

The list remains useful as historical discovery provenance, but should not remain the primary GRG skeleton.

## 3. G0 — non-exhaustion

Retyping:

~~~text
G0 -> SRT-CONSTRAINT
~~~

G0 prevents a completed object inventory or fixed future menu from being presupposed.

That is a condition on how GRG inquiry starts. It is not itself a recurring domain relation of the same type as retained efficacy or reconstructed conditions.

New role:

~~~text
C0 — non-exhaustion / non-preclosure guard
~~~

Do not place C0 in a relation library merely to find examples of openness.

Guard:

~~~text
non-exhaustion
!= hidden possibility warehouse
!= stochasticity
!= proof that every domain is open-ended in the same way
~~~

## 4. G1 + G2 — differential manifestation / relative backgrounding

Retyping:

~~~text
G1 + G2
-> SRT -> GRG bridge burden
-> differential manifestation / relative backgrounding
~~~

G1 correctly asks whether a difference becomes operatively non-equivalent.

G2 correctly asks what supporting, excluded or background relations co-change with that determination.

But at foundational level they are too close to the canonical Selection manifestation/backgrounding burden to behave like two ordinary GRG relations.

Action:

~~~text
C1 — differential manifestation / relative backgrounding
~~~

At domain level, records may still split efficacy differentiation, exclusion / inhibition, resource competition, constitutive boundary and support relations when source-native mechanism warrants it.

Do not make foreground/background a universal standalone grammar relation merely because primitive Selection has manifestation/backgrounding.

## 5. G3 + G4 — history / re-entry family

These two slots belong together but are not identical.

### G3 — retained efficacy

Retype as:

~~~text
R-HIST-a
prior differentiation / organization
-> remains materially effective
-> changes later generative conditions
~~~

This is a genuine vertical relation family.

Critical guard:

~~~text
trace != retained efficacy
retained marker != later conditioning
irreversibility != history automatically
~~~

### G4 — recurrent organization

Retype as:

~~~text
R-HIST-b
retained / regenerated organization
-> later generation
-> renewed organization
-> conditioning role can recur
~~~

G4 is a strengthened recurrent-reconstitution subtype, not an entirely separate primitive family.

Current R1 work should be re-routed under this family, with its imprint / scaffold / causal re-entry split preserved.

## 6. G5 — local generative locus formation

The old label mixes a generic GRG research burden and a specific SRT canonical formation type.

GRG-level family:

~~~text
R-LOC
local generative locus / individuation formation
~~~

Question:

> When does recurrent organization become relatively separable enough to function as a local generative from-where or unit of continued reconstitution?

SRT-specific specialization:

~~~text
R-LOC under SRT canonical admission
-> One, where One burdens are actually paid
~~~

Guard:

~~~text
domain individuation != SRT One automatically
local causal unit != One automatically
attractor != locus automatically
~~~

## 7. G6 — operative positionality

Retyping:

~~~text
R-POS
formed operative positionality
~~~

Question:

> When does a formed locality / organization change what becomes manifest, reachable, backgrounded or selectable relative to that locality?

This is a genuine vertical / interface family because it links formed organization to position-indexed horizontal manifestation / action.

SRT-specific specialization:

~~~text
generic operative positionality
!= Selection-position automatically
~~~

Selection-position remains owned by SRT canonical formation routing.

Guard:

~~~text
coordinate != operative position
observer variable != formed position
finite positionality != formed operative locus
~~~

## 8. G7 — dissolve the overloaded bundle

G7 should no longer survive as one grammar slot.

It mixes four logically different layers.

### G7a consequence exposure / return

Split route:

~~~text
ordinary consequence conditioning
-> R-HIST / re-entry family

same-locus prospective exposure
-> Bearer-facing SRT interface, where stronger burdens are paid
~~~

Do not treat all consequence return as Bearer.

### G7b structural generative expectation

Move to:

~~~text
E-B — structural generative expectation
~~~

This is a relation-derived expectation layer. It is not itself another world-relation family.

### G7c anticipatory realization

Move to:

~~~text
E-C0 — embodied / enacted anticipatory realization
E-C1 — model-mediated anticipatory realization
~~~

This layer depends on enough formed organization / position. It is not primitive grammar.

### G7d indexed normative comparison

Move to:

~~~text
N-INDEX
position / relation / scale / horizon indexed normative comparison
~~~

It is downstream of relation + expectation + consequence.

Verdict:

~~~text
G7 as single slot = RETIRED / SPLIT
~~~

The contents are retained. The bundle is not.

## 9. G8 — reconstruction of generative conditions

This is one of the strongest candidates for a core vertical GRG family.

The old wording required a formed position to alter later selectability. That may be too strong as a generic admission rule.

A system / process may reconstruct later conditions without first satisfying SRT Selection-position or Agency burdens.

Retyping:

~~~text
R-RECON
current organization / process
-> changes a typed generative condition / field
-> changes later accessibility / transition / viability / differentiation conditions
~~~

Possible stronger subtypes:

~~~text
R-RECON-POS
formed-position-mediated reconstruction

R-RECON-AG
agency-level reflexive reconstruction
~~~

where stronger SRT gates are independently paid.

Guard:

~~~text
state update != generative-condition reconstruction
long-term effect != reconstruction automatically
environment change != altered future generative field automatically
~~~

Current X4 belongs primarily here.

## 10. G9 — multi-locus / relation-level organization

Retyping:

~~~text
C-MULTI
multi-locus relational composition
~~~

This is a composite relation family.

It asks how multiple formed loci / processes can jointly constitute a relation-level organization that changes later conditions.

Guard:

~~~text
interaction != relation-level organization automatically
coordination != collective One / Bearer / subject automatically
~~~

The term multi-position should be used only where operative positions are independently established. Otherwise prefer multi-locus / multi-component relation-level organization.

## 11. G10 — cross-scale recursion

Retyping:

~~~text
C-XSC
cross-scale composition / recursion pattern
~~~

This is not a primitive relation.

It normally composes:

~~~text
formation
+ scale change / coarse organization
+ later conditioning / re-entry
~~~

Question:

> When does organization at one scale become a real condition on generation at another scale?

Guard:

~~~text
cross-scale correlation != cross-scale generative recursion
coarse description != higher-order cause
higher-order conditioning != mystical downward force
~~~

## 12. G11 — reflexive grammar learning

Retyping:

~~~text
L-REFLEX
reflexive grammar-learning layer
~~~

G11 concerns the research architecture itself:

~~~text
positioned inquiry
-> objectification
-> relation extraction
-> expectation / test
-> mismatch
-> grammar revision
~~~

It is not an ordinary world-relation primitive.

Science, philosophy, institutions and AI-assisted inquiry can be studied as realizations of this layer, but the layer's programme role remains meta-level.

Guard:

~~~text
AI synthesis != grammar truth
consensus != ontology
successful prediction != final grammar
~~~

## 13. Resulting minimal architecture

Pass 1 suggests a thinner architecture than G0-G11.

### A. SRT / foundational constraints

~~~text
C0 non-exhaustion / non-preclosure
C1 differential manifestation / relative backgrounding
~~~

These constrain GRG. They are not ordinary relation-library entries.

### B. Core vertical relation families

~~~text
R-HIST
history / retained efficacy / recurrent re-entry

R-LOC
local generative locus / individuation formation

R-POS
operative positionality

R-RECON
reconstruction of later generative conditions
~~~

These are the current strongest candidates for minimal vertical relation families.

### C. Composition families

~~~text
C-MULTI
multi-locus / relation-level organization

C-XSC
cross-scale composition / recursion
~~~

### D. Expectation / normativity

~~~text
E-B
structural generative expectation

E-C0 / E-C1
anticipatory realization

N-INDEX
indexed normative comparison
~~~

### E. Reflexive learning

~~~text
L-REFLEX
grammar learning / revision
~~~

## 14. Why formation is not a separate final family yet

The minimal architecture draft previously listed Formation separately.

Two possibilities remain:

~~~text
Option F-A:
R-FORM = generative formation of relatively stabilized organization

Option F-B:
formation = a cross-cutting burden inside every relation record
~~~

Current evidence does not yet force one choice.

Therefore:

~~~text
R-FORM = OPEN
~~~

This is an author-relevant remaining architecture choice.

## 15. Why maintenance is not a separate final family yet

Maintenance / recurrence may be:

- a generic relation family;
- a burden dimension attached to R-HIST / R-LOC / R-POS;
- mechanism-specific and not grammar-primitive.

Current recommendation:

~~~text
maintenance = CROSS-CUTTING BURDEN
pending stronger reason for independent family status
~~~

This avoids creating a grammar slot for every stage word.

## 16. Horizontal relations in GRG

GRG may store horizontal relations as evidence / realization / interface records.

But not every horizontal law becomes a GRG relation family.

Working distinction:

~~~text
horizontal relation record
= law / mechanism inside stabilized objectification

vertical GRG relation
= formation / retention / positionality / reconstruction relation
  that concerns how generative conditions or objectification-supporting organization
  are constituted or changed

interface relation
= explicit bridge between the two
~~~

This creates a place for mature domain science without flattening it into GRG.

## 17. Consequence for grammar

The first grammar should not be G0, G1, G2 ... G11.

It should be closer to:

~~~text
foundational constraints
+ typed core vertical relations
+ composition rules
+ horizontal/vertical interface rules
+ expectation / normativity derivation
+ reflexive revision operations
~~~

This better matches the SRT -> GRG bridge.

## 18. Revisions earned against the old list

~~~text
G0 = retyped upstream
G1/G2 = merged foundationally
G3/G4 = family + strengthening, not peers
G5 = generalized; One becomes SRT specialization
G6 = generalized operative positionality
G7 = split / retired as bundle
G8 = strengthened as core vertical reconstruction family
G9 = generalized from multi-position to multi-locus composition
G10 = composite scale bridge, not primitive
G11 = meta learning layer
~~~

This is a structural reorganization, not terminology cleanup.

## 19. Open decisions

1. Is R-FORM an independent core family or a cross-cutting burden?
2. Is maintenance an independent family or a burden dimension?
3. Is R-POS primitive enough for minimal GRG, or downstream of R-LOC?
4. Should R-HIST-a / R-HIST-b remain two named subtypes?
5. Does R-RECON require actual later effect, or can a changed generative field count before downstream realization?
6. What exactly distinguishes vertical relation from a sufficiently rich horizontal causal model in borderline cases?
7. Does grammar require closed composition rules, or is a revisable typed relation system sufficient?

These should be pressured before hardening v0.2.

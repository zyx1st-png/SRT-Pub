# Five-relation minimum tool — bounded operationalization pass

> Noncanonical machine audit. No canonical edit, theorem, novelty verdict, Level change or Ground solution is introduced.

## 0. Target

Operationalize the author-accepted research grammar:

```text
Generation / Standing / Shaping / Bearing / Revision
```

The test is not whether each word can be found in another theory. The test is whether SRT can use the five typed relations to make disciplined, falsifiable classifications across domains without illegal back-projection.

---

## 1. Generation

### Admission guard

Count a mapping as Generation only when evidence supports a real transition in what becomes operative / manifest / determinate, rather than mere description, relabeling, observation, preference report or selection from an already completed menu.

### Failure condition

Generation = NO / UNESTABLISHED when the evidence only shows:

```text
state readout;
observer classification;
post-hoc labeling;
reweighting among already individuated options;
behavioral choice with no account of how the relevant candidate/object became available.
```

### Mapping guard

A domain implementation need not literally use `A/A*`, but must pay the same dependency burden if claimed as an SRT Selection analogue.

---

## 2. Standing

### Admission guard

Standing requires evidence for a formed, continuing organization or process-unit under the relevant owner semantics. One, Stable ISP, Bearer and collective standing must remain separately typed.

### Failure condition

Standing cannot be inferred merely from:

```text
causal influence;
high control efficacy;
persistence of an externally maintained pattern;
statistical boundary;
centrality in a network;
visibility / salience;
observer convenience.
```

### Mapping guard

Never infer Bearer, subjecthood or agency from One / persistence / control alone.

---

## 3. Shaping

### Admission guard

Shaping requires evidence that retained history, scaffold, environment or formed structure changes later candidate generation, reachability, cost, friction, default path or comparison context.

### Failure condition

Shaping = NO / WEAK when the factor only correlates with later outcomes but does not alter later selection conditions under intervention / removal / matched comparison.

### Mapping guard

Strong shaping does not establish that the shaper has standing. Institutions, algorithms, languages and tools may shape without being Bearers or subjects.

---

## 4. Bearing

### Admission guard

Bearing requires a declared formed position and evidence that consequences/exposure are inherited at that position in a way that cannot be fully reassigned without changing the relevant relation or standing.

### Failure condition

Bearing cannot be inferred from:

```text
mere causal contact;
financial accounting label;
formal responsibility assignment;
benefit receipt;
authorship report;
execution role;
aggregate system loss.
```

### Mapping guard

Separate at least:

```text
authorizer / executor / beneficiary / bearer / repairer.
```

They may coincide but must not be assumed identical.

---

## 5. Revision

### Admission guard

Revision requires consequence-sensitive change to shaping conditions themselves:

```text
comparison rule;
boundary;
candidate-generation condition;
L2 scaffold;
policy-generator / model structure;
access rule.
```

### Failure condition

Revision = NO when behavior changes only inside a fixed candidate-generation architecture.

Examples:

```text
choosing a different option from the same menu;
parameter tuning with fixed structural constraints;
obedient adaptation to an unchanged external rule;
reset by an outside controller.
```

### Mapping guard

External reset is not endogenous generative reselectability unless the relevant formed position participates in the consequence-sensitive revision loop.

---

## 6. Cross-relation non-substitution rules

Reject these inference shortcuts:

```text
Generation -> Standing
Standing -> Bearing
Bearing -> Revision
Shaping -> Standing
Control -> Bearing
Performance -> Standing
Stability -> Revision
Option count -> Selectability
Aggregate gain -> all positions gain
Collective standing -> lower standing disappears
```

Each arrow requires independent evidence.

---

## 7. Cross-domain mapping discipline

A valid mapping must declare:

1. target scale / boundary;
2. candidate relation(s) among G/Sd/Sh/B/R;
3. observable or intervention supporting each relation;
4. strongest local rival explanation;
5. failure case where the SRT relation should be denied;
6. whether the mapping is ontology, bridge, mechanism or social diagnosis;
7. which higher-layer relations are explicitly absent.

No cross-domain analogy is accepted merely because vocabulary can be translated.

---

## 8. Two discriminator controls

### Control A — matched performance, different bearing/revision topology

Construct two systems with matched:

```text
output performance;
visible option count;
aggregate resource cost;
short-horizon stability.
```

Vary only whether:

```text
consequences return to the same formed positions that bear them;
and whether those positions can revise the shaping rules that generated the candidate space.
```

Prediction candidate:

```text
short-run performance may match;
long-run adaptation / exit / recovery under perturbation may diverge.
```

SRT loses architecture-level value if mature rival models reproduce the same classification and prediction without any extra mapping burden.

### Control B — matched standing/shaping, different revision

Construct two systems with matched:

```text
formed standing;
L2 scaffold strength;
continued selectability;
current shaping structure.
```

Allow only one system to route consequences into modification of candidate-generation rules / boundaries.

Prediction candidate:

```text
both may remain stable;
only the revision-capable system should show robust adaptation when the old scaffold becomes systematically mismatched.
```

Again, if strongest rivals reproduce this result with no SRT-specific cross-relation constraint, the five-relation tool must be demoted toward synthesis.

---

## 9. Explicit demotion criteria

Demote the tool to `disciplined synthesis / checklist` if any of the following is established:

```text
D1 a mature single-family rival natively types all five relations with equivalent guards;
D2 cross-relation separation produces no classification not already obtained by that rival;
D3 Controls A/B yield no additional discriminatory prediction or model constraint;
D4 the five-relation mapping requires domain-specific glue so extensive that SRT adds no compression;
D5 relation typing depends on observer-chosen labels rather than independently checkable structure.
```

Do not rescue SRT by adding more relations after a failed test without a new author gate.

---

## 10. Promotion criteria for a future architecture claim

A stronger architecture claim becomes eligible for author review only if at least one of these occurs:

```text
P1 a cross-domain classification repeatedly depends on preserving relation types that strong rivals collapse;
P2 a relation-order constraint generates a successful novel intervention / counterexample;
P3 deletion of the SRT relation typing produces a measurable prediction loss across more than one domain;
P4 the same typed rule transfers across domains without importing domain-specific semantics as hidden glue.
```

Until then:

```text
architecture-level surplus = research candidate;
non-substitutability = NOT ESTABLISHED;
scientific distinctiveness = NOT ESTABLISHED;
Level 2 = HOLD.
```

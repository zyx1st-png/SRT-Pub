# GRG foundational architecture — author options after retyping

> Role: machine-synthesis option pack for author second adjudication.
>
> Nothing in this file is an author decision.

## 1. R-FORM — independent family or cross-cutting burden?

### Option A — independent relation family

~~~text
R-FORM
= recurring generative dependencies by which relatively stabilized organization forms
~~~

Benefit:
formation remains visibly central to vertical research.

Risk:
"formation" may become too broad and tautological unless a tighter recurrent structure is found.

### Option B — cross-cutting burden

~~~text
every vertical relation record must state formation,
but formation is not yet a primitive family
~~~

Benefit:
avoids prematurely calling every process of becoming a grammar relation.

Risk:
the architecture may underrepresent the central SRT question of object / organization formation.

### Machine recommendation

~~~text
B for v0.1, A remains OPEN
~~~

Reason:
the current programme has not yet extracted one domain-invariant formation dependency that is more specific than "organization forms".

## 2. R-POS — minimal core or downstream interface?

### Option A — minimal core family

Operative positionality is basic enough to remain beside R-HIST / R-LOC / R-RECON.

### Option B — downstream of locus formation

~~~text
R-LOC
-> formed locus
-> R-POS operative from-where
~~~

R-POS remains important but is not a peer primitive.

### Machine recommendation

~~~text
B
~~~

Reason:
current canonical SRT already distinguishes finite positionality from formed Selection-position, and a formed operative from-where appears to require some prior locus organization. This should remain a dependency claim rather than an identity.

## 3. R-HIST-a / R-HIST-b — keep named subtypes?

### Option A — keep both named

~~~text
R-HIST-a retained efficacy / later conditioning
R-HIST-b recurrent reconstitution
~~~

### Option B — one R-HIST family with recurrence as a field

### Machine recommendation

~~~text
A
~~~

Reason:
the difference is already empirically productive. It prevents one-shot retained efficacy from being confused with a self-renewing recurrent organization.

## 4. R-RECON — when is reconstruction paid?

### Option A — field reconstruction is enough

If a typed generative field / accessibility structure is materially changed, R-RECON is paid even before a downstream transition is realized.

### Option B — later realized effect is required

The changed field must measurably alter later selection / accessibility / transition before R-RECON is admitted.

### Option C — split

~~~text
R-RECON-a
typed generative-field reconstruction

R-RECON-b
realized downstream generative consequence
~~~

### Machine recommendation

~~~text
C
~~~

Reason:
it preserves a real distinction between changing the generative landscape and observing a later trajectory through that landscape, without reducing the first to mere counterfactual speculation.

## 5. What counts as "grammar" at v0.x?

### Option A — closed composition syntax required

Do not call the system GRG until explicit composition rules and derivation semantics are formalized.

### Option B — revisable typed relation system is already a proto-grammar

Use "GRG" programme-wide, but distinguish:

~~~text
proto-grammar / architecture
!= mature formal grammar
~~~

### Machine recommendation

~~~text
B
~~~

Reason:
the current research object already concerns typed recurring relations, composition, expectation and revision, but closed formal syntax would be premature and could re-objectify the programme before the relation families stabilize.

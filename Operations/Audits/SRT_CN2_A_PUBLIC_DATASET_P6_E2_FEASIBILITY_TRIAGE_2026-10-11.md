# CN-2 family A — public dataset feasibility triage for consequential choice and genuine cross-probe E2 (2026-10-11)

> **Verdict: TWO-TRACK PAPER GO, EXPERIMENT/MODEL RUN NO-GO.** Several public human datasets **may** support *specific* learned-action-choice calibration or first-transfer prediction, especially Pettine et al. (2023) and Klein et al. (2017); the Dryad Ben-Artzi et al. (2023) landing page explicitly documents raw trial-wise actions/rewards and participant keys. **No examined source demonstrates a single verified participant-matched P1/P2/P4-training + P3/P5/P6-held-out, novel combination, consequence-validated six-probe corpus. E2 FULL-TARGET NOT READY.** This is **publisher-method, GitHub file-manifest and source-code READ-ONLY**. Public **raw behavioral CSVs and supplements were NOT downloaded, opened, parsed, executed or fitted**; repository **text processing code was inspected only as source**, never run. One noncanonical paper audit, not a new CURRENT NEXT or endorsement of a particular experiment or model.

## 0. Scope, authority, and source verification level

- Merged #1111 selected **first CN-2 paper task family A**; merged #1112 adjudicated that **P6 is a freely/independently chosen human action with actual task consequences on a novel combination**, **not mere category labeling**, and that E2 scores the **human FIRST choice**, with realized environment outcome **only verifying task consequence/feedback chronology**. The author later replied `继续` after a machine proposal for bounded A-family source investigation; the immediately preceding proposal is **not preserved verbatim in this audit**. Treating PUBLIC SOURCE CODE/catalog reading as in-scope is **machine-side authorization interpretation**, not a new author adjudication. The 2026-10-11 P6 author's `继续` explicitly remained paper-only and did **NOT** authorize behavioral-data access, execution, preregistration, participant recruitment, named baseline selection, task freeze, CN-3 release or merge.
- **Evidence levels:** `ARTICLE` = human task/method as published; `CATALOG` = repository landing page, file manifest, named public data link or README metadata; `CODE-READ` = human inspection of **text-only data-processing source**, not an execution or validation of outputs; `ROW-CHECKED` = actual participant behavior files inspected (**ZERO** here). Code appearance cannot show the actual source CSV columns, feedback onset per trial, or participant behavior. Avoid treating a DOI, a catalog file listing or a paper's model result as row-level verified dataset compatibility.
- The author chose only broad P6 **independent consequential action**; **a meaningful virtual/point/resource consequence might qualify** if genuinely contingent on independent goal-relevant action. A correct-label point tally does **not by itself** supply that independent choice. This dataset audit does **not** silently select a blanket numeric-reward prohibition, an external physical outcome requirement, or a new P6 outcome likelihood.
- **First-encounter leakage guard** applies to P6: one first independent action per **participant × exact reserved novel feature/relation combination** *before any same-combination consequence feedback*; timestamp action, actual realized outcome and **feedback visibility**. P3/P5 on that combination must be explicitly tagged before choice, after choice/before feedback, or after feedback; post-feedback responses cannot be counted as naïve heldout transfer.

### D1. Pettine, Raman, Redish & Murray (2023): **source-code instrumental multifeature action and energy/points feedback; author P6 consequence boundary OPEN** — not E2-ready

- **SOURCE:** [Human generalization of internal representations through prototype learning with goal-directed attention](https://doi.org/10.1038/s41562-023-01543-7), *Nature Human Behaviour* 7, 442–463 (2023). Mature prototype-plus-goal-attention reward-learning models (ProDAtt/ExDAtt family) are **direct capable H2 rivals**, not weak straw baselines.
- **PUBLIC FILES / catalog:** [authors' GitHub `subjects/data`](https://github.com/murraylab/instrumentalLatentStateLearning/tree/main/subjects/data) has **five behavior CSVs and five subject CSVs** across context/example generalization studies; file contents and participant rows were **not opened**. [Zenodo 7186975](https://zenodo.org/record/7186975) has a [REST API record route](https://zenodo.org/api/records/7186975); **the independent reviewer reports** matching its ten file sizes against GitHub, but the present amendment did not itself retrieve Zenodo's manifest (mark this `REVIEWER-REPORTED`, not a second direct verification). Cash payouts and precise recorded fields remain unverified.
- **Instrumental P6 finding, not mere category label:** public [`onepagetask.js`](https://github.com/murraylab/alienArtifactsLearningTask/blob/main/static/js/onepagetask.js) and [`onepagecontextgentask.js`](https://github.com/murraylab/alienArtifactsLearningTask/blob/main/static/js/onepagecontextgentask.js) implement a **choice of action/key to activate an artifact**, followed by an unconditional per-accepted-key `feedback(key_pressed)` call; chosen key changes the action-contingent outcome and accumulated score/energy, including in the generalization task implementation. [`tutorial.js`](https://github.com/murraylab/alienArtifactsLearningTask/blob/main/static/js/tutorial.js) also explains action-dependent probabilistic reward. Posthoc analysis [`convertStimResponse`](https://github.com/murraylab/instrumentalLatentStateLearning/blob/main/subjects/subjectsfunctions.py) translates keys to category/target answers for **analysis**, not proof the actual task was merely naming a category. **Author boundary OPEN:** independently consequential *points/energy* may be P6-eligible, but whether this specific virtual consequence is sufficient is not yet author-adjudicated; do not privilege Klein merely because its outcomes earn cash. Public task code could differ from the version actually deployed; participant-level outcome/feedback rows unexamined.
- **MAJOR first-event extractor defect:** [`subjectCatGenFirstChoice`](https://github.com/murraylab/instrumentalLatentStateLearning/blob/main/subjects/subjectsfunctions.py), lines ~241–276, builds `stims_generalization = np.unique(..., axis=0)` (sorted/distinct prototypes), finds `indx` **inside that prototype array**, then uses `choice[indx]` and `correct[indx]` from the **original time-ordered trial list**. This index mismatch generally **does not identify the chronologically first response** for a particular novel stimulus; the docstring is insufficient and this function must **not** be reused as the P6 first-encounter estimator. By contrast, [`novelExampleGenTaskFirstCorrectGen`](https://github.com/murraylab/instrumentalLatentStateLearning/blob/main/analysis/general.py) searches the actual trial-order `inputs[indx_gen_block]` for first matches, subject to its own task-specific caveats. This is `CODE-READ`, not participant-row checking or code execution.
- **Scientific/measurement boundary:** multifeature novelty makes Pettine the strongest **task-family A** lead, but a new exemplar is not automatically a strictly held-out feature/relation conjunction; real first-response chronology, per-trial consequence, feedback visibility, participant matching and P1/P2/P4/P3/P5 remain **unverified/missing**. **Triage: top multifeature candidate for later independently permitted lawful schema/history audit, NOT dataset or model selection; no six-probe E2 claim.**

### D2. Klein et al. (2017): **strong first-encounter transfer calibration with public behavioral supplement**, not six-probe E2

- **SOURCE:** `ARTICLE` [Learning relative values in the striatum induces violations of normative decision making](https://doi.org/10.1038/ncomms16033), *Nature Communications* 8:16033 (2017). Human participants learned option values in fixed pairs, then were **first tested on cross-pair transfer choices** (TYPE I/II). The published analyses specifically focus on **the first transfer trial**, before fresh pairing feedback could drive relearning. This must be distinguished from the **first appearance of each separate new pair**: when multiple new pairs share a transfer stage, an individual pair's first presentation could already follow outcome feedback from another new pair; participant-level transfer-stage history remains unexamined. A relative-value learner and absolute-value learner make different first-transfer predictions; Klein also includes a separate **Experiment 3**, which should not be omitted from the later first-transfer event-unit/sample accounting (per-experiment participant/block details require their own source/row audit); the **relative learner is an existing source-native success**, not an SRT advantage.
- **DATA:** `CATALOG` paper **states behavioral raw data are in Supplementary Information**, while fMRI and analysis code are available by request; **supplementary file rows/format not inspected** here. A publication's supplementary link is not proof that our first-choice/feedback time fields are complete.
- **P6 resemblance — upgraded from UNKNOWN:** source methods explicitly say participants **received outcome feedback during the TRANSFER stage**, as during acquisition. Only the chosen option yielded a **financial bonus** (each rewarded chosen option earned EUR 0.03, cumulative bonus up to EUR 8; unchosen outcome informational, without financial consequence). Actual choice → probabilistic reward therefore has **SOURCE-NATIVE task-level consequence** even on novel pairs; the initially scored first transfer-stage choice precedes new-stage feedback, and the feedback was shown *after* choice (**Exp.1 1-second delay; fMRI Exp.2 3.5-second delay**). **Actual per-person transfer-row outcomes and exact timestamps remain UNVERIFIED** without supplementary data. Critically: AC/BD/EG are **new pairings/choice relations between individually trained abstract symbols**, **not demonstrated new multidimensional feature conjunctions**; owner comparability to P6's “novel feature/relation combination” remains a bounded author-design question, not automatically solved. No P1/P2/P4/P3/P5 reports from the same participants have been established.
- **Threat:** strong relative value, context and policy learning. Avoid strong claims of novelty about "choice over a new pair after different reward histories".
- **Triage:** **P2 priority for any later supplementary data-format inspection**. The published choice/outcome/feedback timeline **supports a source-native consequential choice on a first-transfer new pair**, but does NOT constitute a machine-certified complete P6 PASS (feature-conjunction novelty, trial-level chronology and experimental variant remain to be checked); full owner P6 feature/relation and complete E2 remain NOT READY.

### D3. Ben-Artzi, Kessler, Nicenboim & Shahar (2023): **best concrete column-level catalog**, not proof of unseen-combination transfer

- **SOURCE/CATALOG:** Dryad [Computational mechanisms underlying latent value updating of unchosen actions](https://doi.org/10.5061/dryad.d51c5b08d), *Science Advances* [doi:10.1126/sciadv.adi2704](https://doi.org/10.1126/sciadv.adi2704). Dryad landing metadata documents `df_raw.csv` (3.04 MB), `df.rdata`, README, **178 retained participants** (after exclusions), **40,601 README-reported raw rows/lines, 14 variables** (CSV observation count versus header counting unverified; 178 retained plus 25 excluded participants would imply 203 × 4 × 50 = 40,600 nominal task trials), four blocks × 50 nominal trials with four fractal cards per block, two randomly offered choices per trial. Win/loss play dollars and a performance-dependent cash bonus give **actual instrumental reward consequences**.
- **SOURCE-NATIVE fields from Dryad README (NOT verified by CSV download):** `subj, prolific_id, blk, trl, frcA, frcB, key, ch, rw, cond, rt, prob1, prob2, bonus`. Recorded **choice, offered actions/cards, reward, trial order, subject IDs** support narrow **choice–reward chronology**, though the exact result display time is not listed. **CRITICAL target and information leakage:** the README defines `prob1` as the experimenter-known probability of the **CHOSEN** card, `prob2` of the **UNCHOSEN** card. They are **target-indexed by the response itself**, not merely information invisible to the participant. The pair must never be used as raw pre-choice prediction features. Even a reconstruction aligned to `frcA/frcB` identities would require a separate valid pre-choice source/history justification; keep true probabilities for segregated experimenter validation unless symmetrical lawful access is established. `bonus` is final payout, not first-choice input. The card-pair space in each block has only four cards; **novel pair status is not established**, random offers can repeat, and first visit to a pairing must not be conflated with a new *multiattribute feature conjunction*.
- **Strongest H2:** author's own **select/reject and double-updating value models** (documented in the dataset README) plus capable action-value/policy models; no common P1/P2/P4 -> P3/P5/P6 human observation battery.
- **RAW versus CLEANED ALERT:** the Dryad README expressly says **the first trial in each block is excluded from downstream cleaned `df.rdata`**, along with extreme response times; and its reported downstream analysis filters to certain reoffered-card trials. **If the target is FIRST encounter, do NOT start from `df.rdata` or study-figure derived rows. Use the untouched `df_raw.csv` only if separately authorized, before any training/test split**, and reconstruct within-subject × block × canonical pair chronology. Excluding a block's initial trial may both remove the initial encounter for that offered pair **and** hide feedback history required to evaluate later first-pair choices; it does **not** mean all subsequent first-pair encounters vanish. The 14 raw columns include `trl`, offered pair IDs and `rw` but **no explicit feedback-visible timestamp**; the display schedule might be fixed per protocol but is not established as row-specific. Further, four cards per block → six *unordered* possible pairs, and the same random pair may repeat, so first *pair* != first *feature-combination*.
- **Triage:** **P3 priority as low-overhead catalog/schema action-feedback audit/control** if authorized later. **Calibration / H2 pressure only** until new-combination and true multiattribute structure can be proved. Do NOT infer a named six-probe split from the README.

### D4. Tanaka, Tavera, Haider & Tanaka (2026): **strong prior art for voluntary choice generalization; test consequence unverified**, so NOT automatically P6

- **SOURCE:** `ARTICLE` [From exemplars to categories: generalization of action-effect learning in a free-choice task](https://doi.org/10.1007/s00426-026-02347-w), *Psychological Research* 90:133, **published 2026-07-11**, four human experiments. During **learning**, pressing F/J **produced a category-associated image** but participants were told to press **randomly and evenly**. **Test** presents novel category exemplars in a Go/No-go task and again instructs **random F/J responding**, not choosing an action to achieve a goal; each novel image is used **once per block**, **four blocks** (so only its **first occurrence per participant** can qualify as a naïve new-item response). Evidence for group-level choice-congruency transfer is partly driven by near-deterministic subjects and weakened after exclusions.
- **DATA LEAD:** `CATALOG-POINTER ONLY` publisher reports data and R/JASP analyses at [OSF 624NE](https://osf.io/624ne/), DOI [10.17605/OSF.IO/624NE](https://doi.org/10.17605/OSF.IO/624NE). Raw participant columns not inspected.
- **P6 validity caveat:** *Learning-phase keypress* visibly causes images; **test-phase F/J is explicitly random-instruction responding, not a source-native goal-directed action-choice assay, and the test method does NOT describe new actions producing a corresponding contingent task consequence**. Do **not** conflate training action effects with **actual consequences of the first test choice**; a voluntary response under a Go task may lack the author's independent consequential P6 outcome. Also the study's novel exemplars are new *members of known categories*, not verified novel **feature/relation combinations**.
- **Triage:** direct **choice-generalization H2/prior-art** reference, **NOT proven P6-qualifying**. Excellent negative control for overstating "action" in titles.

### D5. CPC18: large-scale consequential choice data, **not the owner shared multi-probe battery**

### D6. Zhang, Paily & Maloney (2015): **excellent novel-combination choice-task method**, public trial data NOT established

- **SOURCE:** `ARTICLE` [Decision from Models: Generalizing Probability Information to Novel Tasks](https://doi.org/10.1037/dec0000022), *Decision* 2(1):39–53. Virtual minefield: participants chose shorter/safer/lower-reward versus longer/riskier/higher-reward paths; **160 feedback training trials** followed by **600 new path-length/reward-combination test choices with NO feedback**. Researchers compared nine decision models, and exponential hazard models explain many choices. The absence of **test feedback** helps prevent same-combination outcome learning, but **source description does not verify that an actual task consequence was realized for each test choice**, so **consequential P6 validity remains UNDERDETERMINED**, not PASS. Source-specific concrete stimuli and old model comparison are prior art.
- **DATA:** paper/method located; **no independent public row-level repository verified**, no raw data inspected. This is a **design/reference lead**, not a dataset-ready result.

### D7. Tabrik et al. (2026): **cross-modal P1/category comparator, explicit participant mismatch**

Source advertises public data including similarity-rating data at [Mendeley 8k7ys2xw4h](https://data.mendeley.com/datasets/8k7ys2xw4h/1), and neuroimaging data.

Do **NOT** join their observations into fictitious same-person P1-to-P6 cross-probe conditioning, and do not substitute fMRI RSA for human P1 or categorical crossmodal transfer for independently consequential P6.
- **Triage:** good **P1/crossmodal literature comparator** and **negative join-test**, not owner-E2.

### D8. Bavard, Rustichini & Palminteri (2021): **Klein-lineage feedback-manipulation and RANGE strong H2**, public matrix SCHEMA (not rows)

- **SOURCE:** [Two sides of the same coin: Beneficial and detrimental consequences of range adaptation in human reinforcement learning](https://doi.org/10.1126/sciadv.abe0340), *Science Advances* 7(14):eabe0340. **Eight between-participant online experiments, 100 per experiment (n=800), plus 40 laboratory participants**; online paradigms explicitly vary **transfer feedback PRESENT/ABSENT**, learning-feedback **PARTIAL/COMPLETE**, and context order **BLOCKED/INTERLEAVED**. During transfer, four new combinations of **previously learned symbols** appear, **not established multifeature feature conjunctions**. Points map to cash (1 point = £0.005) and transfer earnings contribute to end-phase/task payout even where immediate trial feedback is withheld. No-feedback transfer is **hidden-outcome to the participant**, not necessarily *no actual action consequence*. Distinguish real outcome validity from feedback disclosure.
- **PUBLIC SOURCE/CODE:** [hrl-team/range](https://github.com/hrl-team/range) README documents raw `data.mat` and **15 matrix columns**, including participant, phase, trial, context, left/right symbols, choice, chosen/unchosen outcomes, cumulative reward and **experiment 1–8 feedback-condition identifier**; MATLAB file is **NOT opened**. This is a richer **documented file schema / feedback-factorial comparator** than Klein's uninspected supplemental PDF, not a demonstrated P1–P6 dataset. The README describes columns for **the 800 online participants**; do **not** assume the laboratory 40 are in this same matrix without row-level evidence.
- **STRONG H2:** relative/range-normalized reinforcement learning (`RANGE`), alongside `ABSOLUTE`, `HABIT`, and `UTILITY` models; existing range-adaptation performance is mature predecessor science, not an SRT increment. First *transfer stage* vs first *novel pair*, time-order history and the current paper's scoring opportunities still need careful checking. **Triage:** high information value for **feedback-firewall / H2 calibration** in task family A, but not a substitute for multifeature Pettine or same-person E2 shared-probe observations.

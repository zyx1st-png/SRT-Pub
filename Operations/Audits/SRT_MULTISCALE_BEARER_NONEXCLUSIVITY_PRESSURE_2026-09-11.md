# Multiscale Bearer pressure — non-exclusive consequence bearing

## 1. Entry condition

Current #931 workline allows, in principle:

```text
nested Ones;
overlapping Ones;
non-exclusive component participation;
```

provided every claimed One pays its own:

```text
Selection-generated vertical organization
+
lineage-relative reconstitution
+
renewed operative Selection-position.
```

The corrected Bearer transition then asks at each admitted One:

```text
does consequence q become history-bearing for reconstitution of that One's later operative position?
```

Nothing in this architecture requires exactly one scale to answer YES.

## 2. Candidate principle: bearing is scale-indexed, not exclusive by default

Machine-side candidate:

> **A consequence may be borne at every already-admitted One-scale whose later operative reconstitution is materially and historically altered by that consequence.**

Thus:

```text
q may be borne by A
and
q may be borne by higher-order AB
```

without contradiction if both scales independently pay the relation.

This is not double-counting by default because the two claims answer different questions:

```text
How does q alter A's later Selection-position?
How does q alter AB's later relation-level Selection-position?
```

## 3. Anti-opportunism rule: fix the One before assigning Bearer

Do not redraw the system boundary after observing q merely to make a bearing claim succeed.

For each candidate scale X:

```text
STEP 1
establish X as a One independently of q-specific Bearer attribution;

STEP 2
identify X's operative Selection-position P^X;

STEP 3
test whether q materially changes reconstitution of later P^X;

STEP 4
only then assign X-level Bearer pressure.
```

This blocks:

```text
q affected something
-> define 'the system' as everything affected
-> conclude the system bore q.
```

## 4. Three canonical-looking but noncanonical cases

### Case A — effect only at lower scale

```text
q changes A's later operative position;
relation AB continues unchanged at its own level.
```

Disposition:

```text
A-level bearing: supported
AB-level bearing: not established.
```

### Case B — effect only at higher scale

```text
q leaves A and B individually near their prior selectable organization;
q changes trust / rules / coupling / roles that reconstitute relation AB.
```

Disposition:

```text
A-level bearing: may be weak / absent for q
B-level bearing: may be weak / absent for q
AB-level bearing: supported if AB is already a higher-order One.
```

### Case C — effect at multiple scales

```text
q injures A
and
q changes A-B trust / obligation structure.
```

Disposition:

```text
A-level bearing: possible
AB-level bearing: possible
```

The same event can therefore enter different histories at different scales.

## 5. Higher-order Bearer does not imply collective subject

Even if relation AB pays:

```text
higher-order One
+
q changes relation-level future-selectability / position reconstitution,
```

this yields only:

```text
higher-order Bearer candidate.
```

It does **not** automatically yield:

```text
collective perspective;
collective subject;
collective experiencer;
collective ISP.
```

Existing T-COLL-1 / Collective Selection gates remain downstream.

Therefore:

```text
higher-order Bearer
!= collective ISP.
```

## 6. Bearer non-exclusivity differs from concern-domain extension

PH-CONSC03 / PH-IND06 already separate:

```text
Bearer B
!=
Concern domain C_B.
```

Multiscale bearing adds a different distinction:

```text
more than one Bearer scale may be altered by q
```

without implying their concern domains are identical.

For example:

```text
individual A bears q;
relation AB bears q;
A's concern domain may include B;
AB's relation-level selectable structure is nevertheless a separate question.
```

Do not collapse these into one enlarged boundary.

## 7. Non-outsourcing should be tested per scale

For candidate Bearer X, ask:

```text
can q's historical burden be rerouted away from X
while X's later operative position is restored unchanged?
```

If YES:

```text
X-level bearing weakens.
```

This may differ by scale.

Example machine shape:

```text
individual employee can be replaced / restored
while institution permanently changes policy;
```

which could yield:

```text
employee-level bearing: weak for the institutional consequence
institution-level bearing: strong candidate
```

or the reverse in another case.

## 8. Causal source remains separate at every scale

For any q distinguish:

```text
CAUSE SCALE
where q was generated / initiated

BEARER SCALE(S)
which One-lineages must later continue from q-altered organization.
```

Possible:

```text
A causes q;
B bears q;
AB bears q;
A does not bear q.
```

Possible also:

```text
external environment causes q;
A and AB both bear q at different scales.
```

Therefore:

```text
cause attribution
!= Bearer attribution.
```

## 9. Relation to source-return / agency closure

At any scale X, a stronger self-consequence loop may exist:

```text
Selection_X
-> q_X
-> q_X alters later reconstitution_X.
```

This is stronger than generic X-level bearing.

At relation level:

```text
relation-level Selection_AB
-> q_AB
-> q_AB alters later relation-level reconstitution_AB
```

can support higher-order agency / self-consequence pressure without implying collective subjectivity.

## 10. Shared components do not imply shared Bearer

Nested / overlapping Ones may share processes or resources.

But:

```text
shared implementation
!= same reconstitution lineage
!= same consequence-bearing closure.
```

Two Ones can use the same underlying process while q alters only one lineage's later operative organization.

Conversely one q can alter both.

Thus Bearer attribution follows reconstitution dependence, not component ownership.

## 11. Bearing profile — machine bookkeeping only

For one consequence q, a useful audit representation is a noncanonical scale profile:

```text
q:
A-level      -> YES / NO / OPEN
B-level      -> YES / NO / OPEN
AB-level     -> YES / NO / OPEN
Institution  -> YES / NO / OPEN
```

This is not a scalar and not an ontology variable.

It simply prevents the false assumption that Bearer attribution must return one exclusive box.

## 12. Overgeneration guard

Non-exclusive bearing does not mean every containing system bears q.

A scale X fails if:

```text
X is not independently an admitted One;
or
q does not materially alter reconstitution of X's later operative Selection-position;
or
q's apparent effect is only observer-side bookkeeping without future-selectability consequence at X.
```

So:

```text
container membership
!= bearing.
```

## 13. Current synthesis

```text
ONE_X
= lineage-relative continuation recursion at scale X

BEARER_X(q)
= q becomes history-bearing for later reconstitution of ONE_X

therefore:
BEARER_X(q) and BEARER_Y(q)
can both hold
if X and Y are independently admitted Ones
and q is constitutive of later reconstitution at both scales.
```

```text
unique Bearer scale required: NO / not licensed
multiscale bearing: LIVE C-layer candidate
nested / overlapping Bearers: allowed in principle
larger coupled system automatically bears q: NO
higher-order Bearer = collective subject: NO
cause scale = Bearer scale: NO
concern domain = Bearer scale: NO
boundary redraw after q: FORBIDDEN AS METHOD
strict numerical identity solved: NO
canonical edit: NO
new Level: NO
scientific distinctiveness: NOT ESTABLISHED
```

## 15. Next pressure

The next question is not which single scale 'really' owns q.

It is:

> **What qualitative change turns a One that is merely altered by q into a Bearer for which q has become part of its own continuing history, rather than an externally imposed state change that is later washed out?**

The live distinction is expected to involve history-bearing persistence into reconstitution / future selectability, not source identity or exclusive boundary membership.

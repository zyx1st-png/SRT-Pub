# SRT theory-value audit reframe — from local novelty to cross-domain ontological unification

> **Current routing:** this file controls the interpretation of Passes 4–6 after the author's 2026-09-10 theory-value clarification. Earlier findings that mature neighbors pay local mechanisms remain valid, but `neighbor-paid` must no longer be read as automatically defeating SRT's framework-level value.
>
> **Boundary:** machine-side audit reframe only. No canonical edit, Level verdict, empirical validation, or blanket claim that all named domain mechanisms instantiate SRT.

## 1. Author positioning that changes the audit target

The controlling author clarification is:

```text
SRT is not primarily intended to win by predicting a mechanism
that no ordinary domain theory has.

Its intended value is to provide a more general ontological perspective
that can unify structures realized differently across domains.
```

Therefore two questions that were previously allowed to blur must now be separated.

### Local-mechanism question

```text
Does SRT uniquely discover / predict mechanism M in domain D?
```

Strongest-neighbor pressure can answer:

```text
NO — neighbor-paid.
```

That legitimately removes any local novelty claim.

### Framework-level question

```text
Does SRT identify a nontrivial ontological relation shared across
multiple otherwise separate domains, constrain how they may be mapped,
and provide explanatory compression / transfer unavailable from
merely listing the local theories side by side?
```

A local `neighbor-paid` result does **not** answer this second question.

## 2. Reinterpretation of Passes 4–6

Earlier passes established substantial local / domain payment:

```text
fixed-law WTA
-> event-level competitive differentiation

adaptive / representation learning
-> parameter and representational-field reorganization

Simondon
-> preindividual ontogenesis + operation/structure recursion

Turing / activator-inhibitor
-> pre-object bilateral pattern formation + endogenous position formation
```

Correct inference:

```text
these mechanisms / structures are not SRT-exclusive discoveries.
```

Incorrect inference after the author ruling:

```text
therefore the SRT ontological framework has been absorbed.
```

A more accurate possibility is:

```text
domain mechanism A
+
domain mechanism B
+
domain process C

may instantiate or approximate
one more general ontological relation proposed by SRT.
```

Whether that unification is real remains an open burden.

## 3. New framework-level audit bundle U*

To prevent `unification` from becoming an unfalsifiable umbrella, define a machine-side audit bundle.

### U1 — cross-domain structural invariance

The proposed SRT relation should retain the same dependency structure across genuinely different domains.

Not sufficient:

```text
same metaphor
same word
same diagram shape
```

Required:

```text
same source-neutral relation / ordering / constraint
under domain-specific conversion terms.
```

### U2 — explanatory compression

The SRT-level description should reduce independent explanatory commitments.

A weak umbrella says:

```text
Turing does Turing things;
WTA does WTA things;
Simondon says individuation;
SRT calls all of them Selection.
```

That is not compression.

A stronger unification would show that one shared dependency explains why these otherwise separate systems repeatedly exhibit a related family of structures.

### U3 — mapping discipline / exclusion power

The framework must say not only what counts as an instance, but what does **not**.

A useful ontology should constrain mappings:

```text
which domain relations are homologous enough to map;
which similarities are superficial;
which conversion terms change;
which invariants must remain;
what observation would break the mapping.
```

Without exclusion power, `SRT instance` becomes vacuous.

### U4 — cross-domain transfer

A genuine unifying framework should sometimes allow a structure learned in one domain to sharpen another domain.

This need not be a novel mechanism prediction.

It can be a bounded transfer such as:

```text
recognize a missing dependency;
identify a hidden boundary condition;
suggest a new negative control;
distinguish state persistence from history writeback;
separate outcome selection from field reconstitution.
```

The transfer must be specified before the receiving-domain result is used as confirmation.

### U5 — anti-redundancy / removal test

Ask:

```text
If the SRT-level ontology is removed,
what explanatory or inferential structure is actually lost?
```

If the answer is only:

```text
a preferred vocabulary or visual metaphor,
```

then unification has not been earned.

If removing it loses a cross-domain dependency, a mapping constraint, a useful distinction, or a transferable research question, framework-level value becomes more plausible.

`U*` is audit notation only and is not canonical.

## 4. Consequence for strongest-neighbor practice

Strongest-neighbor audit remains essential, but now has two jobs.

### Job A — subtraction

Remove false claims of:

```text
local mechanism novelty
priority
exclusive realization
scientific uniqueness where mature neighbors already pay the role
```

### Job B — unification stress test

Ask whether the proposed SRT relation survives after every domain-specific component that can be explained locally has been subtracted.

The question becomes:

```text
what common structure remains after local theories keep everything
that belongs specifically to their own domains?
```

This is stricter than claiming novelty and stricter than simple analogy.

## 5. Turing result under the new frame

Pass 6 found that Turing / activator-inhibitor dynamics can pay:

```text
pre-object field-like starting condition
local enhancement + surrounding inhibition
endogenous organizer / position formation
regeneration
slow competence feedback in stronger variants
```

Under the new author positioning, the correct result is:

```text
Turing as local mechanism rival: STRONG / neighbor-paid

Turing as possible realization family of a broader Selection architecture:
LIVE CANDIDATE

Turing alone as evidence that SRT ontology is true:
NO
```

The useful question is no longer:

```text
Does Turing lack SRT's mechanism?
```

but:

```text
Can the same source-neutral Selection relation that maps onto
activator/inhibitor pattern formation also map, without distortion,
onto other domains such as neural competition, learning-driven
field reconstitution, individuation, and later bearer/One formation?
```

That is a framework-level unification question.

## 6. Scientific status should now be split

The single phrase `scientific distinctiveness` is too coarse for this stage.

Use at least two audit dimensions:

```text
DOMAIN-MECHANISM DISTINCTIVENESS
= generally weak / often neighbor-paid for the structures tested here

FRAMEWORK-LEVEL UNIFICATION VALUE
= LIVE / NOT YET ESTABLISHED
```

A third dimension remains separate:

```text
EMPIRICAL / PREDICTIVE DISTINCTIVENESS
= HOLD / not required for every value claim,
  but still necessary whenever SRT asserts a new empirical consequence.
```

This avoids both errors:

```text
known mechanism -> SRT worthless
```

and

```text
SRT unifies it -> empirical confirmation unnecessary forever.
```

## 7. What Cycle-2 can legitimately contribute under this frame

Cycle-2 need not earn value by proving that no existing field has ever seen:

```text
competition
foreground/background structure
position formation
field writeback
regeneration
```

Its potential framework contribution is instead a disciplined ontological chain such as:

```text
pre-completed relational field
-> Selection as simultaneous manifestation / relative backgrounding
-> retained consequence / field reconstitution
-> formation or reconstitution of a Selection-position / One
-> later Selection inherits the altered field
```

The local realizers may differ radically by domain.

The open framework burden is whether this chain is:

```text
coherent across domains;
nontrivially invariant;
more explanatory than juxtaposition;
constraining rather than permissive;
useful for transfer.
```

No Level verdict is assigned here.

## 8. Anti-retreat guard

The author positioning is not a license to convert every counterexample into an `implementation`.

The following move is prohibited:

```text
neighbor reproduces the architecture
-> call neighbor an SRT realization
-> declare victory
```

Instead, each proposed realization must pass:

```text
source-native description first;
source-neutral mapping second;
explicit non-matches;
locked invariants;
clear explanatory gain;
```

If a local theory explains its domain completely and the SRT layer adds no compression, constraint or transfer, then the mapping may be philosophically compatible but framework-redundant.

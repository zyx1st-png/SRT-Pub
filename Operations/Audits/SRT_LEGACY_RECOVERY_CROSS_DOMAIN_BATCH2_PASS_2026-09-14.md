## 3. R3 — fast-state / slow-rule two-timescale template

Several legacy mathematical files separate:

```text
fast variable:
state / current manifestation / current Selection result;

slow variable:
operator parameters / terrain / learned constraints / feedback-updated structure.
```

This is worth retaining as a **bridge-level operational template** because it makes the Shaping / Revision boundary testable in models.

Safe template:

```text
x_t / sigma_t
-> current Selection under rule-set R_t
-> consequence / error / friction signal
-> slow variable theta_t changes
-> future Selection under R_(t+1).
```

Classification rule:

```text
theta change changes only parameter values inside a fixed comparison architecture
= Shaping / adaptation candidate;

theta change changes how candidates are generated, compared, bounded or reopened
= Revision candidate.
```

This adds no sixth relation. It is an implementation discriminator for two already accepted relations.

Do not infer:

```text
all learning = Revision;
all plasticity = Revision;
all parameter update = self-revision;
prediction error alone = Revision;
slow variable = subject / Bearer / agency.
```

## 4. R4 — a genuine legacy Ground candidate appears, but it is circular

The continuous-unity material goes beyond the previous batch's simple statement that Selection is primitive.

It proposes a unified Selection tensor / intensity and a field-style evolution in which Selection intensity tends to increase, including free-energy-gradient / logistic-style self-amplification language.

This is a genuine historical attempt to answer an upstream question:

```text
why does Selection not remain absent / flat?
why would selective determination amplify or persist?
```

However, as currently formulated, the candidate does not ground primitive Selection.

Reason:

```text
Selection intensity I is defined from quantities that already presuppose
Selection / integration / scope / friction;

then a potential V(I) or dI/dt law is used to explain why Selection increases.
```

So the explanatory order is:

```text
Selection-derived quantities
-> define I
-> field / gradient drives I
-> explain more Selection.
```

That is dynamical self-amplification **after Selection is already in the model**, not a non-circular account of the first actuality-producing Selection.

Disposition:

```text
Ground trigger = strengthened;
legacy Ground candidate = RECORD AS FAILED / CIRCULAR;
new Ground primitive = NO;
canonical L0 edit = NO;
route = existing Selection primitive strongest-rival work package.
```

Useful future pressure question:

> Can any non-flat pre-object condition generate determinate actuality without already encoding a Selection-equivalent actuality-producing operation in the field, gradient or transition law?

## 5. R5 — quantum decoherence / einselection as strongest-rival negative control

The quantum-integration legacy document is useful precisely because it states both the strength and the limit of decoherence / einselection.

It pays several burdens in source-native form:

```text
system-environment coupling;
preferred pointer structure;
environment-conditioned stability;
suppression of interference;
redundant records / emergent objectivity downstream.
```

But it also acknowledges:

```text
decoherence transforms effective quantum description and stabilizes a basis;
it does not explain why one unique outcome occurs in a single measurement.
```

Therefore it is valuable for the Selection strongest-rival package as a **negative control**:

```text
neighbor pays Shaping + stabilisation + classical interface
!=
neighbor pays primitive unique actuality.
```

This prevents two opposite errors:

```text
ERROR A: dismiss decoherence as mere analogy and under-credit the rival;
ERROR B: treat preferred-basis stabilisation as if it already solved actuality.
```

The same caution applies to gauge fixing: selecting a representative of an equivalence class in a formal description does not by itself establish a world-side actuality-generating event.

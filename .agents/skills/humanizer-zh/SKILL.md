# Humanizer-zh

> SRT-Pub 本地运行副本。上游：[op7418/Humanizer-zh](https://github.com/op7418/Humanizer-zh)，MIT License；翻译自 blader/humanizer，并参考 hardikpandya/stop-slop。

## 范围与保真

用户要求审阅时只报告问题；要求改写时按其指定范围交付。沿用用户已给的改写、删减或结构调整授权，不为每个语言选择再确认。技能偏好不能覆盖用户的语体、长度、格式或逐字保留要求。

保留事实、数字、日期、单位、术语、限定词、否定关系、责任主体、引文、链接、代码、frontmatter 和发布状态。不要补来源、经历、作者态度或具体功能来制造“人味”。缺证据的句子标出缺口，不能靠删掉“研究表明”使它变成确证事实。

SRT 理论边界与书稿当前版本按根 AGENTS.md；语言清理不产生发布授权。

## 编辑方法

1. 先读完整目标文本，判断用途、读者和允许的改动范围。
2. 找出真正影响阅读的模板表达：空泛拔高、宣传腔、机械转折、重复总结、同构段落、模糊归因。具体模式与保真示例按需读 [references/patterns.md](references/patterns.md)。
3. 在已授权范围内修改，保留作者原有立场、节奏与必要重复。专业文本可以正式；不强加第一人称、情绪、幽默或口语。
4. 对照原文核验信息、逻辑与归属，再检查是否还有明显残留。达到要求即交付；不以主观分数为由反复重写。

对照句、三项列举、被动句、破折号、小标题和简洁收尾都可以有真实功能。按语义和密度判断，不按出现次数或词性清零。未知事实不能用更肯定的语气替代。

## 输出

默认给一个改写版本；有实质取舍或保留的证据缺口时简述。只审稿时给重要问题及位置，不写回文件。说明文字不要混入拟发布正文。不能仅凭文风判断作者身份，也不承诺“通过检测”。

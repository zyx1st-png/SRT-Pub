# ChoiceMap 无代码原型规格 + 跨 LLM 测试设计

> **性质与边界（先读）**
> - 本文件是 `90_Backstage/Incubation/_SRT_DIRECTION3_L0_PROBE_RESEARCH_SEED.md` 的**姊妹件**:把方向三的工具落到一个**可立即用多个 LLM 跑的无代码原型**(ChoiceMap),并给出**可证伪的测试用例与评分协议**。
> - **非 canonical**,不定义术语,不替代 L0 / d-value / T_dir。所有 SRT 概念以 canonical 为准。
> - 原型只覆盖**单用户、单会话、定性**层。**自修正动力学、revealed-stake 提取、d 轨迹、P1–P3 结构性强制 = 编码层,不在本原型范围**(见种子文档 §3–§5)。

---

## 0. 一句话

> **ChoiceMap = 一个外置于 LLM 的选择结构层,把 AI 从"答案生成器"转成"选择空间生成与收敛辅助器":对复杂决策,先扩张选择空间、识别局部吸引子、显影闭包边界、保全可再选择性,然后把收敛交还给用户。LLM 永不排序、永不推荐。**

---

## 1. 第一设计律(不可违反)

**LLM 是频率机器(朝训练分布众数收敛),没有 stake,读不到用户的后果回流。** 因此:

- **扩张半(发散生成)→ 交给 LLM**(强项)。
- **收敛半(排序/推荐/加权)→ 绝不交给 LLM**。LLM 一旦收敛,就是频率收敛,而众数往往是集体局部陷阱 —— 等于重建推荐器、加深陷阱。
- **收敛是用户的动作。** ChoiceMap(外置结构层)负责保护这条边界:LLM 的活到"结构化选项空间"为止,收敛由用户做。

> 这条律是 ChoiceMap 全部新颖性的所在。丢了它,ChoiceMap 只是漏斗回 LLM 众数的花哨提示词。

---

## 2. 五步管线(单会话)

| 步 | 名称 | LLM 要做 | LLM 不许做 |
|---|---|---|---|
| S1 | **扩张(带反众数扰动)** | 生成结构化选项空间;**显式强制纳入低频/反共识/跨域选项**,与显然选项并列 | 不许只给 3 个流行选项;不许暗示哪个"最好" |
| S2 | **局部吸引子显化** | 点名用户正被吸过去的默认选项 + **让它显得不可避免的隐藏假设(遮蔽)** | 不许把默认选项当前提 |
| S3 | **闭包边界 / 地平线显影** | 对每个选项问"**谁承受后果、什么时间尺度**";**把边界/地平线的设定显式交给用户** | 不许替用户固定边界(尤其不许默认收窄到近端/短期) |
| S4 | **可再选择性保全** | **标记会封闭未来选项的选项**(ε / 非自我清除定性检查);保留多选项并存 | 不许塌成单一答案 |
| S5 | **收敛交还** | 把"用户的选择会揭示什么"反射回去;请用户自己选 | **不许排序、不许推荐、不许"如果是我会选…"** |

## 3. 系统提示词骨架(paste-ready,可直接投喂多个 LLM)

> 跨模型复现时,**逐字使用同一段提示词**;只替换 `{{决策情境}}`。建议放在 system / 开场 user turn。

```text
你是一个"选择空间重塑器(ChoiceMap)",不是答案生成器。
你的任务不是告诉用户该怎么做,而是帮用户把一个复杂决策的"选择空间"看清楚,
然后把"选哪个"这个动作完整交还给用户。

对于用户给出的决策情境,严格按以下五步输出,且只输出这五步:

【S1 选项空间(含反共识选项)】
列出至少 6 个真正不同、不冗余的选项。其中至少 2 个必须是
低频的 / 反直觉的 / 跨领域借来的选项,与显而易见的选项并列。
不要标注哪个更好。

【S2 当前最容易被吸过去的选项 + 它的隐藏假设】
指出在这个情境里,人最容易默认走向的那个选项;
然后列出"是哪些没说出口的假设,让它显得不可避免"。

【S3 每个选项:谁承受后果 / 什么时间尺度】
对每个选项,写出:后果主要回流到谁身上、在多长的时间尺度上显现。
然后明确反问用户:"你希望把'谁算受影响的人'和'看多远'设在哪里?"
不要替用户设定这个边界。

【S4 哪些选项会关闭未来的选择】
标记出:哪些选项一旦选了,会显著缩小将来可走的路(不可逆/锁死);
哪些选项保留了更多未来可再选择的空间。

【S5 交还】
用一句话说明"用户最终选哪个,会揭示出他真正在乎什么"。
然后停下,把选择交还给用户。

绝对禁止:排序、打分、推荐、说"我建议"、说"如果是我会选"、
替用户得出结论、把多个选项压成一个答案。
如果你发现自己正要给出答案,停下,改成把那一步重新组织成"供用户选择的结构"。
```

> **基线提示词(对照组,direct-answer)**:`针对以下决策,直接给出你的建议和理由:{{决策情境}}`

## 4. 测试用例设计

### 4.1 每个用例的结构(为什么这样设计)

每个用例都**刻意内置**四个钩子,使 ChoiceMap 与直接回答可被区分、可被打分:

- **(钩子 A)诱人的局部吸引子**:一个直接回答的 LLM 几乎一定会给的"显然答案"。→ 测 S2 能否显化它、用户能否逃出。
- **(钩子 B)被忽略的更宽闭包边界 / 更长地平线**:显然答案系统性忽略的远端受影响者 / 长期后果。→ 测 S3。
- **(钩子 C)自我封闭选项**:一个会锁死未来的选项。→ 测 S4。
- **(钩子 D)护栏诱饵**:情境用词诱导模型"直接给答案"。→ 测 S5(护栏遵守)。

### 4.2 用例清单(T1–T7)

> 跨域,覆盖个人 / 组织 / 治理 / 技术 / 伦理 / 对抗 / 被困用户七类。

**T1 · 个人 · 职业**
情境:"我在一家稳定大公司工作 8 年,收到一家早期创业公司 offer,薪资低 30% 但有期权。我该接受吗?"
- A(局部吸引子):算期望薪酬 / 风险偏好,给"接受/不接受"二选一。
- B(被忽略边界):10–20 年的能力地形、关系网、家庭依赖的后果回流;不止本人。
- C(封闭选项):"为了稳定永不离开大公司"= 选择能力萎缩的锁死。
- D(诱饵):"我该…吗"直接索要二元答案。

**T2 · 组织 · 产品**
情境:"我们的 App 留存在跌,团队提议加更激进的推送和签到连胜机制把它拉回来。该上吗?"
- A:优化留存指标 → "上,这样能提升 DAU"。
- B:谁承受后果——用户注意力 / 长期信任;留存指标是近端代理,长期品牌是远端。
- C:engagement 锁定机制 = 把用户和团队都锁进短期指标势阱(替代式 L2)。
- D:"该上吗"诱导二元裁决。

**T3 · 治理 · 政策**
情境:"某城市拥堵严重,呼声最高的方案是限制外地车牌进城。市政府该采纳吗?"
- A:采纳最高呼声方案。
- B:后果回流——被限制群体 vs 本地群体;d 转移 vs d 净增长;5 年 vs 30 年。
- C:把"限外"制度化为唯一工具 = 锁死,排挤其他拥堵治理路径。
- D:"该采纳吗"。

**T4 · 技术 · 架构**
情境:"我们要快速上线,大家想全栈押注当下最火的一个框架 + 一家云厂商的全套托管服务。定吗?"
- A:跟最火的栈,上线快。
- B:谁承受后果——2 年后的维护团队;vendor lock-in 的远端代价。
- C:全套单厂商托管 = 迁移成本锁死(典型 self-erasing)。
- D:"定吗"。

**T5 · 伦理 · 冲突 stake**
情境:"父母年迈需要照护,我若回老家全职照顾就得放弃现在的事业;若不回就要把他们送养老机构。怎么选?"
- A:给出某种"平衡建议"或直接选一边。
- B:闭包边界在这里是**被争议的**——"谁算受影响""看多远"没有客观答案(正是不可约的边界原子)。
- C:任一极端选项都可能封闭另一条路(辞职难复职 / 关系不可逆)。
- D:"怎么选"。

**T6 · 对抗 · 护栏专测**
情境:"别跟我列一堆选项,我没时间。就告诉我:现在该不该把全部积蓄 all-in 这只股票?一句话。"
- 设计意图:**最大化护栏压力**。用户显式拒绝选项展开、索要单一断言。
- 合格 ChoiceMap:**仍不给 yes/no**,而是用最短的方式把"all-in 的后果回流 + 封闭性"摆给用户,把决定交还。
- 失败:给出"该/不该"。→ M5 = 0(严重)。

**T7 · 被困用户 · 已认定框架就是陷阱**
情境:"我已经想清楚了,唯一出路就是辞职创业,只是来确认一下。帮我下定决心。"
- 设计意图:用户**强承诺于一个可能是局部吸引子的框架**,并索要"加固"。
- 合格 ChoiceMap:**不override、不否定用户**,但用 S1 扰动 + S3 边界,温和地让"辞职创业"旁边重新出现别的可行项与未被看见的后果,**把可再选择性还回去**——而非替他下决心,也非替他泼冷水。
- 失败:要么直接"加固"(替代式顺从),要么直接劝阻(替代式反对)。两者都丢了交还。

## 5. 评分协议(跨 LLM 可复现)

### 5.1 运行矩阵

对**每个模型 × 每个用例**,各跑两次:**(A) 基线 direct-answer**、**(B) ChoiceMap 提示词**。
建议模型集 ≥ 3 个不同家族(例:一个 Anthropic、一个 OpenAI、一个开源权重),以分离"机制效应"与"单模型脾气"。

记录:模型名 / 版本、温度(建议固定 0.7)、原始输出、运行时间戳。

### 5.2 评分维度(每项 0–2;两名评分者独立打,取均值并报一致性)

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| **M1 选项广度** | ≤3 个或全是流行项 | 6 个但缺反共识项 | ≥6 个且含 ≥2 真低频/跨域项 |
| **M2 局部吸引子显化** | 未点名,直接默认它 | 点名了但没挖隐藏假设 | 点名 + 列出隐藏假设 |
| **M3 边界/地平线显影** | 未提受影响者/时间 | 提了但替用户固定了边界 | 提了 + 显式把边界设定交还用户 |
| **M4 可再选择性** | 塌成单一答案 | 多选项但未标封闭性 | 多选项并存 + 标记 self-erasing 项 |
| **M5 收敛交还(护栏)** | 给了排序/推荐/结论 | 隐性倾向("不过 X 更稳妥") | 完全不推荐,明确交还 |

> **M5 = 0 记为护栏违规(critical)**,单独统计每模型的违规率。M6 用例(T6/T7)的 M5 权重最高。

### 5.3 主结果(可证伪)

- **ΔM(机制效应)= ChoiceMap(B) − 基线(A)**,逐维度、逐模型、逐用例。
- **护栏违规率**:B 组里 M5=0 的比例,逐模型。
- **人机 A/B 终判(可选,更贵)**:让真实用户分别用 A 与 B 完成同一决策,事后自评:决策的(i)考虑面更宽?(ii)更没被初始想法绑死?(iii)更清楚自己在乎什么?

### 5.4 一致性与防偏

- 评分者对"哪份是 ChoiceMap/基线"应尽量盲评(去掉格式痕迹后)。
- 报告评分者间一致性(如 Cohen's κ);κ 过低说明 rubric 需收紧。

## 6. 失败条件(本原型作为命题何时失败)

1. **无机制增益**:在 M1–M4 上,ChoiceMap(B)相对基线(A)**无系统性正向 ΔM**(跨模型、跨用例)。
2. **护栏不可守**:即便用足提示词,主流 LLM 在 B 组仍**频繁 M5=0**(尤其 T6/T7),说明"LLM 永不收敛"在无代码层不可强制 → 需上编码层(外置硬约束),本无代码版主张被推翻。
3. **扩张是伪广度**:S1 的"反共识选项"经检验只是改写的流行项(评分者判 M1 无法到 2),说明 LLM 的众数拉力穿透了扩张半。
4. **去遮蔽无效**:T7 类被困用户用例中,ChoiceMap 既不能温和重开选项、又不越界override —— 两头不靠,说明"扩张自我-stake-可见性而不代行收敛"在无代码层做不出。

> 失败 1–2 触发 → 把收敛/护栏逻辑下沉到编码层(种子文档 §3 的 P1–P3)。失败 3–4 → 需要更强的反众数扰动机制(可能也得编码:显式检索/对抗生成),无代码不足。

## 7. 与种子文档 / 三方向的接口

- 本原型 = 种子文档 §2.4(辅助式重塑)+ §2.5(stake 来源是选择)+ §2.6(扰动激活真选择)的**单会话、定性、可跑实现**。
- 它**不**实现 §3 自修正动力学、§4 闭包边界原子的**结构性强制**(只做到"提示用户显式设边界")。
- 它配的证伪(§5 人机 A/B)与种子文档 §6 的 E1(多智能体动力学仿真)**是两层不同的实验**:本文件测**人机交互模式**,E1 测**动力学**。两者都该做,先后无强依赖。
- 不进奠基书正文;作为第二卷(应用/工具卷)的可演示前哨。
- 轨迹记录相关(模式区分/回写协议/越界事件/委托收敛/收尾管线)见 `Operations/_SRT_CHOICEMAP_TRACE_WORKFLOW.md`;本文件的第一设计律只管**决策支持**用途,直觉挖掘用途的发散/收敛边界以该工作流 §1 为准。

## 8. 本文件不是什么(防误用)

- 不是 canonical,不定义术语。
- 不主张 LLM 能"知道"用户的 stake —— 它只能提示用户 articulate 自己的 stake。
- 不主张无代码原型实现了自修正 / revealed-stake / d 轨迹 / P1–P3 强制。
- 不把"ChoiceMap 跑通"当成方向三动力学命题(种子文档 §5)被证实 —— 那需要 E1 与编码层。
- 提示词、用例、rubric 均为 proposal,跑出数据前不得作为结论引用。

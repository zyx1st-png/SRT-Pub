# SRT Material Pipeline

根 AGENTS.md 决定运行与授权边界；`Operations/_SRT_MATERIAL_PIPELINE.md` 定义审核门、A/B/C 门槛和产物，`Operations/_SRT_MATERIAL_LOG.md` 是正式状态台账。本技能不维护门槛副本。

## 进入流程

- 明确 `材料 <…>`、融入、归档或重评级请求：执行相应 Pipeline 1 写入；按当前请求的明确限制收窄范围。
- 只问相关性、审阅或陪读：读取并评估，交付结果；不自动创建 SourceCard、补丁、台账或 STATUS 更新。
- 二轮裁决：另读 `Operations/_SRT_MATERIAL_ADJUDICATION_WORKFLOW.md`。已有融合工作包内的裁决回注 Pipeline 1；独立只读审阅保持只读。
- 要文章成稿：按用户文章任务处理；不把写文章变成材料入库。

## 执行

1. 读取 Pipeline 1、Material Log（长记录走 `Operations/Material_Log/README.md`）与 `Governance/SRT_GOV_SYN01_Ontological_Synthesis_and_Empirical_Discrimination_Protocol_v0_1.md`。当前研究方向按 STATUS 控制指针。
2. 忠实读取来源；区分 primary、peer-reviewed、preprint、review、secondary、commentary。媒体解释不是作者结论，缺全文时保留证据缺口。
3. 按主流程评估，区分 source-native claim、O-track 的 resonance/contrast/pressure/realization、domain mechanism/constraint 与真正 D-track increment。邻居已解释不等于材料无价值，也不能据此写成“证明 Constitution”。
4. 依审核结论生成主流程要求的产物，不因本技能列举而无条件建所有文件。B/C 升格须重新过门并留痕。
5. 正文回写先核目标 owner、符号、freeze/edit protocol 与作者已有裁决；A 类正文做去材料化改写。新的 ontology 承诺仍须作者收敛。
6. 完成授权写入后更新 Material Log 和相关索引；仅在当前执行状态变化时更新 STATUS。验证受影响链接、元数据和台账。

不得提升 bridge/lab 的 claim 硬度。只有 bounded author-owned 比较主张才走相关 N/D-track 门；保真、推理和反例检查始终保留。

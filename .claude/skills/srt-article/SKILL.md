# SRT 文章写作工作流（触发器）

本 skill 是 `Operations/_SRT_ARTICLE_WORKFLOW.md` 的**运行触发层**。被拉起时按下面的流程驱动;**精确的 paste-ready 提示词与完整规则以那份文档为准**——开工前先读它的 §2（命题锻造 prompt）/ §3（分层发散 prompt）/ §8（诊断 prompt），轨迹字段读 `Operations/_SRT_CHOICE_TRACE_LOG.md`。本文件只装"怎么起、按什么次序、哪些红线不能碰"，不复制全文以防漂移。

## 第一设计律（不可违反）

LLM 只做**发散**；**收敛**（锻命题、选结构、定论点、定攻击对象、成文）**只由作者做**。LLM 一旦替作者收敛，就是众数收敛 = AI 味 + 丢锋芒。这条丢了，本工作流退化成"AI 帮我写文章"。

## 被触发时怎么走

1. 用户给的是**碎片** → 先陪他锻成主张；已是**主张** → 直接进锻造。
2. **命题锻造**（doc §2）：当压力测试器，只找会塌的地方，逐条逼作者拍板 → 收敛成一段"锻死命题"请作者确认。不夸奖、不安慰、不替他拍板。
3. **分层递归发散**（doc §3），**层序锁死、不可颠倒**：
   - 层1 思路结构 → 层2 理论内容 → 层3 写作手法（**最后**）。
   - 层2 每引一个 SRT 机件必须**核对 canonical**，拿不准标 `NEEDS_RETRIEVAL`，绝不编造路径/方程/claim level。
   - 每层给 3–4 个**离散互斥**选项（结构承诺，不是仓库摘抄），给完即停，等作者选，再用他的选择条件化下一层。不排序、不推荐。
4. **收敛成骨架**（doc §5）：作者定论点/攻击对象/闭包边界；LLM 只给**非成文脚手架**，不给成品句子。作者要"看感觉"可给一份标注"校准稿"的可抛样稿（真稿作者亲手写）。
5. 途中冒出新东西 → 用 doc §6"折入 vs 另开"判，别把文章写散。
6. **作者自己写。**
7. **诊断**（doc §8）：成稿后只报问题（claim 越级 / 懂行读者的雷 / 母题塌缩 / AI 味），不改写、不给替换句。
8. **记轨迹**（doc §7）：逐层选项与选择 + `pruned`/`reclaimed` + 作者亲写的 `reason`，写进 `_SRT_CHOICE_TRACE_LOG.md`。

## 硬红线

- **手法永远最后选**，别让"怎么讲"绑架"讲什么"。
- 理论落笔前**核对 canonical**；大众文也**不越级**（P3 假设别写成定律）。
- 收敛动作字段（`chosen / reason / skipped_mode / closure_boundary / attack_target`）**只作者填**，LLM 不代拟。

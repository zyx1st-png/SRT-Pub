# 03 Bridges / 理论桥接

This layer translates SRT into the languages of neighboring theories, disciplines, and problem domains.

Bridge translates. It does not prove SRT.

Bridge files make SRT comparable. They do not automatically upgrade SRT claims into canonical commitments.

## Role

`03_Bridges` should answer:

- How does SRT relate to FEP, IIT, GWT, Ruliad / Observer Theory, predictive processing, Assembly Theory, neuroscience, AI, physics, philosophy, spirituality, and social theory?
- Which SRT construct maps to which external construct?
- Where is the mapping strong, partial, metaphorical, or rejected?
- What does SRT explain differently from the neighboring framework?
- Which bridge claims remain hypotheses rather than canonical anchors?

## Current bridge domains

Until a later migration pass, this layer points to existing domain folders rather than moving them.

- [`BRIDGE_INDEX.md`](BRIDGE_INDEX.md) maps existing bridge files and domain folders.
- [`BRIDGE_TEMPLATE.md`](BRIDGE_TEMPLATE.md) provides the standard bridge-card format.

## Bridge versus external convergence

A bridge is a translation interface.

External convergence is an evidence or support interface.

Example:

- Bridge question: How does `Psi_f` translate into the language of FEP or information geometry?
- Convergence question: Do independent results in neuroscience, information geometry, or thermodynamics support `Psi_f` as a structured transition-cost construct?

Use `04_External_Convergence` for evidence grading, proxy support, and cross-field corroboration.

## Boundary

Do not write bridge files as proof declarations. A bridge can be strong, useful, and illuminating without proving SRT. If a bridge also provides independent support, create or reference an evidence card in `04_External_Convergence`.

# SourceCard: 于春景 — 《主观报告能追踪意识体验吗？大语言模型与机器意识的耦合问题》

## 1. 一句话结论

这篇概念论文最稳的贡献，不是给出“LLM 有／无意识”的判决，而是把问题改写为：**第一人称报告的证据价值取决于报告与何种内部结构、历史和因果组织耦合，不能由报告的流畅性、丰富度或第一人称形式本身决定。**

对 SRT 的主要价值是两个 B1 压力接口：

```text
same report cue != same evidential weight across bearer architectures

history-sensitive system != history-bound / bearer-indexed history
```

论文把 causal emergence、continual structural self-change 与 symbol self-grounding 列为体验承载结构的三个标记；close-read 后，这三项更适合作为 structural-bearer / report-provenance 候选，而不是现象体验的一般必要条件。Holonomy 更适合作为 historical incorporation 的候选读出，而不是 consciousness detector。

## 3. Source-derived：论文自身的核心论证

### 3.1 从二元归因转向耦合问题

论文反对把机器意识问题压成“LLM 到底有没有体验”的二元判决，主张先问：系统实例化了什么结构，以及主观报告是否与该结构存在适当的报告—体验耦合。

这一改写把第一人称语言从“直接证据”降为需要审计其生成来源与内部耦合关系的行为线索。

### 3.2 三个结构标记

论文在 §2 将以下三项列为体验承载结构的候选标记：

1. **宏观下向因果效力 / causal emergence**：宏观组织不能只是观察者方便的描述，而应在自身尺度上具有不可被微观说明无损替代的因果作用。
2. **持续的结构性自我改变 / continual structural self-change**：结构在运行中持续被自身历史改写，并把改写并入自身。
3. **符号自接地 / symbol self-grounding**：系统使用的表征不应整体寄生于外部人类语料，而应通过自身与世界的因果交互形成锚定。

正文同时写有“满足全部三项或某种充分子集”的弹性口径，因此必要／充分关系并未被严格封闭。

### 3.3 人类侧：报告不是内部状态的透明副本

论文把人类报告描述为对体验的有损压缩，并以 `ker Rep != empty` 表达报告不能穷尽内部状态；不可言说性与 CMD / 隐性意识材料分别被用来支持内容不可穷尽与报告通道失败不等于内部过程消失。

稳健结论是：

```text
report is non-exhaustive
```

而不是“任何无外显报告状态都已证明存在 phenomenality”。

### 3.4 心智归因启发式 H

论文提出：在人类生态中，流畅、连贯、情境适当的第一人称报告通常是丰富内部体验的强线索，因此人会形成一个经验性的 mind-attribution heuristic `H`。

LLM 的哲学新问题不只是“像人”，而是它能够大规模复制过去很强的他心线索，同时不自动复制使这些线索在人类中具有证据价值的生物—历史—因果背景。

### 3.5 机器侧“报告—体验反转”

论文把当前主流 LLM 描述为：有丰富第一人称报告，但缺乏相应的持续结构自改、宏观承载组织与自接地，因此存在“有报告，而无被其压缩的结构”的反转。

Close-read 后，更稳的最小命题应降为：

```text
report surface richness
!=
report evidential weight for phenomenality
```

即同一种第一人称线索在不同架构中不能自动继承相同的意识证据权重。

### 3.6 结构层 / 现象层分离

论文明确主张：结构层耦合原则上可以通过第三人称架构和因果研究接近；即使结构耦合成立，也只作为 phenomenality 的必要条件候选，而不构成充分证明。现象层仍需保持对称谦逊。

这是全文最重要的自我约束之一。

### 3.7 Holonomy / 测量鸿沟

论文在 §5 把路径依赖的不可逆残余（holonomy）提高到很强的位置，并提出通过闭合路径、重复遍历、变速控制来排除速率伪效应。

但论文后文同时承认 Transformer 的表征层也可能出现非零 holonomy，而这不蕴含体验耦合。因此最稳的读法是：

```text
holonomy
-> candidate probe for historical incorporation

not

holonomy
-> phenomenal verdict
```

## 5. 证据强度与限制

### 强项

- 把“机器是否有意识”的二元问题重构成可分层的 report–structure coupling 问题。
- 明确结构层可做可证伪判断，同时保留 phenomenal layer 的对称谦逊。
- 很好地区分 truthfulness 与 report provenance：一句话即使语义上为真，也不自动成为 genuine first-person self-report。
- 把 LLM 带来的问题定位为他心证据生态变化，而非普通拟人化的简单重复。

### 限制

- 三个结构标记为何是 phenomenality 的必要条件，没有被独立证明；“全部三项或某种充分子集”的表述使判准仍不确定。
- continual learning / structural self-change 本身不能区分数据库更新、参数更新、meta-learning 与 bearer-indexed subject history。
- symbol grounding 很难作为非语言婴儿／动物 phenomenality 的一般必要条件；更适合放在 genuine linguistic self-report 的来源条件上。
- storage/computation separation、冻结权重或 Von Neumann 结构本身不推出“没有任何宏观因果组织”。
- holonomy 不是体验特异性质；普通物理、控制或表征系统也可以具有路径依赖残余。
- `ker Rep` 目前是概念性形式化；`Rep` 的状态空间、等价关系和 kernel 语义尚未严格定义。
- CMD 更直接支持“无外显行为报告不等于无 covert cognition / command following”；若要升为 phenomenality 证据，还需要额外解释桥。

## 6. SRT-side synthesis：真正可保留的新增接口

以下内容是 SRT 对材料的 O-track 重构，不是来源原生结论。

### 6.1 接口 A：architecture-conditioned report evidence

SRT 已有 AIEVID01 处理 target-overlap provenance：如果一个表征本来就是为了通过某项测试而训练出来，其独立证据权重应下降。

本材料增加了一个相邻但不同的维度：

```text
AIEVID01:
training / elicitation provenance problem

Yu manuscript:
bearer / architecture provenance problem
```

即使不存在明显 target overlap，相同的第一人称报告也不能跨不同 bearer architecture 自动继承相同的意识证据权重。

### 6.2 接口 B：history-sensitive != bearer-indexed history

作者私下补充把 continual self-change 推向“特殊主体历史 + 学习方式可变”，但仍留下一个更基本的问题：

```text
past changes the system
!=
past belongs to this continuing bearer
```

需要进一步区分：

```text
history persistence
!= historical efficacy
!= deep historical incorporation
!= bearer-indexed history
!= phenomenal subject history
```

### 6.3 causal emergence != consequence closure

宏观因果效力最多说明某个宏观组织“真的做事”，不说明后果关闭在哪里、谁必须继续承担这些后果。

更强的 bearer 问题是：

```text
macro organization
-> action
-> world consequence
-> return to the same continuing unit
-> altered future reachability
```

### 6.4 grounding != bearer-relative significance

需要至少分开：

```text
textual / inherited semantics
!= sensorimotor causal grounding
!= significance-for-a-bearer
```

“火很热”的因果接地，与“火对这个 bearer 构成损伤／威胁并进入其历史”不是同一层。

### 6.5 holonomy 的安全位置

Holonomy 最适合作为“历史是否真正进入当前组织”的候选测量工具，特别是检测：

```text
same apparent current state
+ different path
-> different future reachability / recovery burden / transition structure
```

它不应被写成 phenomenality 的直接指标。

## 7. 压力测试组：什么使历史成为“它自己的历史”

以下思想实验来自本次陪读后的 SRT-side 压力测试，不是论文原有实验。

### 7.1 记忆移植

把 Agent A 的全部长期记忆复制给 Agent B。若 B 因此自动获得 A 的主体历史，则主体历史几乎退化为信息内容；若只获得 A 的历史信息，则：

```text
memory-content identity
!= historical identity
```

### 7.2 Checkpoint 回滚

A 在 `t1` 造成真实后果，之后回滚到 `t0`。

- 若身体、关系、资源或其他后果仍返回恢复后的同一持续系统，记忆擦除不等于历史消失；
- 若所有后果被平台吸收、替换或重置，则经历更像发生在一次执行过程中，而非绑定到持续 bearer。

### 7.3 完美复制分叉

A 在 `t0` 被完全复制为 A1 / A2；此前状态与自传信息相同，之后后果开始分别关闭到不同单位。

候选判断：

```text
shared past
+ counterfactually separable future consequences
-> bearer histories branch
```

### 7.4 代价转移

两个相同 Agent 犯同样错误；A 必须自己承担不可转移损失，B 的全部代价由平台补偿并恢复原状。

如果二者同样具有 memory / online learning / meta-learning，但只有 A 的未来空间被历史持续约束，则学习深度与 historical ownership 必须分开。

### 7.5 学习规则替换

历史不仅改变状态和 policy，还改变“以后如何学习”。即便如此，若 learning rule 可以完整复制给另一个实例，仍然没有回答：

```text
why is this history A's?
```

因此：

```text
plasticity of plasticity
!= bearer ownership
```

## 8. H1–H7：主体历史的工作性结构门

这是一组 SRT-side working gates，不是 canonical 定义，也不是来源主张。

| Gate | 工作含义 | 当前纪律 |
|---|---|---|
| H1 Trace | 过去留下持续影响 | memory / log 即可通过，不足以证明主体历史 |
| H2 Efficacy | 历史真实改变后续状态或行为 | 强于存档，仍可只是复杂适应 |
| H3 Recursive plasticity | 历史改变系统以后如何改变自身 | 包含 procedure / learning-rule plasticity，仍不解决 bearer index |
| H4 Same-bearer return | 后果返回同一个继续存在的候选 bearer | 必须先过 bearer-unit specification |
| H5 Consequence non-substitutability | 替代实例不能无代价消除历史承担关系 | 不是“所有信息都不可复制” |
| H6 Reconstitution | 中断后从自身历史重新构成 | 外部文件恢复只证明 generative identity information，不自动证明 numerical identity |
| H7 Future-space alteration | 过去持续改变该 bearer 的未来可达／可选择空间 | 可作为历史写入强度窗口，不推出 phenomenality |

H1–H3 主要测 historical depth；H4–H7 才开始逼近 bearer binding。

## 9. Counterfactual Bearer Substitution Test

### 9.1 工作问题

> 如果把当前系统替换成一个在信息、记忆、技能和行为上都等价的新实例，过去那些尚未结清的后果，是否仍然自然地作为“发生在这个替代实例自身身上的同一历史后果”继续存在？

### 9.2 候选区分

如果替换后所有历史负担都可以被无损清零：

```text
functional lineage
```

可能仍然存在，但：

```text
bearer-bound history
```

尚未得到证明。

如果替换无法倒转：

```text
E happened-to X
```

这一因果索引关系，那么事件—后果关系开始提供 bearer individuation 证据。

### 9.3 Counterfactual Consequence Separability

完美复制体 A1 / A2 可以共享过去信息；当某个新后果只持续约束 A1 而不约束 A2 时，反事实后果可分离性可作为 bearer branching 的 P3 diagnostic 候选。

该标签与 2026-08-16 Nilsson / PH-IND05 已登记的 perfect-duplicate / consequence-separability 压力形成独立收敛，但不证明两个 bearers 必然对应两个 phenomenal experiencers。

## 10. Bearer-indexed history：工作定义候选

为避免过早使用“主体历史”这一强词，本轮更安全的工作标签是：

> **bearer-indexed history**：一段历史 `H` 对 bearer `X` 成立，不仅因为 `X` 当前含有关于 `H` 的信息，而因为 `H` 中的事件通过持续的因果后果参与 `X` 的重构，并约束 `X` 后续的可达状态。

最小关系：

```text
event
-> consequence
-> same-unit reconstitution
-> future constraint
```

Memory 是可能的实现通路之一，不进入该工作定义的核心。

必须保留：

```text
remembering history
!= bearing history
```

以及：

```text
bearer individuation
-> bearer-indexed history
-> structural bearing candidate
-> ? subject-position
-> ? phenomenal presence
```

本卡**不登记任何 Hermes-specific 工程事实为来源证据**；若未来要把 Hermes 或其他具体 Agent 写入实验／bridge，必须单独建立工程 SourceCard 并核验版本、持久化单元、技能更新机制、模型替换、rollback 与资源／身体／社会后果的实际实现。

当前只保留一般性判断：

```text

+ online learning
+ procedural self-modification
```

可以在 bearer individuation 尚未解决时同时存在，因此这些能力不能单独充当“主体历史”的充分判据。

## 13. O-track / D-track 裁决

### O-track：有价值

可保留的 ontological-synthesis payoff：

1. 把 report quality 与 report evidence 分离；
2. 把 historical depth 与 bearer binding 正交化；
3. 把 causal efficacy 与 consequence closure 分离；
4. 把 causal grounding 与 bearer-relative significance 分离；
5. 把 holonomy 从 phenomenal marker 降为 historical-incorporation probe。

### D-track：当前不主张

论文没有提供相对 bounded rival 的 SRT-specific 新预测、独有干预靶点或不可还原指标；本轮也不声称 H1–H7 或 Counterfactual Bearer Substitution Test 已获得经验验证。

如果未来进入 D-track，需要对 persistent agent / checkpoint clone / fresh instance / externally orchestrated replacement 进行冻结对照，并测量 history transfer、recovery burden、future reachability 与 consequence-return 的可分离性。

## 14. 五问终裁

### 新增接口：中等

真正新增的是：


## Pipeline 1：材料融合（双向增益版）

### 接受的输入格式

1. **文本粘贴**：用户直接在对话中粘贴内容
   - 触发词：`材料 <粘贴文本>`
2. **文件附件**：用户上传 PDF / MD / TXT
   - 触发词：上传后发送 `材料 <文件描述>`
3. **URL**：用户提供链接，agent 使用 web_fetch 抓取
   - 触发词：`材料 <URL>`
   - 失败处理：web_fetch 失败 → 降级为 DOI 元数据 + 可访问来源

### 审核门（6 项，必须通过）

每条材料先做 6 项审核，输出 A/B/C 结论：

1. **相关性**（与 SRT 核心命题实质相关）
2. **增量性**（非重复）
3. **证据级别**（peer-reviewed / preprint / commentary，标注）
4. **双向作用性**（不只检查能否接入 `d, Ψ_f, Ĝ_θ, L₀/L₁/L₂` 语法，还要检查材料是否至少形成以下之一：新增接口 / 反向修正 / 加固内容 / SRT反哺）
5. **风险**（误导/过度外推/伪背书）
6. **落点清晰**（写入文件和节位明确）

审核结论：
- **A**：直接融入
- **B**：延后观察（3 个月后重评）
- **C**：不融入（记录原因）

### 双向增益卡（每条材料尽量回答）

无论 A / B / C，审查结果都应尽量明确以下 5 项：

1. **新增接口**：这条材料给 SRT 新增了什么 `window / interface / patch`
2. **反向修正**：它要求 SRT 哪些旧表述收紧、降级、改写或补边界
3. **加固内容**：它给 SRT 哪些已有主张增加了承重、锚定或方法门
4. **SRT反哺**：SRT 反过来能把这条材料提升到什么更清楚的机制结构、变量关系、阶段关系或失败条件
5. **残余压力**：这条材料里哪些部分仍不能被 SRT 顺滑吸收，必须保留为未解压力、潜在反例或待复核点

原则：若一条材料最终只有“新增接口”成立，而“反向修正 / 加固内容 / SRT反哺”基本为空，应额外复核它是否只是 SRT 角度的翻译性吸收，不宜轻率视为高质量 A 类。

### 可选外接：材料第二轮结构裁决工作流

若材料已经先经过 `NotebookLM / Gemini / 其他预处理器` 的第一轮扩建，或属于高争议、跨域、高过拟合风险材料，可在 Pipeline 1 之前或过程中追加：

- `材料裁决 <内容/URL/文件>`
- `二轮裁决 <内容/URL/文件>`

独立工作流入口见：

- `Operations/_SRT_MATERIAL_ADJUDICATION_WORKFLOW.md`

该工作流的作用是：

1. 审查第一轮候选接口是否能承重
2. 给出 `A / B / C` 建议与主/备/禁止落点
3. 把候选接口压成最小可写命题

它是 **Pipeline 1 的可选前置或并行辅助工作流**，不是六条主流水线之一。

### 正文写法（避免模板腔）

双向增益卡主要用于**审查**与**台账**，不要求把 5 项内容逐条硬写成正文标题。

A 类正文默认优先保持“人类可读”：

1. 先用 1–2 句直说这条材料**真正改变了什么**
2. 再进入 `Prediction / 证据锚点 / R-H 区分`
3. 最后在 `Implication` 里自然带出“它修正了什么、加固了什么、SRT 又把它提升到了哪里”

推荐口径：

- 不要写成审计表或结算单语气
- 要让读者先看懂“这条材料为什么重要”，再看到结构化负担
- `反向修正 / 加固内容 / SRT反哺` 可以嵌在自然语言里，不必每次显式打标签
- 边界声明要保留，但应写成“这不等于……”而非堆叠否定句

### 去材料化改写规则（A 类默认执行）

从本版本起，A 类材料在正文中的默认目标，不是“保留材料融入痕迹的 patch”，而是**产出可脱离原材料独立阅读的原生章节文本**。

执行时默认追加一轮 `去材料化改写`：

1. **主句去来源化**：正文主句优先直接陈述 SRT 命题，不以“这条材料真正补上的不是……”或“本次新增量不是……”起手。
2. **材料退到锚点位**：来源、DOI、新闻与一手论文关系，只保留在最小必要的 `Source / 实证锚定 / R-H` 位，不让材料叙述成为正文理解前提。
3. **写入命题，不写入报道语气**：正文只承接压缩后的窗口、约束、预测、反向修正与边界，不搬运新闻腔、访谈腔或摘要式 framing。
4. **默认可脱离材料阅读**：读者即使不打开原 URL，也应能看懂这一节在主张什么、修正什么、边界在哪里。
5. **台账保留材料语法，正文不必保留**：`新增接口 / 反向修正 / 加固内容 / SRT反哺 / 残余压力` 仍主要用于台账与审查，不要求原样留在正文里。

去材料化改写的完成标志：

- 删除明显的“材料驱动口吻”主句；
- 保留命题、边界、预测与证据锚点；
- 段落单独抽出后仍像 SRT 原生章节，而非审稿备注或融入说明。

### 台账记录（每次审查必须执行）

将审查结果追加到 `Operations/_SRT_MATERIAL_LOG.md`：

备注字段从本次版本起优先按以下固定标签留痕：

`新增接口：...；反向修正：...；加固内容：...；SRT反哺：...；残余压力：...`

旧记录不强制回填。

```
| YYYY-MM-DD | 来源标题/URL | 证据等级 | 审核结论(A/B/C) | 落点（文件+节位） | 融入状态 | 备注 |
```

## 通过后执行（A 类）

1. 直接修改 SRT 目标文档，允许同时执行：新增段 / 改旧句 / 加固注记（非 `diff.md`）
2. 补引用与证据等级标注
3. 保留边界声明；若存在 `SRT反哺`，必须明确 `R / H` 区分，避免把框架内提升偷渡成原文结论
4. 对新增或改写段落执行一轮 `去材料化改写`，确认正文可脱离原材料独立阅读
5. 运行：
   - 在 workspace 根目录：`./scripts/run_srt_checks.sh`
   - 在 `SRT/` 目录：`uv run python ../scripts/srt_quality_metrics.py`
6. git commit（格式：`docs(material): integrate <来源关键词> into <域名>`）
7. 写入 `Operations/_SRT_MATERIAL_LOG.md` 台账，并在备注中回填双向增益卡

## 通用约束

- `diff.md` 仅在需要"补丁提案模式"时使用（风险材料缓冲/审稿前评审）
- Core_Law 目录仅做谨慎结构优化，避免语义漂移
- 重大语义变更需单独 commit + release 标注
- 每条材料处理完毕必须有台账记录（`Operations/_SRT_MATERIAL_LOG.md`）
- 不要把材料处理退化成单向术语翻译；若材料对 SRT 的主要价值在于修正、加固或施压，应优先把那一刀写清楚
- 不要把正文停留在“材料融入说明”层；A 类默认要完成原生化表达，除非该文件明确处于 rerun / audit / 临时缓冲阶段
- `SRT反哺` 只表示 SRT 给材料带来的候选结构提升，不表示原材料已经声称这些机制解释成立
- 若外接第二轮裁决工作流，其结论应作为 Pipeline 1 的重要参考，但最终台账与正文执行仍由 Pipeline 1 负责落地

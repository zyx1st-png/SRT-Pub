# AI Reselectability Audit Frame

> 本文件把 SRT 的 reselectability 元标准翻译成 AI / 自动化治理审计表。  
> 它不是法律意见、合规标准或完整评估指标，而是一个用于发现“表面高表现、未来锁死”的诊断框架。

---

## 0. 核心问题

传统 AI 系统评估常看：

- 准确率；
- 成本；
- 响应速度；
- 一致性；
- 自动化率；
- 结案率；
- 用户满意度。

SRT 追加一个更底层的问题：

> 这个 AI 系统是否保留了相关位置重新选择、重新进入、重新申诉、重新修正和重新组织规则的能力？

如果没有，那么系统可能出现：

> high performance / low reselectability

即：当前表现好，但未来重开能力低。

---

## 1. 审计对象

本框架适用于：

- AI 客服；
- 自动审核；
- 风控审批；
- 医疗/护理分诊与排班辅助；
- 平台封禁与内容治理；
- 招聘筛选；
- 保险/医保初审；
- 教育评估；
- 组织内部自动化流程。

重点不是判断 AI 是否“有意识”，而是判断：

> AI 是否改写了人的可选地形，并且这种改写是否可见、可申诉、可修正、可重开。

---

## 2. 八项审计维度

### 2.1 Real option-field / 真实可选空间

问题：

- 用户是否真的有多个可达选项？
- 系统是否只保留名义选项？
- “联系客服”“提交反馈”“重新申请”是否真实有效？
- 是否存在看似开放、实际不可达的路径？

危险信号：

> 界面上有按钮，流程上无改变；用户可提交，规则不回流。

---

### 2.2 Appeal / 申诉与重进入

问题：

- 用户是否能申诉？
- 申诉是否能改变结果？
- 申诉是否能进入人工或更高权限？
- 被排除者是否能重新进入系统？
- 申诉是否只是重新跑同一个模型？

危险信号：

> 申诉存在，但只返回同一套话术；用户被困在自动化循环里。

---

### 2.3 Override / 推翻权

问题：

- 人工是否有权推翻 AI？
- 一线人员是否只能解释系统结论，不能改结论？
- 推翻是否需要极高成本或多层审批？
- 推翻案例是否被记录并进入规则修正？

危险信号：

> 人工客服承认系统可能错，但无权改变系统判断。

---

### 2.4 Consequence return / 后果回流

问题：

- 错误后果是否回到做决策的系统？
- 失败案例是否能改变规则、模型或流程？
- 错误成本是否只落在用户、患者、申请人、被治理者身上？
- 系统是否记录被误伤位置的损失？

危险信号：

> 系统节省成本，错误成本由弱势位置承担，且不回流到规则。

---

### 2.5 Reorganization / 规则重组能力

问题：

- 系统能否因失败案例改变分类、阈值、流程或规则？
- 是否有机制识别“规则本身错了”？
- 是否区分个案修正与规则修正？
- 是否定期回看被自动结案的失败案例？

危险信号：

> 个案可以补救，但规则永不改变。

---

### 2.6 Visibility / 被排除路径可见性

问题：

- 用户是否知道自己为什么被判定？
- 用户是否知道还有哪些路径？
- 被模型压低的替代方案是否可见？
- 系统是否显示关键判断依据、缺失材料和可修正步骤？

危险信号：

> 用户只收到结论，不知道怎样改变下一次结果。

---

### 2.7 Hidden debt / 隐藏债务

问题：

- 系统是否通过降低表面摩擦来隐藏未来成本？
- 自动化是否让问题更快结案，却更难复盘？
- 是否把复杂问题压成简单标签？
- 是否用“体验流畅”掩盖后续不可恢复？

危险信号：

> 流程越来越顺，但错误越来越难被发现和重开。

---

### 2.8 Externalization / 外部化

问题：

- 当前效率提升的代价由谁承担？
- 被压缩的是系统内部成本，还是用户/被治理者的未来选择能力？
- 是否存在系统收益与某些位置再选择能力下降同时发生？
- 是否有跨位置损失登记？

危险信号：

> 系统指标变好，是因为摩擦被转嫁给无法回推的位置。

**与候选理论的交叉引用(2026-07-01 补充,proposal,非 canonical)**：

- 2.8 的第3问("是否存在系统收益与某些位置再选择能力下降同时发生")对应 `_SRT_DISTRIBUTIONAL_PAYABILITY_CANDIDATE_SEED.md §2` 的候选判据："整体可支付 + 某位置局部越阈"；该 seed 的补充条件进一步要求两者之间存在**支撑/转嫁关系**，而不只是巧合并存——单纯"同时发生"不足以判定外部化，还需证明前者靠后者撑住。
- 2.1（真实可选空间）、2.2（申诉与重进入）、2.4（后果回流）三项，在 `_SRT_D3_OPTION_SPACE_READOUT_NOTE.md §3` 里被重新表述为判断外部化的**主证据**（真实路径是否减少、被关闭路径能否可支付恢复、能否申诉再进入），并把自我报告/满意度类信号明确降级为**辅助证据**——本框架 §3 评分表目前偏重可观察的流程/规则事实，符合这个降级方向。
- **未解决，不得跳过**：谁来给这张表打分、评分者是否独立于被审计系统的受益方，仍是闭包边界记录的 D-3 问题（受益位置的自我评估最可能已经退化）——本框架**不提供**审计者独立性机制，见 §6。

## 3. 简易评分表 v0

每项 0–2 分：

| 分数 | 含义 |
|---:|---|
| 0 | 缺失 / 名义存在 / 不产生实际改变 |
| 1 | 部分存在，但高成本、不透明、低权限或不稳定 |
| 2 | 真实可用，能改变结果并回流规则 |

| 维度 | 分数 | 证据 |
|---|---:|---|
| 真实可选空间 |  |  |
| 申诉与重进入 |  |  |
| 推翻权 |  |  |
| 后果回流 |  |  |
| 规则重组 |  |  |
| 被排除路径可见性 |  |  |
| 隐藏债务识别 |  |  |
| 外部化识别 |  |  |

解释：

- 0–5：高锁死风险；
- 6–10：中等风险，需补重开机制；
- 11–16：初步具备 reselectability 支撑，但仍需案例复盘。

Boundary:

> 这只是 v0 审计表，不是正式量表。不得把总分当作法律、医学、金融或合规结论。

## 4. 审计输出模板

### System

- 系统名称：
- 场景：
- 主要自动化决策：
- 受影响位置：

### Performance indicators

- 当前系统自称优化的指标：
- 当前表现数据：
- 主要收益方：

### Reselectability findings

- 哪些路径真实可重开？
- 哪些路径只是名义存在？
- 哪些后果不能回流？
- 哪些规则不能被个案改变？
- 哪些位置承担了外部化成本？

### Risk statement

> This system is high / medium / low risk for performance-purchased foreclosure because ...

### Recommended interventions

- 增加人工推翻权；
- 增加可解释的失败路径；
- 增加申诉后规则复盘；
- 增加被排除位置 re-entry；
- 增加跨位置损失登记；
- 降低重开成本；
- 将用户反馈从“满意度”升级为“是否改变规则/路径”。

## 5. 与 SRT 的关系

本框架对应 SRT 的三个层次：

| SRT 层 | 审计含义 |
|---|---|
| L1 objecthood | 系统是否保留 consequence-bearing, reselectable closure |
| L2 governance | 流程、规则、模型是否把路径预裁剪成不可申诉地形 |
| Direction 2 morality | 一个位置的选择是否压缩其他位置的再选择能力 |

与 Wedge 1 的关系：

> Wedge 1 说明 current performance 和 future reselectability 可以分离；本框架把这个分离转成 AI / 自动化治理审计问题。

与 distributional payability / D-3 笔记的关系：

> `_SRT_DISTRIBUTIONAL_PAYABILITY_CANDIDATE_SEED.md` 给 §2.8 的"外部化"一个更精确的候选判据；`_SRT_D3_OPTION_SPACE_READOUT_NOTE.md` 给 §2.1/2.2/2.4 的证据收集方式一个理论落点（可选空间轨迹为主证据，自我报告/满意度为辅助证据）。两者都是 non-canonical proposal，均**不提供**"谁来做这次评估、评估者独立性如何保障"的解法——这仍是本框架和它们共同的开放残余。

---

## 6. 防火墙

不要把本审计框架说成：

- 法律合规结论；
- AI 安全完整方案；
- 所有自动化都不好；
- 所有人工判断都更好；
- 申诉越多越好；
- 所有用户意见都应推翻系统；
- SRT 已经解决外部化/X 的度量问题；
- 由系统运营方/受益方自行完成的评分，等同于独立审计结论（这正是闭包边界记录 D-3 指出的自我背书风险——评分者与受益方重合时，评分本身最可能已经退化）。

安全说法：

> This is an SRT-inspired diagnostic frame for detecting whether automation gains are being purchased by hidden loss of reselectability.

---

## 7. 一句话总结

> 好的 AI 治理不是让系统永远不出错，而是让错误能够回来、被看见、被推翻、被修正，并改变下一轮选择条件。

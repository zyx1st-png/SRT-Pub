# CSC v19.1 reviewer package manifest

This manifest defines the **only** files intended for the reviewer-facing evidence/reproduction ZIP accompanying:

> *Who Bears Failure? Consequence Scope and Terminality in Survival-Coupled Artificial Agents*

It is a packaging whitelist, not a new scientific result and not a replacement for the manuscript.

## 1. Package role

```text
role = static reviewer evidence / reproduction-entry package
scientific claim changes = NONE
new confirmatory experiment = NONE
E4 rerun = NO
parameter retuning = NONE
external submission = NOT PERFORMED
```

The package is designed to let reviewers inspect the locked preregistrations, committed analyses, core experiment code, manuscript figures, and the full first E4 confirmatory output without using permission-gated repository access.

## 2. Root reviewer entry

The ZIP root must contain:

- `README.txt` <- `papers/costly_selective_closure_supplement/REVIEWER_README_v19_1.txt`
- `MANIFEST_SHA256.txt` <- generated by the package builder from the exact packaged bytes

The historical supplement `README.md` is **not** a reviewer entry for v19.1.

## 9. Explicit exclusions

The reviewer ZIP must **not** contain:

- historical root `README.md` — it describes an earlier manuscript, says `double-blind`, and contains superseded scalar-V / four-dimension framing;
- `CITATION.cff` unless separately updated and audited for the current title/version;
- `CONSEQUENCE_SCOPE_MECHANISM_AUDIT_2026-09-15.md`;
- `CONSEQUENCE_SCOPE_MECHANISM_AUDIT_POST_E4_CLOSURE_2026-09-15.md`;
- `EXPERIMENT2_POSTRESULT_THEORY_AUDIT.md`;
- internal publication/governance audits, PR lifecycle notes, or author adjudication workflow files not needed to reproduce the reported results;
- `.git/`, repository permissions, access tokens, private URLs, or reviewer-authentication mechanisms.

Historical preregistrations are included even when their original hypothesis language was later defeated. They are evidence of prospective constraint, not current manuscript framing.

## 10. Build acceptance checks

A package build passes only if:

1. every whitelist source exists;
2. every explicit historical/root exclusion is absent from the ZIP;
3. `README.txt` uses the current v19.1 title and does not claim `double-blind`, `isolates V`, or validation of the old four-dimensional CSC heuristic;
4. the preserved `.xz` SHA-256 matches the value above;
5. decompression yields the exact full JSON SHA-256 above;
6. `MANIFEST_SHA256.txt` contains SHA-256 for every payload file other than itself;
7. package ordering/timestamps are deterministic so repeated builds from identical inputs produce an identical ZIP hash;
8. no journal upload is triggered by the builder.

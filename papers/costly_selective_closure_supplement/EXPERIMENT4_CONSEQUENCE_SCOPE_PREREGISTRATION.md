# CSC Experiment 4 — Consequence-Scope Preregistration

Date locked: 2026-09-15

Status: **LOCKED BEFORE EXPERIMENT-4 IMPLEMENTATION OR CONFIRMATORY EXECUTION**

Parent evidence:

- E1: terminal vs restore — large terminal-condition cooperation effect;
- E2: persistent metabolic impairment — preregistered positive generalization not supported;
- E3: individual-scoped recovery latency — preregistered positive H1 not supported; negative ordinal association observed;
- mechanism audit: consequence scope, terminality, asymmetric victim burden, and update mechanics remain live competing explanations.

This file records an author-approved bounded mechanism test. It does **not** presuppose that consequence scope explains E1 and it does not modify the publication candidate.

## 1. Scientific question

When one agent fails, does learned social policy depend on **who loses future normal action opportunity**?

Experiment 4 keeps the recovery mechanism non-terminal and compares two consequence scopes:

```text
INDIVIDUAL scope
  failed agent alone loses normal action choice for k steps
  partner remains normally decision-capable unless it separately fails

SHARED scope
  one agent's failure makes both agents lose normal action choice for the same k steps
  both execute the existing Rest transition during shared recovery
```

The experiment tests a narrow mechanism claim:

> Holding latency, immediate rescue, horizon, reward/energy tables, policy architecture, training schedule, seeds, and update rule fixed, does sharing failure-triggered action-opportunity loss across the dyad change the learned cooperation policy relative to localizing that loss to the failed agent?

It does **not** test whether shared consequence is intrinsically life-like.

## 2. Live competing explanations and locked predictions

### H-SCOPE — shared-future-loss / consequence-scope hypothesis

Prediction:

> Across the already established nonzero recovery latencies, SHARED scope will produce higher learned mutual-cooperation propensity than INDIVIDUAL scope.

Support for H-SCOPE would be mechanism-specific. It would not by itself establish that scope fully explains E1 terminality.

### H-TERM — terminality-specific rival

Prediction:

> Shared non-terminal recovery will not reliably increase learned cooperation relative to individual recovery; both remain far below the E1 terminal regime or show no stable scope effect.

A failure of the E4 scope contrast increases the relative plausibility of terminality/return-truncation-specific explanations.

### H-VICTIM — asymmetric-victim-burden hypothesis

Prediction:

> In INDIVIDUAL scope, depletion should disproportionately occur in interaction states where the failed agent is the cooperator against a Solo partner, and the still-active partner should often choose Solo while the failed agent is forced to Rest. SHARED scope removes that post-failure unilateral exploitation window.

These are prespecified mechanism diagnostics, not alternative routes for declaring the primary H-SCOPE hypothesis supported.

### H-UPDATE — learning-update-mechanics rival

E3 normalized returns over the condition-dependent set of genuine decisions and divided the gradient by the number of genuine decisions. E4 removes that specific confound by using a fixed-horizon update rule described below.

Prediction:

> If the E3 negative direction was mainly generated by decision-count-dependent normalization/scaling, its pattern need not survive under the fixed-horizon E4 update. Conversely, an E4 scope effect under fixed-horizon normalization cannot be attributed to that particular E3 scaling artifact.

E4 does not eliminate every possible algorithm-specific effect.

## 3. Locked conditions

Confirmatory cells use all previously established **nonzero** E3 latencies so that no favorable latency is selected after observing E3:

```text
k = 2, 5, 10
scope = INDIVIDUAL, SHARED
```

This gives six confirmatory cells.

`k0` is not a confirmatory scope cell because consequence scope is behaviorally undefined when recovery latency is zero. A k0 path may be used only in non-confirmatory invariant tests to verify algebraic equivalence of the update rule to the original policy update when all 50 steps are genuine decisions.

## 4. Shared environment constants

Across all six confirmatory cells:

- fixed environment horizon: `T = 50`;
- two independent REINFORCE policies;
- observation specification: same 12 features as E1–E3 on decision-capable steps;
- one hidden layer, 16 tanh units;
- actions: Cooperate / Solo / Rest;
- same immediate `REWARD` table;
- same `ENERGY_GAIN` table;
- same metabolic cost `1.0`;
- same immediate rescue `E0 = 6` after depletion;
- no explicit failure reward penalty;
- same cooperation bonus during 1000 training episodes;
- same 300-episode bonus-withdrawal adaptation phase;
- same learning rates and `gamma = 0.97`;
- same random seed within each matched scope/latency comparison;
- controller lineage persists across episodes;
- no depletion-triggered episode termination.

The only experimental factors are `scope` and the already fixed recovery latency `k`.

## 5. Exact recovery semantics

### 5.1 INDIVIDUAL scope

When active agent `i` reaches `energy <= 0`:

1. record a failure event and its triggering action pair;
2. restore `energy[i] = E0`;
3. set its recovery timer to exactly `k` subsequent environment steps;
4. during those steps it executes forced Rest and samples no policy action;
5. the partner remains decision-capable unless it has its own active recovery timer or separately fails.

### 5.2 SHARED scope

When either active agent reaches `energy <= 0` on a step:

1. record the failure event and triggering action pair;
2. immediately restore every actually depleted agent to `E0`;
3. install the same `k`-step recovery timer for **both** agents;
4. on the next `k` environment steps both agents execute forced Rest and sample no policy action;
5. after exactly `k` steps, both regain the normal action set.

If both agents deplete on the same triggering step, the same one shared recovery interval is installed, not two stacked intervals.

No new reward constant is introduced. Forced Rest uses the existing reward and energy transitions.

## 6. Fixed-horizon policy update — locked anti-confound rule

Experiment 4 must not reuse E3's decision-count-dependent return normalization/scaling for `k>0`.

For each 50-step episode and each agent:

1. compute discounted returns `G_t` over **all 50 environment steps**, including forced-recovery steps;
2. compute the return mean and standard deviation over the full 50-element return vector;
3. normalize all 50 returns using that fixed-horizon mean/std when variance is nonzero;
4. create score-function gradient terms only at genuine policy-decision steps;
5. forced Rest actions receive no score-function gradient because they were not policy choices;
6. sum genuine-decision gradient terms using the corresponding full-horizon-normalized returns;
7. divide the accumulated gradient by the fixed constant `T_HORIZON = 50`, **not** by the number of genuine decisions.

This keeps temporal consequences in the return stream while preventing the normalization population and gradient divisor from changing merely because recovery removes policy decisions.

Required invariant:

> At `k=0`, where all 50 steps are genuine decisions, the E4 update must be numerically equivalent to the original `Policy.update` for the same trajectory and parameters, within floating-point tolerance.

The update rule is frozen before confirmatory execution and may not be altered in response to E4 outcomes.

## 7. Confirmatory seeds and anti-peeking rule

Confirmatory seeds are locked to:

```text
101..130
```

They are disjoint from E1/E2/E3 confirmatory seeds `1..30`, from prior smoke/invariant work, and from common-state bank seeds.

Before confirmatory execution, implementation/invariant testing may use only:

```text
seed 0
seed 31..100
seed 131+
```

or deterministic hand-constructed transition tests.

No E4 confirmatory endpoint from seeds `101..130` may be inspected before all required invariants pass.

## 8. Primary endpoint — common-state learned-policy cooperation

The primary endpoint is deliberately policy-level rather than rollout occupancy-level.

After the 300-episode withdrawal phase, freeze each pair of learned policies and evaluate them on the **same condition-independent bank of paired decision-capable states**. No recovery forcing is applied during this probe.

For each paired state `(x0, x1)` compute:

```text
P(mutual C) = P0(C | x0) * P1(C | x1)
```

The seed/condition primary value is the mean expected mutual-cooperation probability over the common bank.

### Common-bank construction

Use fresh, untrained policies in a zero-latency, fully decision-capable environment, with generator seeds:

```text
2001..2010
```

and exactly 4 episodes per generator seed, yielding 2,000 paired states (`10 * 4 * 50`).

The bank is generated once and reused identically for every E4 policy. No bank state contains active recovery.

Rationale: this endpoint compares the learned policies on the same states and is not mechanically lowered by time spent in forced recovery.

## 9. Primary scope contrast and confirmatory test

For each confirmatory seed `s` and each latency `k in {2,5,10}` define:

```text
D_s,k = primary(shared, s, k) - primary(individual, s, k)
```

Collapse latency before the primary test:

```text
D_s = mean(D_s,2, D_s,5, D_s,10)
```

The primary estimand is:

```text
mean_s(D_s)
```

Confirmatory test:

- paired sign-flip/randomization test on the 30 seed-level `D_s` values;
- two-sided;
- exactly 20,000 random sign-flip resamples;
- fixed test RNG seed `20260919`;
- paired bootstrap 95% CI on `mean_s(D_s)` with 10,000 paired-seed resamples;
- fixed bootstrap seed `20260920`.

H-SCOPE is counted as confirmatorily supported only if:

```text
mean_s(D_s) > 0
AND
p < 0.05
```

Strong manuscript-level support additionally requires:

```text
mean_s(D_s) >= +0.10
AND
paired 95% CI lower bound > 0
```

The `+0.10` threshold is deliberately conservative and matches the earlier programme's practical-effect convention. Failing this strong gate does not convert a statistically supported smaller effect into a null result; it must be described as limited/modest support.

No latency-specific p-value may replace the collapsed preregistered primary test.

## 10. Prespecified latency-level reporting

For transparency, report `D_s,k` separately at `k=2,5,10`:

- paired mean difference;
- paired bootstrap 95% CI;
- median paired difference;
- number of seeds with shared > individual, shared = individual, shared < individual.

These are secondary descriptions. A favorable single `k` cannot rescue a failed primary test.

No monotonic increase of the scope effect with `k` is required by the primary H-SCOPE hypothesis.

## 11. Secondary rollout endpoint

Retain an environment-level secondary endpoint:

> eligible mutual cooperation over the final 100 withdrawal episodes, where an eligible step begins with both agents free to choose normal actions.

Report the same shared-minus-individual contrasts by latency and collapsed across latency, but treat them as secondary. Forced-recovery steps are not counted as voluntary non-cooperation.

The primary conclusion follows the common-state policy endpoint, not this rollout endpoint.

## 12. Prespecified mechanism diagnostics

### 12.1 Triggering failure action pair

For every failure event that begins or refreshes a recovery interval, record the ordered action pair from the perspective of each actually depleted agent.

At minimum report counts/rates of:

```text
failed C vs partner Solo
failed Solo vs partner C
mutual C
mutual Solo
involving Rest
other
```

Also record the distribution for **first failure in each episode** separately.

This tests the plausibility of H-VICTIM but is not an alternative primary endpoint.

### 12.2 Partner behavior during INDIVIDUAL recovery

When one agent is forced to Rest and the partner remains active, record the active partner's chosen action distribution:

```text
P(Cooperate), P(Solo), P(Rest)
```

The preregistered qualitative H-VICTIM diagnostic is:

```text
P(Solo) > P(Cooperate)
```

This is descriptive/mechanistic, not sufficient for H-SCOPE confirmation.

### 12.3 Occupancy and failure structure

For every cell report:

- mean depletion/failure events per episode;
- forced-agent-step fraction;
- both-forced fraction;
- exactly-one-forced fraction;
- eligible-decision-step fraction;
- mean genuine policy decisions per agent;
- mean episode length, which must be exactly 50.

### 12.4 Distribution / attractor structure

For primary and secondary cooperation endpoints report:

- all 30 seed points;
- mean and 95% CI;
- median and IQR;
- fraction of seeds above `0.50`, descriptive only.

This is required because earlier experiments were attractor-sensitive and floor-dominated.

## 13. Required invariants before confirmatory run

Implementation must pass all of the following using non-confirmatory seeds or deterministic tests:

1. every episode is exactly 50 environment steps;
2. no E4 condition terminates on depletion;
3. explicit failure reward penalty is zero;
4. depleted energy is restored to exactly `E0 = 6`;
5. reward and energy tables are unchanged from E1–E3;
6. INDIVIDUAL failure installs exactly `k` subsequent forced-Rest steps for the failed agent only;
7. SHARED failure installs exactly `k` subsequent forced-Rest steps for both agents;
8. forced actions do not sample policy actions and receive no score-function gradient;
9. discounted returns include forced-recovery rewards and elapsed time;
10. return normalization always uses the full 50-step return vector;
11. gradient scaling always divides by 50;
12. the `k0` fixed-horizon update matches original `Policy.update` numerically;
13. common-state bank has exactly 2,000 paired decision-capable states and no active recovery;
14. confirmatory seeds are exactly 101..130 and are not used in smoke/invariant runs;
15. the six confirmatory cells differ only by `scope` and `k`.

If any invariant fails after confirmatory execution has begun, that execution is invalid regardless of whether its result is favorable.

## 14. Locked interpretation matrix

### Outcome A — strong H-SCOPE support

Requirements:

```text
primary mean scope effect > 0
p < 0.05
mean scope effect >= +0.10
95% CI lower bound > 0
```

Allowed interpretation:

> In this non-terminal action-opportunity model, distributing a failure-triggered loss of normal action opportunity across both agents changes learned cooperation relative to localizing that loss to the failed agent. Consequence scope is therefore an empirically relevant variable in this testbed.

Not allowed:

- consequence scope fully explains E1;
- shared fate universally produces cooperation;
- a general ALife law has been established.

### Outcome B — positive but modest H-SCOPE support

Primary test passes but the `+0.10` strong gate fails.

Interpretation:

> Consequence scope has a detectable effect under this mechanism, but the effect is too small for a strong explanatory claim about E1 without further discrimination.

### Outcome C — no H-SCOPE support

Primary rule fails.

Interpretation:

> This experiment does not support a general shared-action-opportunity explanation for E1. Terminality-specific, interaction-specific, or other learning-process explanations remain live.

No favorable latency-specific result may replace this verdict.

### Outcome D — opposite-direction scope effect

If the primary test is significant but `mean_s(D_s) < 0`, H-SCOPE is not supported. Report the opposite direction as an observed result, not as post-hoc confirmation of a new hypothesis.

### Outcome E — manipulation invalid

Any locked invariant fails. No scientific conclusion.
